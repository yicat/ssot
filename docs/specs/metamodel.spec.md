# 元模型：通用原语清单

## 目的

定义**通用引擎**的类型与约束原语。

引擎**不认识任何游戏概念**——「鬼火」「技能倍率」「御魂」全部由 schema 用通用原语表达。
换一个游戏只需换 schema，不改代码。这是「通用引擎」路线的全部意义，也是它唯一的代价：
表达力受限于原语集合。

因此本规格的核心约束是：**原语要少而正交**。
新增一个原语，就要付出「迁移脚本 + 历史数据重解释规则」的长期代价。
**只有当现有原语的组合被证明无法表达时，才允许新增原语。**

## 术语

- **原语（primitive）**：引擎内建、不可由 schema 定义的类型或约束。
- **类型（type）**：字段取值的形态。
- **约束（constraint）**：字段取值必须满足的条件。按作用范围分三级（见下）。
- **量纲（unit）**：数值的计量单位。**数值字段必须声明**。
- **不透明（opaque）**：逃生舱类型，原样保存、不做校验。
- **元模型版本**：原语集合自身的版本号。

## 一、类型原语（封闭集合，11 个）

| 原语 | 含义 | 必需附加声明 |
|---|---|---|
| `text` | 短文本 | — |
| `longtext` | 长文本（检索与展示语义不同） | — |
| `number` | 数值（整数/小数由精度决定） | **量纲** |
| `bool` | 布尔 | — |
| `date` | 日期（无时刻） | — |
| `datetime` | 日期与时刻 | — |
| `enum` | 封闭取值集合 | 取值列表 |
| `ref` | 引用另一实体的身份 | 目标实体类型 |
| `list` | 同质列表 | 元素类型 |
| `object` | 嵌套结构 | 子字段列表 |
| `opaque` | **逃生舱**：原样保存，不校验 | — |

设计取舍：

- **不设 `integer`**：用 `number` + `precision: 0` 表达，保持正交。
- **不设 `identifier`**：身份由约束 `identity` 声明，类型仍是 `text` 或 `number`。
- **`text` 与 `longtext` 分开**：因为二者在检索、截断、展示上的语义不同（见
  `framework-capability.md` 关于中文检索的实测）。
- **`opaque` 不可省**：当外部出现引擎表达不了的机制时，系统必须能「**未建模但已记录**」，
  而不是丢弃或拒绝（见 `core.spec.md` 与语义设计的可扩展性一节）。

## 二、约束原语

### 2.1 字段级（单字段自洽）

| 约束 | 适用类型 | 含义 |
|---|---|---|
| `required` | 全部 | 该字段必须出现 |
| `nullable` | 全部 | 出现时是否允许空值（与 `required` 不同） |
| `identity` | text / number | 作为该实体的身份字段 |
| `min` / `max` | number, date, datetime | 取值范围 |
| `minLength` / `maxLength` | text, longtext | 长度范围 |
| `pattern` | text | 正则模式 |
| `precision` | number | 小数位数（0 即整数） |
| `unit` | number | **量纲**，必填 |
| `default` | 全部 | 缺省值 |

### 2.2 记录级（同一记录内跨字段）

| 约束 | 含义 |
|---|---|
| `atLeastOne: [字段…]` | 所列字段至少有一个出现 |
| `mutuallyExclusive: [字段…]` | 所列字段至多一个出现 |
| `requiredIf: { when: {字段: 值}, then: [字段…] }` | 条件必填 |
| `compare: { left, op, right }` | 两个字段的比较，`op ∈ {lt, lte, eq, ne, gte, gt}` |

**记录级约束只能取自上表这四种固定形式，不允许任意表达式。**

这不是偷懒，是实测约束：标准库无表达式求值能力，且离线环境中没有任何表达式库
（见 `framework-capability.md`）。引入表达式语言等于把校验逻辑变成不可静态检查的字符串。

### 2.3 集合级（需跨记录查询）

| 约束 | 含义 |
|---|---|
| `unique` | 取值唯一，可多字段组合 |
| `scope` | 唯一性的作用域：全局，或限定在某父实体内 |
| `ref` 完整性 | 引用目标必须存在 |

**集合级约束必须由存储层保证，不得在应用层「先查再插」**——后者在并发下有竞态。
实测：三个进程各写 300 条，唯一性由数据库索引守住，零重复。

## 三、枚举的开放性（关键设计）

引擎对「结构错误」与「数据取值」采取**相反**的策略：

| 情形 | 策略 | 理由 |
|---|---|---|
| schema 使用未知的类型名或约束名 | **拒绝加载，指出位置** | schema 由我们自己写，typo 必须被抓到 |
| 数据取值不在枚举集合内 | **接受并标记「未建模取值」** | 数据来自外部，新版本会出现新值，丢弃等于信息损失 |

这是「严格防错」与「不丢信息」的调和点：**对我们写的东西严，对别人给的东西宽但不静默**。

- Given 数据取值不在枚举内 When 校验 Then 接受、标记，**不得拒绝，也不得静默通过**
- Given 同一枚举积累了未建模取值 When 达到阈值 Then 提示为该枚举补充取值

## 领域规则（Given-When-Then）

### 类型

- Given 一个字段 When 声明类型 Then 类型名必须取自封闭集合；未知名加载失败并指出位置
- Given 类型为 `list` When 声明 Then 必须声明元素类型
- Given 类型为 `object` When 声明 Then 必须声明子字段
- Given 类型为 `ref` When 声明 Then 必须声明目标实体类型
- Given 类型为 `number` When 声明 Then 必须声明量纲，缺失即拒绝
- Given 类型为 `opaque` When 统计覆盖率 Then 计为**未建模**，不计为已填充

### 约束

- Given 记录级约束 When 声明 Then 只能取自四种固定形式；出现其他形式即拒绝加载
- Given 集合级约束 When 校验 Then 由存储层保证，并发下唯一性成立
- Given `identity` 字段 When 声明 Then 该字段必须同时为 `required`，否则拒绝
- Given 一个实体类型 When 声明 Then 必须声明身份字段（单个或组合）

### 量纲

- Given 两个来源的同一事实量纲不同 When 比对 Then 按量纲换算后比对
- Given 缺少两个单位之间的换算关系 When 比对 Then **拒绝比对**并指出缺失
- Given 一条断言未声明量纲 When 参与比对 Then 拒绝

### 逃生舱

- Given 某字段无法用现有原语表达 When 声明 Then 允许使用 `opaque`，原样保存
- Given 使用了 `opaque` When 生成方案 Then 必须标注该字段未建模
- Given 一个不透明字段 When 被引用进方案 Then 方案标注存在未建模成分

### 元模型版本

- Given 元模型变更 When 发布 Then 必须递增版本
- Given 一份 schema 声明了它要求的元模型版本 When 加载 Then 版本不匹配必须**明确报告**，不得静默按当前版本解释
- Given 需要新增原语 When 评估 Then 必须先证明现有原语的组合无法表达

### 组合与递归

- Given 嵌套 `object` 或 `list` When 声明 Then 深度受限
- Given 类型自引用 When 声明 Then 必须显式允许并设置深度上限，否则拒绝

## 验收标准

- [ ] 未知类型名或约束名导致加载失败，并指出位置
- [ ] `list` 未声明元素类型时被拒绝
- [ ] `object` 未声明子字段时被拒绝
- [ ] `ref` 未声明目标实体时被拒绝
- [ ] `number` 未声明量纲时被拒绝
- [ ] 记录级约束出现四种固定形式以外的写法时被拒绝
- [ ] 集合级唯一约束在并发写入下成立
- [ ] `identity` 字段未声明为 `required` 时被拒绝
- [ ] 实体类型未声明身份字段时被拒绝
- [ ] 量纲不同的两源事实在换算后比对
- [ ] 缺失换算关系时拒绝比对并指出缺失的单位对
- [ ] 枚举未建模取值被接受且被标记
- [ ] 未建模取值达到阈值时产生补充提示
- [ ] `opaque` 字段计为未建模，不计入已填充
- [ ] 引用 `opaque` 字段的方案被标注
- [ ] 元模型版本不匹配时报错而非静默解释
- [ ] 嵌套深度超限被拒绝
- [ ] 自引用未显式允许时被拒绝

## 边界与异常

- 空类型名、空约束名：拒绝
- `list` 的元素类型为 `list`，且嵌套超过深度上限：拒绝
- `enum` 取值为空集合：拒绝
- 量纲为引擎未知的单位且无换算关系：允许声明，但参与比对时拒绝
- `identity` 字段类型为 `object` 或 `list`：拒绝
- 同一字段同时声明 `atLeastOne` 与 `mutuallyExclusive` 且互相矛盾：拒绝
- `requiredIf` 的 `when` 指向的字段不存在：拒绝
- `compare` 的 `left` 与 `right` 量纲不同且无换算：拒绝
- schema 声明的元模型版本**高于**引擎支持：拒绝加载
- schema 声明的元模型版本**低于**引擎支持：允许，但标注为旧版
- `opaque` 字段内嵌套 `opaque`：允许（整体不透明）

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 元模型清单必须可被外部读取，使调用方知道当前引擎支持哪些原语
- schema 加载失败必须指出**具体位置与原因**，而不只是一个失败状态
- 未建模取值与 `opaque` 字段的清单必须可被外部查询

## 附：游戏概念如何用通用原语表达

本表用于验证「通用引擎能否表达阴阳师的机制」。若某一行无法表达，说明原语集合有缺口。

| 游戏概念 | 表达方式 |
|---|---|
| 鬼火（资源） | 独立实体 + `ref`，或 `enum` 的取值 |
| 鬼火上限 | `number` + `unit: count` + `min`/`max` |
| 「鬼火后来又分了几种」 | **新增枚举取值或新增实体实例**，不改元模型 |
| 技能倍率 80% | `number` + `unit: percent` + `precision` |
| 技能 5 级倍率 | `list` of `object{ level: number, value: number(percent) }` |
| 式神属性面板 | `object` 嵌套，各子字段为 `number` + 各自量纲 |
| 暴击 50% vs 0.5 | 同一 `number` 字段，靠量纲归一对齐 |
| 「无视 20% 防御」 | 拆成断言：谓词=无视防御，值=20，量纲=percent |
| 触发条件「当总攻击最高时」 | **断言的限定条件（qualifiers）**，不是 schema |
| 「同一效果在不同条件下不同」 | **两条限定条件不同的断言并存**（见 `core.spec.md`） |
| 御魂套装效果 | 独立实体 + `ref` |
| 未建模的新机制 | `opaque` 字段 + 标记，不丢弃 |

**关键**：条件性一律落在**断言的限定条件**上，不落在 schema 上。
schema 描述「字段长什么样」，断言描述「什么条件下成立什么」。
