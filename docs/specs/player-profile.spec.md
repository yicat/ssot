# 玩家档案：状态与偏好

## 目的

为「针对具体玩家输出方案」提供输入层。

共享事实层描述**游戏本身**（式神、技能、御魂、活动规则）；本层描述**某个玩家此刻的状态，以及他想要什么**。

没有这一层，同一份事实源只能给出泛泛的通用建议，无法回答「我该不该抽」「我够不够」「我该练什么」。同一份事实源之所以能对全图鉴党、斗技党、新区玩家给出不同答案，差别全部来自本层。

使用方：方案生成、差距分析、资源规划。
数据来源：用户录入或导入。

## 术语

- **档案（profile）**：一个玩家的状态与偏好的集合。一个部署可以有多个档案。
- **状态（state）**：客观、可校验的事实——持有哪些式神、御魂、资源库存。
- **偏好（intent）**：主观、只能由玩家声明的选择——玩法倾向、约束、目标。
- **快照（snapshot）**：状态在某一时刻的取值。状态变化产生新快照，不覆盖旧快照。
- **保质期**：某类状态字段在该时长内被视为有效。
- **差距（gap）**：目标所需与当前状态之差。

**状态与偏好必须分开建模**：状态客观、可导入、可校验、有保质期；偏好主观、只能声明、无对错、随人而变。二者的更新机制与信任级别不同，不得混为一种数据。

## 领域规则（Given-When-Then）

### 状态：持有与库存

- Given 一份玩家持有的式神列表 When 导入 Then 每条都以共享事实层的实体标识记录
- Given 导入内容包含共享事实层不存在的实体标识 When 导入 Then 拒绝该条并列出，**不得静默丢弃，也不得创建占位实体**
- Given 同一实体被重复导入且属性不同 When 导入 Then 取时间最新的一条，并保留两条历史
- Given 某资源的数量被更新 When 记录 Then 产生带时间戳的新快照，**旧快照仍可查询**
- Given 查询某资源的当前数量 When 最近快照已超出保质期 Then 结果标注为可能过期，**不得直接当作有效**
- Given 同一资源的两个来源给出不同数量且时间相同 When 记录 Then 两条并存并标记冲突

### 状态：保质期分级

- Given 不同类别的状态字段 When 定义保质期 Then 持有类与库存类**不同**：持有类变化慢，库存类变化快
- Given 一个字段已超出保质期 When 它被方案引用 Then 方案必须显式标注该字段已过期

### 偏好：必须显式声明

- Given 玩家未声明玩法倾向 When 请求生成任何方案 Then **拒绝生成**并指出缺少哪项声明，**不得默认成某种倾向**
- Given 玩法倾向为「全图鉴」 When 生成抽卡建议 Then 该倾向作为**约束**参与计算，而不只是一句提示
- Given 玩法倾向变更 When 重新生成方案 Then 旧方案不受影响且可复现
- Given 某偏好字段从未被声明 When 求解过程引用它 Then 拒绝求解并指名该字段

### 差距分析

- Given 一个目标与当前状态 When 计算差距 Then 输出「缺什么、缺多少」
- Given 目标的完成还取决于随机因素 When 计算差距 Then 输出的是分布或期望，而非单一确定值

### 与共享事实层的关系

- Given 共享事实层中某实体被删除或改名 When 玩家状态引用了它 Then 引用**不自动消失**，而是标记为待处理
- Given 共享事实层更新了某实体 When 玩家状态引用了它 Then 玩家状态不自动改写，仅在方案生成时体现差异

### 档案隔离

- Given 存在多个档案 When 查询状态或生成方案 Then **必须指定档案**，不得隐式取第一个
- Given 个人状态数据 When 与共享事实层交互 Then 个人状态**不得**写入或上传到共享层

## 验收标准

- [ ] 导入持有式神列表：合法标识全部接受，非法标识全部被拒绝并逐条列出
- [ ] 资源数量更新产生新快照，且旧快照仍可查询
- [ ] 超出保质期的字段在查询结果与引用它的方案中均被标注
- [ ] 未声明玩法倾向时，方案生成被拒绝，并明确指出缺少的声明
- [ ] 偏好变更后，变更前后的方案各自可复现
- [ ] 共享事实层实体消失时，玩家状态中的引用被标记而非被删除
- [ ] 多个档案并存时，未指定档案的查询被拒绝
- [ ] 个人状态不出现在共享事实层的任何读写路径中
- [ ] 同一资源两个来源冲突时，两条快照并存且被标记为冲突

## 边界与异常

- 导入内容为空、格式错误、编码非 UTF-8：拒绝，报出位置
- 导入中出现共享层不存在的标识：拒绝该条；其余条目的处理（整批回滚 / 逐条报告）由调用方选择
- 等级、数量为负或超出上限：拒绝
- 时间戳缺失或早于已有快照：拒绝（无法定位「最新」）
- 同一资源被两个来源在同一时刻更新：两条并存并标记冲突，不自动择一
- 偏好字段值不在允许集合内：拒绝，并列出允许值
- 状态引用的实体在共享层被改名：引用按原标识保留，另记改名事实，不自动改写
- 空档案（无任何状态与偏好）：允许存在，但任何方案生成都应因缺少声明而失败
- 方案引用了已过期字段：允许生成，但必须标注；**不得静默使用过期值**

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 个人状态是**本地数据**，不得上传到共享事实层
- 方案输出必须能指认它使用了**哪份档案**、**哪个偏好版本**、以及**哪些字段已过期**
- 状态导入必须能报告「逐条接受/拒绝」的结果，而不是只给整体成败

## 待确认

1. 是否支持多个档案并存？（当前按支持设计，但需要确认是否单人单档案）
2. 状态导入的来源渠道有哪些：手动录入 / 文件导入 / 截图识别 / 其他？
3. 「保质期」的默认值由谁定：部署默认、还是每个档案各自声明？
4. 是否允许偏好随时间变化而保留历史版本，还是只保留当前值？
5. 御魂库是否需要独立建模（数量大、结构复杂），还是先只支持式神与资源？
