# docs/specs/ —— 我们确认过的事实与规范

这里放**我们确认过的东西**：事实、约定、口径。它是改代码前必须先改的地方（见根 `AGENTS.md`）。

## 规则

1. 凡要改到代码的，先在这里写下来、一起定，然后才动手
2. 实现与这里不一致时，**先改这里**，不许绕过去改实现
3. 已经定下的规范要改，先提出来讨论，**不擅自改**
4. 过程中确认的新事实、新约定，回头补进对应的文件

## 命名

`<主题>.spec.md`，一个主题一份，例如 `ingestion.spec.md`、`damage.spec.md`。
主题怎么切、要不要固定模板（目的 / 规则 / 验收 / 边界 / 契约），等新方案定下来再定——
现在**不要**先摆一堆空壳文件。

## 与别处的分工

| 放哪 | 放什么 |
|---|---|
| `docs/specs/` | 我们确认过的事实与规范（权威） |
| `docs/plans/` | 技术方案：怎么实现上面那些规范（**规范冲突时以 `docs/specs/` 为准**） |
| `docs/adr/` | 架构决策记录：做过什么决定、为什么、**否掉了什么**（决策变了不删旧条，新开一条并互相指） |
| `docs/ARCHITECTURE.md` | 整体方案总览（水面上下、三层结构、数据流、边界） |
| `docs/STATUS.md` | 进度与整理台账：现在做到哪、下一步、卡在哪 |
| `docs/OPEN.md` | 问题清单：每个问题标阻塞/待定/观察 |
| `AGENTS.md`（根与子目录） | 给 agent 的协作约定与环境坑 |
| `scripts/` | 脚本本身及其说明（做什么、适用范围） |
| 代码注释 | 为什么这么写（决策的来龙去脉） |
