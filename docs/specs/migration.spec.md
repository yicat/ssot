# Schema 演进与迁移

## 目的

定义 schema 变更时，**既有数据怎么办**。

数据一旦进入系统，schema 就会开始变。本规格定义：如何识别变更的性质、如何评估影响、
如何安全执行、以及**什么情况下不得自动迁移**。

核心立场有两条：

1. **迁移只改变表示形式，不改变事实内容。** 任何改变事实语义的操作都不是迁移，
   必须走核验流程重新建立断言（见 `verification.spec.md`）。
2. **不得为满足新 schema 而编造数据。** 新增必填字段时，既有记录的缺失必须表示为「未知」，
   而不是填一个看起来合理的值。

## 术语

- **变更（change）**：两份 schema 之间的差异项。
- **兼容 / 需回填 / 破坏性**：变更的三种类别（见下表）。
- **影响清单**：变更会导致哪些既有记录违规的逐条报告。
- **回填（backfill）**：为既有记录补上新字段的取值。
- **受阻记录**：无法自动迁移的记录。**不得丢弃，只可标记。**
- **原子迁移**：要么全部成功、要么全部回滚。
- **未知值**：一个显式的取值状态，含义是「我们知道这里应该有值，但我们不知道它是什么」。
  与「缺失」「空值」都不同。

## 一、变更分类

| 变更 | 类别 | 说明 |
|---|---|---|
| 新增可选字段 | 兼容 | 既有记录该字段缺失 |
| 放宽范围 / 长度 | 兼容 | — |
| 新增枚举取值 | 兼容 | — |
| 新增带默认值的字段 | 需回填 | 用声明的策略补齐 |
| **新增必填字段** | **需回填** | 既有记录必须补值或标记未知 |
| 改类型（可无损转换） | 需回填 | 转换后需校验 |
| 改类型（不可无损转换） | 破坏性 | 转不了的记录会受阻 |
| 收紧范围 / 长度 | 破坏性 | 既有记录可能越界 |
| 删除枚举取值 | 破坏性 | 既有记录可能取到已删值 |
| 新增唯一约束 | 破坏性 | 既有记录可能已重复 |
| 新增 `requiredIf` 条件 | 破坏性 | 部分既有记录可能触发 |
| 删除字段 | 破坏性 + **不可逆** | 数据丢失 |
| **改量纲** | 破坏性 + **不可逆** | **数值含义变了** |
| **改身份字段** | 破坏性 + **不可逆** | **既有引用全部失效** |
| 改 `ref` 目标 | 破坏性 | 引用可能悬空 |

**改量纲与改身份字段是最危险的两类**——前者会让所有历史数值的含义静默改变，
后者会让所有引用指向错误的对象。二者都必须走人工确认。

## 领域规则（Given-When-Then）

### 变更的识别与分类

- Given 两份 schema 版本 When 比较 Then 必须逐项列出差异并归类
- Given 某个变更无法自动归类 When 比较 Then 标记为**待人工判定**，**不得默认为兼容**
- Given 变更中同时包含兼容项与破坏性项 When 处理 Then 整批按**最高风险**处理
- Given 两份 schema 无差异 When 处理 Then 不执行任何操作

### 影响清单

- Given 一次 schema 变更 When 请求迁移 Then **必须先产出影响清单**：受影响记录数、逐条标识、违规原因分类
- Given 影响清单非空 When 请求直接执行 Then **拒绝**，必须显式确认
- Given 影响清单为空 When 执行迁移 Then 允许直接执行
- Given 影响清单中的记录 When 展示 Then 必须能看到其**当前值与新约束的冲突点**

### 未知值

- Given 新增必填字段且既有记录无该字段 When 迁移 Then **不得编造值**，
  应填入「未知」或按声明的回填策略处理
- Given 一个字段取值为「未知」 When 校验 Then 满足「必须出现」，但**不满足「必须已知」**
- Given 一个字段取值为「未知」 When 生成方案 Then 必须显式标注
- Given 「未知」与「缺失」「空值」 When 统计 Then 三者必须可区分

> 「未知」是「已知未知」的载体。没有它，新增必填字段就只能靠编造值来满足约束——
> 那正是「数据源不准」的起点。

### 回填

- Given 声明回填策略 When 执行迁移 Then 策略只能取自**固定形式**（常量 / 由另一字段复制 / 标记未知）；
  **不得使用任意表达式**（引擎无表达式求值能力，见 `framework-capability.md`）
- Given 迁移回填写入了一个值 When 记录其来源 Then 来源必须为「**迁移回填**」，
  **不得伪装成原始来源或已验证事实**
- Given 一个值来自迁移回填 When 被方案引用 Then 方案标注该字段为回填值

### 执行与回滚

- Given 一次迁移 When 执行 Then **要么全部成功、要么全部回滚**，不得留下部分迁移状态
- Given 迁移被标记为不可逆 When 请求执行 Then 必须先备份并显式确认
- Given 迁移失败 When 回滚 Then 数据与 schema 版本**均**回到迁移前
- Given 迁移进行中被中断 When 恢复 Then 不得处于半迁移状态
- Given 对同一 schema 版本重复执行迁移 When 执行 Then 幂等，不产生二次影响

### 迁移不改写事实

- Given 一次迁移 When 执行 Then 只能改变**表示形式**——结构适配、量纲换算、类型转换——
  **不得改变断言的语义内容**
- Given 变更需要改变事实本身（例如某个数值被更正） When 评估 Then 该操作**不是迁移**，
  必须走核验流程建立新断言，并保留旧断言为历史
- Given 迁移中做了量纲换算 When 记录 Then 必须记录换算关系与依据
- Given 迁移改变了任何断言的取值 When 记录 Then 该断言必须标记为「经迁移变更」，
  且其原有的核验状态**必须回到待核验**

> 最后一条是本规格与核验规格的接缝：**改过值的东西不能继续携带旧的核验结论。**

### 受阻记录

- Given 某记录无法迁移 When 执行 Then **不得丢弃、不得静默改写**，
  标记为「迁移受阻」并**保留原值**
- Given 存在受阻记录 When 迁移结束 Then 必须报告数量与逐条标识，并转入人工队列
- Given 受阻记录比例超过阈值 When 迁移完成 Then 允许完成，但必须显著报告

### 审计

- Given 任何一次迁移 When 完成 Then 必须记录：迁移前后的 schema 版本、变更清单、
  影响记录数、受阻数、执行者、时间、结果
- Given 迁移记录 When 查询 Then 必须能回答「某条记录在哪一次迁移中、被改成了什么」

## 验收标准

- [ ] 两份 schema 的差异被逐项列出并归类
- [ ] 无法自动归类的变更被标记为待人工判定，不被默认为兼容
- [ ] 含破坏性项的变更整批按最高风险处理
- [ ] 迁移前产出影响清单，含逐条标识与冲突点
- [ ] 影响清单非空时，未确认不得执行
- [ ] 新增必填字段时既有记录被标记为「未知」，而非被编造值
- [ ] 「未知」「缺失」「空值」三者可区分
- [ ] 回填策略只接受固定形式，表达式形式被拒绝
- [ ] 回填值的来源被记录为「迁移回填」，不伪装成原始来源
- [ ] 迁移失败时数据与 schema 版本均回滚
- [ ] 中断后恢复不产生半迁移状态
- [ ] 重复迁移幂等
- [ ] 迁移不改变断言语义；需改事实的操作被拒绝并要求走核验
- [ ] 迁移中取值被改动的断言，核验状态回到待核验
- [ ] 受阻记录被保留原值、逐条报告、转入人工队列
- [ ] 迁移审计能回答「某条记录在哪次迁移中被改成什么」

## 边界与异常

- 两份 schema 无差异：不执行任何操作，不产生审计记录
- 影响清单为空但迁移仍失败：报出失败原因，**不得声称成功**
- 回填结果与既有唯一约束冲突：迁移失败并回滚
- 新 schema 要求的元模型版本高于引擎支持：**拒绝加载**（见 `metamodel.spec.md`）
- 迁移过程中源 schema 文件被外部修改：检出并拒绝继续
- 身份字段变更：必须列出全部失效引用，并转入人工队列
- 量纲变更：必须要求人工确认，并列出受影响的全部数值断言
- 受阻记录比例过高（超过阈值）：允许完成但显著报告，且该 schema 版本不得被标记为「已采用」
- 迁移遇到「未知」值且新约束不允许该值：迁移失败，指出该约束
- 同一记录在同一迁移中命中多条冲突变更：并列报告全部冲突，不择一

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 影响清单必须**逐条**可读，含记录标识与冲突点，而不只是汇总数字
- 迁移必须支持**明确确认**这一步，不允许静默执行破坏性变更
- 受阻记录与回填值的清单必须可被外部查询
- 迁移审计必须可被外部读取

## 待确认

1. 是否支持渐进迁移（新旧 schema 并存），还是只支持原子迁移？
   —— 当前按**原子**设计；当前规模（百至千级记录）够用，但断言量增长后需重新评估
2. 回填策略的固定形式最终清单（当前为：常量 / 复制另一字段 / 标记未知）
3. 受阻记录的人工队列是否与核验队列合并（倾向合并，理由：都需要人判断）
4. 不可逆迁移的备份保留期
5. 破坏性迁移是否需要审批流程，以及与核验流程的关系
6. 「已采用」的 schema 版本标记由谁赋、何时赋
