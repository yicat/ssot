# 歧义：登记与裁决（底座）

## 目的

系统遇到「有多个说得通的说法」时，唯一正确的做法是**不猜**。
但「不猜」不等于「丢掉」：这类项如果只被打印出来，进程一退出就消失——
人无法处理，而且**歧义与缺失分不开**（都是「没抽到」）。

本规格是**底座**，被两个部件共用：

| 种类 | 问题 | 谁产生 |
|---|---|---|
| **指代歧义**（`reference`） | 这个词在这段上下文里指哪个义项？ | 词表（见 `dict.spec.md`） |
| **抽取歧义**（`extraction`） | 这段文本里该取哪个值？ | 数据定义（见 `dataschema.spec.md`） |

两者形状不同（一个选词条，一个选值），但**处置方式完全相同**：
登记成一条可处理、可追溯、可复现的待办；agent 提交全部候选并附上下文；
人裁决；裁决结果走各自应有的落库路径；来源变化时重新打开。

因此它单独成规格，而不是塞进任一边——**歧义不挑部件，处置方式不该写两遍。**

## 术语

- **歧义事项（decision item）**：一个「有多种说得通的说法、必须由人选」的问题。
  **它不是数据。**
- **候选（candidate）**：一种说得通的说法，附带位置与**上下文片段**。
- **裁决（resolution）**：人对该事项做出的选择——选中某个候选、判定「都不对」、或暂缓。
- **重新裁决**：对已裁决事项改变结论。旧结论**保留为历史**，不是覆盖。
- **「都不对」**：一个**结论**——该处确实没有可用取值，记为缺失。
- **「暂缓」**：**未处理**——事项仍在队列里。

## 领域规则（Given-When-Then）

### 歧义的产生

- Given 一段原文中某个位置只能抽出 1 个取值 When 处理 Then 产出结果，
  **不产生**歧义事项
- Given 抽出 0 个取值 When 处理 Then **不产生**歧义事项——「没有」不是「不确定」
- Given 多次命中而取值**全部相同** When 处理 Then 视为唯一命中，
  **不得记为歧义**——歧义是「有多个**不同**的说法」，不是「命中了很多次」
- Given 抽出 2 个以上**不同**的说法 When 处理 Then 产出歧义事项并**携带全部候选**，
  **不得只报数量、不得自行择一、不得丢弃**
- Given 一个歧义事项 When 记录 Then 必须携带：种类、关于什么、全部候选、
  所在文档与修订、位置、歧义原因——缺任一则不是一条可处理的事项
- Given 歧义发生在正文的一段文字中 When 记录候选 Then 每个候选必须带
  **足以判断的上下文片段**——只给一个数字或一个词，人无法判断
- Given 一个词面在词表里只有一个义项 When 处理 Then **不产生**歧义事项，
  直接判定（见 `dict.spec.md`）

### 候选的提出

- Given agent 提出候选 When 记录 Then 允许携带排序与倾向说明，
  但**必须提交全部候选**，且**不得预填选中的那个**
- Given 候选被排序 When 人查看 Then 排序理由必须可见；
  排序**不影响**裁决结果，也不得隐藏任何候选
- Given 两个候选等价（取值相同 / 指向同一词条） When 构造事项 Then **去重**；
  去重后不足 2 个则**不是歧义**
- Given agent 只提交一个候选 When 构造事项 Then **拒绝**——
  单候选应当直接走正常路径，不进待办

### 裁决

- Given 一个歧义事项 When 裁决 Then 裁决人**必须是人**；
  **agent 不得裁决**（与 `agent.spec.md` 的拍板规则一致）
- Given 人选中某个候选 When 裁决 Then 按种类落到各自的路径：
  - **抽取歧义**：该值经**准入**校验后写入项目基础数据，
    分级不得高于该解析方式的允许上限（回退解析 → 不高于结构化，见 `basicdata.spec.md`）
  - **指代歧义**：该选择成为一条**条件指代规则**（见 `dict.spec.md`），
    下次同样上下文**直接判定**，不再重复问人
- Given 裁决产生结果 When 落库 Then 结果与裁决记录**原子写入**——
  不得出现「值已入库但没有对应裁决记录」
- Given 人选「都不对」 When 裁决 Then **不产生任何结果**，该处记为**缺失**，
  并记录理由。这是**结论**，事项视为已处理
- Given 人暂缓 When 裁决 Then 事项保持待处理，**不产生结果**，不得记为已处理
- Given 裁决完成 When 查询 Then **未被选中的候选仍然保留**——
  「当时还有哪些说法」是可追溯性的一部分
- Given 一次裁决 When 记录 Then 必须含：选择、理由、裁决者、时间；
  **理由为空时整笔拒绝**——只有结论没有理由的不是裁决
- Given 裁决产生结果 When 记录 Then 按该结果的性质标注：
  抽取歧义的裁决等同于一次人拍板；指代歧义的裁决记录其依据

### 重新裁决与重开

- Given 事项来源的修订标识变化 When 重新处理 Then 事项**重新打开**并带上新候选，
  旧裁决保留为历史
- Given 事项已裁决且来源变化 When 新候选中**仍然包含**当初选中的说法 Then
  保持已裁决，不打扰人
- Given 事项已裁决且来源变化 When 新候选中**不再包含**当初选中的说法 Then
  标为**「需复核」**，**不得静默保留**旧结论
- Given 事项判定为「都不对」且来源变化 When 重新处理 Then **重新打开**——
  原文变了，「都不对」这个结论未必还成立
- Given 暂缓事项且来源变化 When 重新处理 Then 回到待处理
- Given 修订标识未变化 When 重新处理 Then 不改变已裁决事项的状态
  （重复处理必须**幂等**）
- Given 修订标识未变化但候选结果变化 When 重新处理 Then 候选取本次结果；
  若原选项已不在候选中，同样标为**「需复核」**——
  原文没变而候选变了，说明判断依据变了
- Given 一个已复核的事项 When 人重新裁决 Then 产生**新的裁决记录**，
  旧记录保留为历史

### 人力的分配

- Given 歧义事项多于人力 When 排序 Then 依据**影响面**（该处被引用次数）降序；
  影响面相同则**候选数少者优先**——先清判断成本低的
- Given 排序 When 生成 Then 必须确定且可复现：同一批数据两次排序结果相同
- Given 一个事项 When 展示 Then 必须显示它**为什么排在这里**；
  排在前面的理由不可见，人只能盲信排序

### 队列只有一处

- Given 一个歧义事项 When 出现在词表页 or 数据定义页 Then 它同时出现在
  工作台的**待办区**；**同一件事只有一处队列**，不得在多个页面各排一次
- Given 工作台 When 展示 Then **没有独立的「核验队列」入口**；
  人需要动手的地方只有两处：待拍板与待裁决

## 验收标准

- [ ] 抽出多个**不同**说法时产出歧义事项并携带全部候选与位置
- [ ] 抽出 0 个或 1 个说法时不产出歧义事项
- [ ] 多次命中而说法相同不记为歧义
- [ ] 每个候选带上下文片段，人不打开原文也能判断
- [ ] 候选等价时去重；去重后不足 2 个则不产生事项
- [ ] agent 无法提交只有一个候选的事项
- [ ] 裁决人缺失或非人类时被拒绝
- [ ] 指代歧义的裁决成为条件指代规则，不再重复问人
- [ ] 抽取歧义的选中值经准入写入，分级不高于该解析方式的上限
- [ ] 裁决原子地写入结果与裁决记录
- [ ] 裁决理由为空时整笔被拒绝
- [ ] 选「都不对」时不产生结果，该处记为缺失且记录理由
- [ ] 暂缓不产生结果，事项仍在待处理中
- [ ] 未选中的候选在裁决后仍可查询到
- [ ] 选中的候选未通过准入校验时整笔被拒绝，事项保持待处理，原因返回界面
- [ ] 修订变化后事项重新打开；不再包含原选项时标记为需复核
- [ ] 重复处理同一批数据不改变已裁决事项的状态
- [ ] 已复核事项可重新裁决，旧裁决记录保留
- [ ] 待处理队列可按影响面排序，且排序确定可复现
- [ ] 每个事项显示它为什么排在这里
- [ ] 同一歧义只在一处队列出现
- [ ] 工作台没有独立的核验队列入口

## 边界与异常

- 候选数为 0：构造事项时**拒绝**（没有候选不是歧义）
- 候选数为 1：构造事项时**拒绝**（单候选应直接走正常路径）
- 候选取值重复：按语义去重；去重后不足 2 个则不是歧义
- 本轮处理未再产生某条已存在事项：**不自动关闭、不删除**
  （来源仍在，人仍可裁决），仅在处理报告中列出数量
- 修订变化重新处理时，候选以新修订为准——旧候选可能已不在原文里，
  留着会让人选出一个源里根本没有的说法；已裁决的裁决记录不因此改变
- 裁决索引越界（含小于 -1）：**拒绝**
- 裁决人未标识、或标识为 agent：**拒绝**
- 选中的候选未通过准入（定义未声明该字段、量纲非法、唯一性冲突、引用不存在）：
  **拒绝整笔裁决**并把原因返回界面，事项**保持待处理**——
  不得「先记为已裁决再报错」
- 来源缺失：事项保留，标注来源不可达，不阻断裁决（人可凭已有上下文判断）
- 同一事项被并发裁决：后到者因「已裁决」被拒绝（除非是显式重新裁决），
  不产生第二条结果
- 「都不对」与「暂缓」不得混淆：前者是结论，后者是未处理
- 事项引用的主体/谓词/词条在定义变化后不存在：拒绝裁决并报明原因，
  不静默丢弃
- 事项的候选上下文片段过长：按固定上限截断，但必须保留能区分候选的那一段

## 前后端契约

`DecisionService`（作用域：项目；裁决影响 Case 时可从 Case 作用域读）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | `kind, status, limit` | `DecisionItem[]` | `kind` 为空表示两种都取；`status` 为空表示「还需要人看的」（`open` + `deferred` + `stale`） |
| `Get` | `id` | `DecisionItem` | |
| `Resolve` | `id, choice, by, reason` | `DecisionResult` | `choice >= 0` 选候选；`choice == -1` 表示「都不对」 |
| `Defer` | `id, by, reason` | `DecisionItem` | 状态变为 `deferred` |
| `Reopen` | `id, by, reason` | `DecisionItem` | 对已裁决事项重新裁决；旧记录保留 |
| `Stats` | — | `DecisionStats` | 各状态条数 |

`DecisionItem`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 由（种类, 目标, 来源）决定，**跨修订稳定** |
| `kind` | string | 否 | `reference` / `extraction` |
| `kindText` | string | 否 | 中文说明 |
| `subject` | string | 否 | 人话：这条歧义是关于什么的 |
| `target` | `TargetView` | 否 | 结构化定位：词面 or（实体, 主体, 谓词） |
| `reason` | string | 否 | 歧义原因（人话，含候选个数） |
| `context` | string | 否 | 歧义所在片段 |
| `docId` / `title` | string | 否 | 来源文档 |
| `revision` | string | 否 | 源内容修订标识 |
| `anchor` | string | 否 | 段落锚点，可跳转 |
| `impact` | int | 否 | 影响面：该处被引用次数 |
| `impactWhy` | string | 否 | **为什么排在这里** |
| `status` | string | 否 | `open` / `deferred` / `decided` / `stale` |
| `candidates` | `Candidate[]` | 否 | 全部候选，长度 ≥ 2 |
| `resolution` | `Resolution \| null` | 是 | null 表示未裁决 |

`TargetView`：`{ kind, surface, term, entity, subject, predicate }`
——按 `kind` 填充相应字段，其余为空串。

`Candidate`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `index` | int | 否 | 候选序号，裁决时回传 |
| `label` | string | 否 | 给人看的说法（词条显示名 或 值的展示形式） |
| `value` / `unit` | string | 否 | 抽取歧义用；指代歧义为空串 |
| `ref` | string | 否 | 指代歧义用：词条标识；抽取歧义为空串 |
| `anchor` | string | 否 | 该候选在原文中的位置 |
| `context` | string | 否 | 该候选周围的片段 |
| `note` | string | 是 | agent 的倾向说明；**可以为空，不影响裁决** |

`Resolution`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `choice` | int | 否 | 选中的序号；`-1` 表示「都不对」 |
| `chosen` | string | 否 | 选中项的标识；`-1` 时为空串 |
| `by` | `ActorView` | 否 | 裁决者，必须是人 |
| `reason` | string | 否 | **必填** |
| `at` | string | 否 | RFC3339 |
| `produced` | string | 否 | 产出的结果标识（数据 id 或规则 id）；「都不对」时为空串 |

`DecisionResult`：`{ applied: bool, status, produced, message }`

`DecisionStats`：`{ open, deferred, decided, missing, stale }`
——`missing` 是判为「都不对」的条数。

约定：

- `Resolve` 的 `by` 在服务层校验必须是人；agent 身份一律拒绝
- `Resolve` 失败时事项状态**不变**，原因必须返回界面
- 两种歧义共用同一队列与同一套裁决接口，但 `produced` 指向的东西不同：
  抽取歧义指向一条数据，指代歧义指向一条条件指代规则。
  **调用方不需要知道区别**；需要知道的地方是落库路径，那是服务内部的事
- `Reopen` 与 `Resolve` 分开：对已裁决事项动手必须走 `Reopen`，
  避免「不小心把已定的结论改了」
- `List` 必须一并返回 `impact` 与 `impactWhy`，使界面能显示排序理由

## 待确认

1. 「都不对」在指代歧义下的含义（该词面在此处无可用义项？还是应新增一个义项？）
2. 裁决是否需要「依据」字段（当前只有理由；抽取歧义的人拍板是否需要更强的依据）
3. 事项长期未处理是否需要提示（当前只在工作台上显示放置时长）
4. 批量裁决是否需要（当前只支持逐条；批量最容易造成大面积错误）
