# 待判定：歧义的人工裁决

## 目的

接入层在原文里遇到**多个都说得通的取值**时，唯一正确的做法是**不猜**。
但「不猜」不等于「丢掉」：此前这类项只被打印到控制台，进程一退出就消失——
人无法处理，而且**歧义与缺失分不开**（都是「没抽到」）。

本层把「文本里有、但无法确定」变成**一条可处理、可追溯、可复现的待办**：
agent 提出全部候选并附带原文锚点与上下文，人在界面上选一个（或判定都不对、或暂缓），
选择过程留下核验记录，选中的候选走**与普通候选完全相同的准入路径**。

它回答的是：**人是唯一能裁决歧义的角色，那么给这个人看什么、他选完之后留下什么。**

## 术语

- **待判定事项（decision item）**：一个「有多个候选值、必须由人选」的问题。**它不是断言。**
- **候选（candidate）**：一种说得通的取值，附带原文锚点与**上下文片段**。
- **裁决（resolution）**：人对该事项做出的选择——选中某个候选、判定「都不对」、或暂缓。
- **改判**：对已裁决事项改变结论。本层**不支持覆盖式改判**（见「边界与异常」）。

## 领域规则（Given-When-Then）

### 歧义的产生

- Given 一段原文中某个谓词只能抽出 1 个取值 When 接入 Then 产出候选，**不产生待判定事项**
- Given 抽出 0 个取值 When 接入 Then **不产生**待判定事项——「没有」不是「不确定」
- Given 多次命中而取值**全部相同** When 接入 Then 视为唯一命中，产出候选，
  **不得记为歧义**——歧义是「有多个**不同**的取值」，不是「命中了很多次」
- Given 抽出 2 个以上**不同**取值 When 接入 Then 产出待判定事项并**携带全部候选**，
  **不得只报数量、不得自行择一、不得丢弃**
- Given 一个待判定事项 When 记录 Then 必须携带：主体、谓词、全部候选、来源原件、
  修订标识、采集时间、歧义原因——缺任一则不是一条可处理的事项
- Given 歧义发生在正文的一段文字中 When 记录候选 Then 每个候选必须带
  **足以判断的上下文片段**——只给一个数字，人无法判断

### 候选的提出

- Given agent 提出候选 When 记录 Then 允许携带其排序与倾向说明，
  但**必须提交全部候选**，且**不得预填选中的那个**
- Given 候选被排序 When 人查看 Then 排序理由必须可见；排序**不影响**裁决结果，
  也不得隐藏任何候选
- Given 两个候选取值相同 When 构造事项 Then **去重**；去重后不足 2 个则不是歧义

### 裁决

- Given 一个待判定事项 When 裁决 Then 裁决人**必须是人**；
  agent 不得裁决（与 `verification.spec.md` 一致）
- Given 人选中某个候选 When 裁决 Then 该候选经**准入层**校验后写入断言，
  分级不得高于该候选解析方式的允许上限（文本抽取 → 不高于 L2）
- Given 裁决产生断言 When 记录 Then 必须同时产生一条核验记录且理由必填，
  断言与核验记录**原子写入**——不得出现「断言已入库但没有对应裁决记录」
- Given 人选「都不对」 When 裁决 Then **不产生任何断言**，该谓词记为**缺失**，
  并记录理由。这是**结论**，事项视为已处理
- Given 人暂缓 When 裁决 Then 事项保持待判定，**不产生断言**，不得记为已处理
- Given 裁决完成 When 查询 Then **未被选中的候选仍然保留**——
  「当时还有哪些说法」是可追溯性的一部分
- Given 裁决产生断言 When 核验 Then 初始状态即可为「已核验」（人已经看过原文并做出判断），
  但方法只能是**编审**，除非裁决人给出更强的依据

### 失效与重开

- Given 事项来源原件的修订标识变化 When 重新接入 Then 事项**重新打开**并带上新候选，
  旧裁决保留为历史
- Given 事项已裁决且修订变化 When 新候选中**仍然包含**当初选中的取值 Then 保持已裁决
- Given 事项已裁决且修订变化 When 新候选中**不再包含**当初选中的取值 Then
  标记为**「需复核」**，**不得静默保留**旧结论
- Given 事项判定为「都不对」且修订变化 When 重新接入 Then **重新打开**——
  原文变了，「都不对」这个结论未必还成立
- Given 暂缓事项且修订变化 When 重新接入 Then 回到待判定
- Given 修订标识未变化 When 重新接入 Then 不改变已裁决事项的状态（重复接入必须幂等）
- Given 修订标识未变化但抽取结果变化 When 重新接入 Then 候选列表取本次结果；
  若已裁决事项的原选项已不在候选中，同样标记为**「需复核」**——
  原文没变而候选变了，说明判断依据变了

### 人力的分配

- Given 待判定事项多于人力 When 排序 Then 依据**影响面**（该主体被引用次数）降序，
  影响面相同则**候选数少者优先**——先清判断成本低的
- Given 排序 When 生成 Then 必须确定且可复现：同一批数据两次排序结果相同

## 验收标准

- [ ] 原文抽出多个**不同**取值时产出待判定事项，且携带**全部**候选与原文锚点
- [ ] 抽出 0 个或 1 个取值时不产出待判定事项
- [ ] 多次命中而取值相同不记为歧义，按唯一命中处理
- [ ] 每个候选带上下文片段，人不打开原文也能判断
- [ ] 候选值重复时去重；去重后不足 2 个则不产生事项
- [ ] agent 无法提交只有一个候选的事项
- [ ] 裁决人缺失或非人类时被拒绝
- [ ] 选中的候选经准入写入断言，分级不高于该候选解析方式的上限
- [ ] 裁决原子地产生断言与核验记录，核验记录缺少理由时整笔被拒绝
- [ ] 选「都不对」时不产生断言，该谓词记为缺失且记录理由
- [ ] 暂缓不产生断言，事项仍在待判定队列中
- [ ] 已裁决事项再次裁决被拒绝
- [ ] 未选中的候选在裁决后仍可查询到
- [ ] 选中的候选未通过准入校验时整笔被拒绝，事项保持待判定，原因返回给界面
- [ ] 修订变化后事项重新打开；不再包含原选项时标记为需复核
- [ ] 重复接入同一批数据不改变已裁决事项的状态
- [ ] 待判定队列可按影响面排序，且排序确定可复现

## 边界与异常

- 候选数为 0：构造事项时**拒绝**（没有候选不是歧义）
- 候选数为 1：构造事项时**拒绝**（单候选应直接走准入，不进待判定）
- 候选取值重复：按取值去重；去重后不足 2 个则**不是歧义**，不得构造事项
- 本轮接入未再产生某条已存在事项：**不自动关闭、不删除**（原件仍在，人仍可裁决），
  仅在接入报告中列出数量
- 修订变化重新接入时，候选列表以新修订为准——旧候选可能已不在原文里，
  留着会让人选出一个源里根本没有的值；已裁决事项的裁决记录不因此改变
- 裁决索引越界（含小于 -1）：**拒绝**
- 裁决人未标识、或标识为 agent：**拒绝**
- 裁决理由为空：**拒绝**——只有结论没有理由的不是裁决
- 选中的候选未通过准入（schema 未声明、量纲非法、唯一性冲突、引用不存在的实体）：
  **拒绝整笔裁决**并把准入层给出的原因返回界面，事项**保持待判定**——
  不得「先记为已裁决再报错」
- 事项已裁决而再次提交：**拒绝**。改判不是覆盖，需要新的核验记录；
  MVP 不支持改判，遇到时明确报「已裁决，不支持改判」而不是静默接受
- 来源原件缺失：事项保留，标注来源不可达，不阻断裁决（人可以凭已有上下文判断）
- 同一事项被并发裁决：后到者因「已裁决」被拒绝，不产生第二条断言
- 事项状态为「需复核」时可再次裁决：新结论产生新核验记录，旧结论保留为历史
- 「都不对」与「暂缓」不得混淆：前者是结论，后者是未处理
- 事项引用的主体/谓词在 schema 中不存在（定义变化后）：拒绝裁决并报明原因，
  不静默丢弃

## 前后端契约

方法均挂在核验工作台服务上，参数与返回均为可 JSON 序列化结构。

### `Decisions(status string, limit int) ([]DecisionItem, error)`

- `status` 可选：`open` / `deferred` / `decided` / `stale`；空串表示 **open + deferred + stale**
  （即「还需要人看的」）
- `limit <= 0` 表示不限制
- 返回按影响面降序、候选数升序排列

`DecisionItem`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 事项标识，由 (实体, 主体, 谓词, 原件) 决定，**跨修订稳定** |
| `entity` | string | 否 | 实体类型 |
| `subject` | string | 否 | 主体 |
| `predicate` | string | 否 | 谓词 |
| `reason` | string | 否 | 歧义原因（人话，含候选个数） |
| `context` | string | 否 | 歧义所在原文片段 |
| `artifact` | string | 否 | 来源原件 |
| `revision` | string | 否 | 源内容修订标识 |
| `source` | string | 否 | 来源名 |
| `status` | string | 否 | `open` / `deferred` / `decided` / `stale` |
| `candidates` | DecisionCandidate[] | 否 | 全部候选，长度 ≥ 2 |
| `resolution` | DecisionResolution | **是** | null 表示未裁决 |

`DecisionCandidate`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `index` | int | 否 | 候选序号，裁决时回传 |
| `value` | string | 否 | 取值的展示形式 |
| `unit` | string | 否 | 量纲单位，如 `percent` |
| `anchor` | string | 否 | 原文锚点 |
| `context` | string | 否 | 该候选周围的原文片段 |
| `note` | string | 是 | agent 的倾向说明；**可以为空，不影响裁决** |

`DecisionResolution`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `choice` | int | 否 | 选中的候选序号；`-1` 表示「都不对」 |
| `chosenValue` | string | 否 | 选中取值的展示形式；`-1` 时为空串 |
| `by` | string | 否 | 裁决人（人类身份） |
| `reason` | string | 否 | 裁决理由 |
| `method` | string | 否 | 核验方法，取值同 `verification.Method` |
| `evidence` | string | 是 | 依据 |
| `at` | string | 否 | RFC3339 |
| `assertionId` | string | 否 | 裁决产出的断言 ID；`-1` 时为空串 |

### `ResolveDecision(id string, choice int, by, method, reason, evidence string) (DecisionResult, error)`

- `choice >= 0` 选中该序号候选；`choice == -1` 表示「都不对」
- `by` 必填且为人类身份；`method` 可空，默认 `editorial`
- `reason` 必填
- 失败时返回 error，事项状态**不变**

`DecisionResult`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `applied` | bool | 否 | 是否成功裁决 |
| `status` | string | 否 | 裁决后的事项状态 |
| `assertionId` | string | 否 | 产出断言 ID；「都不对」时为空串 |
| `message` | string | 否 | 人话结果，含被拒原因 |

### `DeferDecision(id, by, reason string) error`

- `by` 与 `reason` 必填
- 事项状态变为 `deferred`，不产生断言

### `DecisionStats() (DecisionStats, error)`

| 字段 | 类型 | 说明 |
|---|---|---|
| `open` | int | 待判定 |
| `deferred` | int | 已暂缓 |
| `decided` | int | 已裁决（含「都不对」） |
| `missing` | int | 判为「都不对」的条数（谓词记为缺失） |
| `stale` | int | 需复核 |
