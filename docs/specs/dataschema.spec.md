# 数据定义：从文档里能确定读出来的那些关系

## 目的

文档里有大量**明确的关系**：「这个技能一段造成攻击 80% 伤害」。这类关系要能被算，
所以要被定义出来——技能的一个属性叫「一段伤害倍率」，它是百分数，取值在 0 到 1000 之间。

这里是全项目**最需要严格**的一层，因为下游的计算与答案都建立在它上面。因此每个定义必须：

| 要求 | 含义 | 不满足会怎样 |
|---|---|---|
| **写明确** | 有一句**阐述性说明**：这个字段到底是什么 | 两个人对同一个字段的理解不同，抽出来的数就不是一回事 |
| **有使用文档** | 写清什么时候用、什么时候不能用、容易和谁混 | 「不能混用」只能靠文档说清，不能靠命名约定 |
| **有确定性** | 同一份来源 + 同一套定义 → 两个人抽出同一个结论 | 数据随人而异，往下全是流沙 |
| **无歧义** | 抽不出唯一值时登记歧义，不猜 | 猜出来的值一旦进了基础数据，就再也分不清是读到的还是编的 |

它类似数学里的**阐述性定义**：先界定清楚「我说的是什么」，然后才谈得上用。

## 术语

- **定义（definition）**：对一类主体上若干属性的声明。包含身份字段、字段列表与使用文档。
- **字段（field）**：定义里的一条属性，是抽数的最小单位。
- **阐述性说明**：一句话界定该字段是什么。**不是**它的用途，也不是它的算法。
- **使用文档**：什么时候用、什么时候不能用、容易与哪些定义混。
- **抽取规则**：这个字段的值从哪来——从文档里按什么读、由公式算出、还是由调用方给出。
- **原语（primitive）**：平台内建、不可由项目定义的类型与约束。**封闭集合**。
- **量纲（unit）**：数值的计量单位。数值字段必须声明。
- **未建模（unmodeled）**：平台表达不了、但必须原样保留的内容。
- **漂移（drift）**：定义与数据之间的不一致——定义里有而数据里从没有、数据里有而定义里没声明。

## 领域规则（Given-When-Then）

### 一个定义要齐备才算可用

- Given 一个定义 When 登记 Then 必须齐备：稳定标识、显示名、**阐述性说明**、
  **使用文档**、身份字段、字段列表、依据（哪份文档或哪次交叉校验支撑它）、拍板者与理由
- Given 一个定义 When 缺使用文档 Then **不可用**：不能用于抽数、不能被计算引用
- Given 一个字段 When 登记 Then 必须齐备：稳定标识、显示名、**阐述性说明**、
  类型、量纲（数值时）、约束、**抽取规则**
- Given 一个定义的显示名 When 登记 Then 必须**挂到一个词条上**（见 `dict.spec.md`）——
  字段名与「我们说的东西」是同一套指代，不得各搞一套
- Given 一个定义 When 拍板 Then 拍板针对**具体哪一版**；此后定义变更，拍板作废（见 `agent.spec.md`）

### 确定性

- Given 一套定义与一份来源 When 两个人各自抽取 Then 必须得到**同一个结论**；
  做不到就说明定义不够明确，**改定义**而不是让它随人而异
- Given 一个字段的抽取规则 When 声明 Then 必须**可复现**：写清从哪读到、按什么读
- Given 抽取过程中遇到多种读法 When 处理 Then **登记歧义**
  （机制见 `decision.spec.md`），携带全部候选与原文位置，由人裁决，不猜
- Given 抽取出来的值 When 记录 Then 必须带上**它是怎么读出来的**（解析方式），
  且解析方式决定它的分级上限——回退解析出来的值**不得**被当作直引（见 `basicdata.spec.md`）
- Given 一个字段由公式算出 When 记录 Then 它是派生值，不是直引值；
  两者在分级上必须可区分

### 不能混用

- Given 两个定义 When 描述同一类主体上的同一件事而口径不同 Then **报冲突**，
  不自动择一，也不允许两个并存而不标记
- Given 一个字段名 When 已被某个定义使用 Then 不得在另一个定义里表示不同的含义
- Given 一个定义 When 与其他定义容易混 Then **必须在使用文档里写明差异**——
  「容易混」本身就是必须写下来的信息
- Given 一个显示名 When 与另一个字段的显示名相同 Then 报告并指出两个字段，
  由人决定是合并还是改名
- Given 一个定义 When 引用另一个定义的字段 Then 必须显式声明引用关系，
  不得靠名字相似猜

### 类型原语（封闭集合，11 个）

平台**不认识任何游戏概念**——「鬼火」「技能倍率」「御魂」全部由定义用通用原语表达。
换一个游戏只换定义，不改代码。这是通用路线的全部意义，也是它唯一的代价：表达力受限于原语集合。

| 原语 | 含义 | 必需附加声明 |
|---|---|---|
| `text` | 短文本 | — |
| `longtext` | 长文本（检索与展示语义不同） | — |
| `number` | 数值（整数/小数由精度决定） | **量纲** |
| `bool` | 布尔 | — |
| `date` | 日期（无时刻） | — |
| `datetime` | 日期与时刻 | — |
| `enum` | 封闭取值集合 | 取值列表 |
| `ref` | 引用另一类主体的身份 | 目标类型 |
| `list` | 同质列表 | 元素类型 |
| `object` | 嵌套结构 | 子字段列表 |
| `unmodeled` | **逃生舱**：原样保存，不校验 | — |

设计取舍：

- **不设 `integer`**：用 `number` + `precision: 0` 表达，保持正交。
- **不设「标识符」类型**：身份由约束 `identity` 声明，类型仍是 `text` 或 `number`。
- **`text` 与 `longtext` 分开**：两者在检索、截断、展示上的语义不同。
- **`unmodeled` 不可省**：外部出现平台表达不了的机制时，必须能「**未建模但已记录**」，
  而不是丢弃或拒绝。

### 约束原语

**字段级（单字段自洽）**

| 约束 | 适用类型 | 含义 |
|---|---|---|
| `required` | 全部 | 该字段必须出现 |
| `nullable` | 全部 | 出现时是否允许空值（与 `required` 不同） |
| `identity` | text / number | 作为该类主体的身份字段 |
| `min` / `max` | number, date, datetime | 取值范围 |
| `minLength` / `maxLength` | text, longtext | 长度范围 |
| `pattern` | text | 模式 |
| `precision` | number | 小数位数（0 即整数） |
| `unit` | number | **量纲**，必填 |
| `default` | 全部 | 缺省值 |

**记录级（同一记录内跨字段）**

| 约束 | 含义 |
|---|---|
| `atLeastOne: [字段…]` | 所列字段至少有一个出现 |
| `mutuallyExclusive: [字段…]` | 所列字段至多一个出现 |
| `requiredIf: { when: {字段: 值}, then: [字段…] }` | 条件必填 |
| `compare: { left, op, right }` | 两个字段比较，`op ∈ {lt, lte, eq, ne, gte, gt}` |

记录级约束**只能取自上表这四种固定形式**，不允许任意表达式。
引入表达式语言等于把校验逻辑变成不可静态检查的字符串；而这四种形式覆盖了实测需要的全部情形。

**集合级（需跨记录查询）**

| 约束 | 含义 |
|---|---|
| `unique` | 取值唯一，可多字段组合 |
| `scope` | 唯一性的作用域：全局，或限定在某父记录内 |
| `ref` 完整性 | 引用目标必须存在 |

集合级约束**必须由存储层保证**，不得在应用层「先查再插」——后者在并发下有竞态。

### 值的三态（有值 / 未知 / 空 / 缺失）

字段取值有四种状态，必须**可区分、可分别计数**：

| 状态 | 含义 | 满足 `required` | 满足 `nullable: false` |
|---|---|---|---|
| **有值** | 有确定的取值 | ✅ | ✅ |
| **未知** | 该有值，但我们不知道它是什么 | ✅ | ✅ |
| **空值** | 明确无值 | ✅ | ❌ |
| **缺失** | 字段未出现 | ❌ | — |

关键：**「未知」既不是空值，也不是缺失**，它是「已知未知」的载体。
没有这一态，新增必填字段时既有数据只能靠**编造一个看起来合理的值**来满足约束——
那正是数据失准的起点。

- Given 一个字段为「未知」 When 校验 `required` Then 通过
- Given 一个字段为「未知」 When 被答案引用 Then 必须标注
- Given 统计覆盖率 When 存在「未知」值 Then **不计为已填充**
- Given 查询或统计 When 四态并存 Then 必须能分别计数

### 枚举的开放性

平台对「结构错误」与「数据取值」采取**相反**的策略：

| 情形 | 策略 | 理由 |
|---|---|---|
| 定义里用了未知的类型名或约束名 | **拒绝加载，指出位置** | 定义由我们自己写，笔误必须被抓到 |
| 数据取值不在枚举集合内 | **接受并标记「未建模取值」** | 数据来自外部，新版本会出现新值，丢弃等于信息损失 |

这是「严格防错」与「不丢信息」的调和点：**对我们写的东西严，对别人给的东西宽但不静默。**

- Given 数据取值不在枚举内 When 校验 Then 接受并标记，**不得拒绝，也不得静默通过**
- Given 同一枚举积累了未建模取值 When 达到阈值 Then 提示补充取值

### 量纲

- Given 一个数值字段 When 声明 Then 必须声明量纲；缺失即拒绝
- Given 两个来源的同一事实量纲不同 When 比对 Then 按换算关系归一后比对
- Given 缺少两个单位之间的换算关系 When 比对 Then **拒绝比对**并指出缺失的单位对
- Given 一条值未声明量纲 When 参与比对 Then 拒绝
- Given 换算关系成环 When 加载 Then 拒绝

### 逃生舱与未建模

- Given 某个字段无法用现有原语表达 When 声明 Then 允许用 `unmodeled`，原样保存
- Given 使用了 `unmodeled` When 统计覆盖率 Then 计为**未建模**，不计为已填充
- Given 内容被引用进答案 When 其中含未建模成分 Then 答案必须标注
- Given 需要新增原语 When 评估 Then 必须先证明现有原语的组合无法表达；
  **不得**因为单个项目的需要而就地扩展原语集合

### 漂移检测

- Given 定义里有而数据里从未出现的字段 When 检查 Then 列出——
  可能是定义写了没人填，也可能是抽数一直没生效
- Given 数据里出现而定义里未声明的字段 When 检查 Then 列出，并说明它**会被拦下**
  （见 `admission.spec.md`）——未声明的字段不得进入基础数据
- Given 必填字段在数据里没有值 When 检查 Then 单独标出，与「全部为空」区分
- Given 漂移 When 报告 Then 只报告**差异**，不重复报告已经归因过的合法差异

### 演进

- Given 定义发生变更 When 评估 Then 列出**全部**差异并逐项归类：
  兼容 / 破坏 / 无法自动归类
- Given 存在无法自动归类的差异 When 处理 Then 标为**待人工判定**，
  **不得默认为兼容**
- Given 一批变更中含破坏性项 When 处理 Then **整批按最高风险处理**
- Given 一次演进 When 执行 Then 先产出**影响清单**（含逐条标识与冲突点）；
  影响清单非空时，**未经确认不得执行**
- Given 新增必填字段 When 迁移 Then 既有记录标为**未知**，而不是编造一个值
- Given 需要回填 When 制定策略 Then 只接受固定形式，**表达式形式被拒绝**；
  回填值的来源记为「迁移回填」，不伪装成原始来源
- Given 一次演进 When 失败 Then 定义与数据**均回滚**到演进前；中断后恢复不得留下半迁移状态
- Given 同一次演进 When 重复执行 Then 幂等
- Given 演进中取值被改动的记录 When 完成 Then 其分级与拍板状态**回到未拍板**，
  不得沿用旧结论
- Given 受阻的记录 When 处理 Then 保留原值、逐条报告、转入人工队列
- Given 一次演进 When 审计 Then 能回答「某条记录在哪次演进中被改成了什么」

## 验收标准

- [ ] 缺使用文档的定义不可用，不能被抽数或计算引用
- [ ] 定义的字段齐备性被校验：标识、显示名、阐述性说明、类型、量纲、抽取规则
- [ ] 显示的字段名挂到词条上
- [ ] 定义变更后原拍板作废，需重新拍板
- [ ] 同一来源与同一套定义抽出的结论一致（确定性）
- [ ] 抽取规则可复现，写清从哪读、按什么读
- [ ] 抽不出唯一值时产出歧义事项，携带候选与原文位置
- [ ] 抽取值带上解析方式，且解析方式决定分级上限
- [ ] 派生值与直引值在分级上可区分
- [ ] 两个定义口径冲突时报出，不自动择一
- [ ] 同一字段名在不同定义里表示不同含义时被拒绝
- [ ] 显示名重复时报出并指出两个字段
- [ ] 未知类型名或约束名导致加载失败，并指出位置
- [ ] `list` 未声明元素类型、`object` 未声明子字段、`ref` 未声明目标时被拒绝
- [ ] 数值字段未声明量纲时被拒绝
- [ ] 记录级约束出现四种固定形式以外的写法时被拒绝
- [ ] 集合级唯一约束在并发写入下成立
- [ ] `identity` 字段未声明为 `required` 时被拒绝
- [ ] 主体类型未声明身份字段时被拒绝
- [ ] 「未知」「空值」「缺失」三态可区分且可分别计数
- [ ] 「未知」值满足 `required` 但不计入已填充
- [ ] 枚举未建模取值被接受且被标记，达到阈值时提示补充
- [ ] `unmodeled` 字段计为未建模，不计入已填充
- [ ] 含未建模成分的答案被标注
- [ ] 量纲不同的两源值在换算后比对；缺换算关系时拒绝比对并指出单位对
- [ ] 换算关系成环时拒绝加载
- [ ] 定义与数据之间的双向漂移都能检出
- [ ] 必填但无值的字段被单独标出
- [ ] 演进产出影响清单，未确认不得执行
- [ ] 无法自动归类的差异标为待人工判定，不默认为兼容
- [ ] 含破坏性项时整批按最高风险处理
- [ ] 新增必填字段时既有记录标为未知，不编造值
- [ ] 回填策略的表达式形式被拒绝；回填来源记为「迁移回填」
- [ ] 演进失败时定义与数据全部回滚；重复执行幂等
- [ ] 演进审计能回答「某条记录在哪次演进中被改成什么」
- [ ] 嵌套深度超限被拒绝；自引用未显式允许时被拒绝

## 边界与异常

- 空类型名、空约束名、空定义标识：拒绝
- `list` 的元素类型为 `list` 且嵌套超过深度上限：拒绝
- `enum` 取值为空集合：拒绝
- 量纲为平台未知的单位且无换算关系：允许声明，但参与比对时拒绝
- `identity` 字段类型为 `object` 或 `list`：拒绝
- 同一字段同时声明 `atLeastOne` 与 `mutuallyExclusive` 且互相矛盾：拒绝
- `requiredIf` 的 `when` 指向的字段不存在：拒绝
- `compare` 的 `left` 与 `right` 量纲不同且无换算：拒绝
- 定义声明的原语版本高于平台支持：拒绝加载；低于则允许但标注为旧版
- `unmodeled` 字段内嵌套 `unmodeled`：允许（整体不透明）
- 两个定义的标识相同：拒绝
- 定义没有依据（说不出它是从哪份文档或哪次校验来的）：拒绝登记——
  定义是事实源，无依据的定义等于人凭印象定的
- 定义的使用文档为空字符串或纯占位：视为缺文档，不可用

| `statement` | string | 否 | **阐述性说明**：这个字段是什么 |
| `type` | string | 否 | 原语之一 |
| `unit` | string | 否 | 量纲；非数值字段为空串 |
| `constraints` | `string[]` | 否 | 人类可读的约束表述 |
| `extract` | `ExtractView` | 否 | 抽取规则 |
| `required` | bool | 否 | |
| `basis` | `Basis[]` | 否 | |

`ExtractView`：`{ kind, source, rule, maxConfidence, maxConfidenceText }`，
`kind` 为 `pattern`（从文档按模式读）/ `compute`（由公式算出）/ `input`（由调用方给出）/ `manual`（人工填写）；
`maxConfidence` 是该抽取方式的分级上限——**回退解析不得被当作直引**。

`Basis`（依据）是跨部件共用的类型，定义见 `document.spec.md`：
`{ kind: "doc" | "tool-run" | "data", ref, note }`。定义与字段的依据**不可为空**。

`MigrationPlan`：`{ id, changes, diffs, risk, riskText, affected, unresolved, blocked }`
——`risk` 为 `compatible` / `breaking` / `unknown`；含 `unknown` 时整批按最高风险处理；
`affected` 是受影响的记录数，`unresolved` 是无法自动归类的差异，`blocked` 是受阻记录。

约定：

- 每个读接口都返回 `ready` 与 `readyText`：**「不可用」必须在界面上看得见**，
  否则使用者会以为定义生效了而其实没有
- `Put` 在服务层校验使用文档非空、字段齐备、显示名已挂词条；任一不满足即拒绝并说明
- `Plan` 与 `Apply` 分开：影响清单必须先给人看，确认之后才允许落盘
- 原语清单可被外部读取，使调用方知道平台支持什么

## 附：游戏概念如何用通用原语表达

本表用于验证「通用平台能否表达阴阳师的机制」。若某一行无法表达，说明原语集合有缺口。

| 游戏概念 | 表达方式 |
|---|---|
| 鬼火（资源） | 独立定义 + `ref`，或 `enum` 的取值 |
| 鬼火上限 | `number` + 量纲 `count` + `min`/`max` |
| 「鬼火后来又分了几种」 | **新增枚举取值或新增记录**，不改原语 |
| 技能倍率 80% | `number` + 量纲 `percent` + `precision` |
| 技能 5 级倍率 | `list` of `object{ level: number, value: number(percent) }` |
| 式神属性面板 | `object` 嵌套，各子字段为 `number` + 各自量纲 |
| 暴击 50% vs 0.5 | 同一 `number` 字段，靠量纲归一对齐 |
| 「无视 20% 防御」 | 拆成字段：无视防御，值 20，量纲 `percent` |
| 触发条件「当总攻击最高时」 | **限定条件**，不是定义 |
| 「同一效果在不同条件下不同」 | **两条限定条件不同的值并存**（见 `basicdata.spec.md`） |
| 御魂套装效果 | 独立定义 + `ref` |
| 未建模的新机制 | `unmodeled` 字段 + 标记，不丢弃 |

**关键**：条件性一律落在**限定条件**上，不落在定义上。
定义描述「字段长什么样」，数据描述「什么条件下是什么」。
