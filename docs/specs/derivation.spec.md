# 派生与缓存：中间产物的层次

## 目的

定义**断言**与**方案**之间的中间产物。

此前只有两层：`原件 → 断言 → 方案`。但实际存在一整层中间物：

- 式神满级面板（由基础属性算出，**伤害、配速、斗技都要用**）
- 技能倍率表（抽取加确认后的结果）
- 御魂套装的属性总和
- 单位归一后的统一数值

这些既不是外部来的断言，也不是场景的输出。**它们的生命周期此前没有被定义。**

核心问题有两个：

1. **该不该固化成数据？** 固化则可能上下文爆炸，不固化则可能重复计算。
2. **固化了什么时候失效？** 公式改了、源数据改了，固化的值不能继续装作是新的。

## 术语

- **派生值（derived value）**：由公式对断言求值得到的结果。
- **上下文中立（context-free）**：不依赖任何场景上下文。**这是能否固化的判据。**
- **上下文相关（context-bound）**：依赖场景上下文（如某阵容、某副本、某版本）。
- **派生断言**：已固化的、上下文中立的派生值。它是断言，分级为 L3，带推导链。
- **场景中间结果**：上下文相关的派生值。**不固化、不共享。**
- **缓存（cache）**：可重算结果的暂存。**它不是断言。**
- **输入指纹（fingerprint）**：一份结果所依赖的全部输入与公式版本的摘要。

## 一、五层图景

```
原件 artifact                  ← 接入层产出，来自外部
  ↓ 解析 + 准入
断言 assertion                 ← 项目级共享；是事实；要溯源、要核验
  ↓ 计算（上下文中立）
派生断言 L3                    ← 项目级共享；是事实；有推导链；可核验
  ↓ 计算（上下文相关）
场景中间结果                    ← 场景私有；不是事实；不固化；只在方案中留痕
  ↓
方案 plan                      ← 场景私有；持久化
```

**缓存是横切的**，不属于任何一层。任何一层的求值结果都可以缓存，但缓存永远不是断言。

## 二、固化判定

一个派生值该不该存下来，判据只有一个：**是否上下文中立**。

| 派生值 | 上下文中立？ | 处置 |
|---|---|---|
| 式神满级面板 | ✅ 与场景无关 | **固化为派生断言**，全项目共享 |
| 技能各级倍率 | ✅ | 固化为派生断言 |
| 御魂套装属性总和 | ✅ | 固化为派生断言 |
| 「这套阵容对某副本的伤害」 | ❌ 依赖阵容与副本 | **不固化**，场景中间结果 |
| 「按我当前配置还差多少速度」 | ❌ 依赖个人档案 | **不固化**，场景中间结果 |

### 固化 vs 缓存的选择

即使上下文中立，也不一定固化——还要看**上下文组合数**：

- Given 一个上下文中立的派生值 When 其参数组合少 Then **固化为断言**（每个组合一条）
- Given 一个上下文中立的派生值 When 其参数组合多而单次计算便宜 Then **作为缓存**，不固化
- 判据：固化的存储与维护成本，是否高于重复计算

### 重复出现的信号

- Given 两个场景各自产出了**相同**的中间结果 When 检测到 Then 提示该结果**应提升为派生断言**
- 理由：两个场景都需要它，说明它其实与场景无关——是之前判定错了

## 三、缓存：与断言的区别

这是本规格最需要说清的一条界限。

| | 断言 | 缓存 |
|---|---|---|
| 是不是事实 | ✅ | ❌（只是计算结果的暂存） |
| 要不要溯源 | ✅ | ❌（溯源在公式与输入上，不在结果上） |
| 要不要核验 | ✅ | ❌（可重算，核验无意义） |
| 能否被方案引用为依据 | ✅ | ❌ |
| 能否丢弃 | ❌ | ✅ 随时可丢，无数据损失 |
| 失效条件 | 来源变化 | 输入或公式的指纹变化 |

**关键规则：缓存不得被呈现为已核验的事实。**
一条计算结果值若能作为「依据」被方案引用，它就必须是断言，而不是缓存。

## 四、失效传导

派生值的新鲜度不靠人工维护，靠**依赖链自动传导**：

```
源断言被驳回
  → 依赖它的派生断言标记「失效」
    → 依赖该派生断言的场景中间结果不再产出
公式被修改
  → 引用该公式的全部派生断言标记「待重算」
源页面修订标识变化
  → 由该源产出的断言转「待重核验」
    → 其下游派生断言标记「待重算」
```

## 领域规则（Given-When-Then）

### 固化

- Given 一个派生值 When 它上下文中立 Then 可固化为派生断言，并带推导链
- Given 一个派生值 When 它依赖场景上下文 Then **不得固化为断言**，只作为场景中间结果
- Given 派生值 When 被固化 Then 必须记录其分级（L3）、推导链与所依赖的公式版本
- Given 两个场景产出相同中间结果 When 检测到 Then 提示提升为派生断言

### 缓存

- Given 一个结果 When 被缓存 Then 必须记录其**输入指纹**（所依赖的断言标识与版本、公式版本、参数）
- Given 缓存被使用 When 指纹不匹配 Then **重算或拒绝使用**，不得返回旧值
- Given 缓存 When 被呈现 Then **不得**表现为已核验的事实
- Given 缓存 When 被清空 Then 不产生任何数据损失
- Given 结果含**未标记的随机量** When 处理 Then 求值被拒（见 `computation.spec.md`）
- Given 结果含**已标记的随机量** When 缓存 Then 只能缓存其**分布或期望**，不得缓存单次抽样值
- Given 缓存结果 When 被方案引用为依据 Then 拒绝——依据必须是断言

### 失效传导

- Given 派生断言的推导链上任一环变化 When 检测到 Then 标记为「待重算」
- Given 公式发生变更 When 记录 Then 引用该公式的全部派生断言标记为「待重算」
- Given 源断言被驳回 When 记录 Then 依赖它的派生断言标记为「失效」，不得再被引用
- Given 一个派生断言被重算 When 完成 Then 产生新值并**保留旧值的历史**（与 `migration.spec.md` 的原子应用一致）
- Given 存在「待重算」的派生断言 When 场景运行 Then 允许运行，但输出必须标注

### 场景中间结果

- Given 场景中间结果 When 场景运行结束 Then 只在方案的留痕中保留，**不作为共享数据**
- Given 场景中间结果 When 被持久化 Then 必须连带其输入指纹，使其可判断是否仍然有效

### 引用完整性

- Given 一个方案 When 引用派生断言 Then 必须记录该断言的版本
- Given 一个方案 When 引用缓存结果 Then **拒绝**

## 验收标准

- [ ] 上下文中立的派生值可固化为 L3 断言并带推导链
- [ ] 上下文相关的派生值不被固化为断言
- [ ] 固化时记录所依赖的公式版本
- [ ] 两个场景产出相同中间结果时产生提升提示
- [ ] 缓存记录输入指纹
- [ ] 指纹不匹配时缓存不被使用
- [ ] 缓存不被呈现为已核验事实
- [ ] 清空缓存不产生数据损失
- [ ] 随机量的缓存只存分布或期望，不存单次抽样
- [ ] 方案引用缓存作为依据时被拒绝
- [ ] 推导链上环变化导致派生断言标记「待重算」
- [ ] 公式变更导致引用它的派生断言标记「待重算」
- [ ] 源断言被驳回导致下游派生断言标记「失效」
- [ ] 重算保留旧值历史
- [ ] 存在「待重算」断言时场景仍可运行，但输出标注
- [ ] 场景中间结果不被其他场景读为共享数据
- [ ] 方案引用派生断言时记录其版本

## 边界与异常

- 派生断言的推导链存在环：拒绝，不得重算
- 推导链深度过大：允许但标记，并提示可能需要中间固化
- 缓存与断言同名同键但值不同：以断言为准，缓存被丢弃
- 缓存损坏或不可读：丢弃并重算，**不得报为数据错误**
- 公式被删除但仍有派生断言引用它：这些断言标记「失效」
- 派生断言的输入包含「未知」值：允许，但结果也必须携带该未知性，**不得当作确定值**
- 派生断言的输入包含未核验断言：允许，但派生断言的可信度**不得高于其依赖的最低可信度**
- 场景中间结果引用了已被驳回的派生断言：该次运行中止
- 同一派生值在不同时间算出不同结果（公式未变、输入未变）：报为**确定性被破坏**，属严重错误

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 「待重算」与「失效」的派生断言必须可被外部查询
- 缓存状态（命中/失效/大小）必须可被运维查询与清理
- 方案必须能追溯它所引用的派生断言的**版本**，而不只是标识

## 待确认

1. 「参数组合数多」的判定阈值由谁定
2. 派生断言是否与普通断言存在同一存储中（倾向：是，只是分级为 L3）
3. 缓存是否跨项目共享（倾向：**否**，项目隔离）
4. 是否允许手动强制固化为断言（覆盖自动判定）
5. 场景中间结果是否需要持久化，还是仅存在于方案留痕中

## 附一：与经验层的边界

**派生断言不是经验。** 二者容易混淆，因为都"由推导或归纳而来"：

| | 派生断言 | 经验（见 `experience.spec.md`） |
|---|---|---|
| 性质 | **事实** | **判断** |
| 归属 | **项目** | **场景** |
| 上下文中立 | ✅ | ❌ 围绕用途 |
| 验证方式 | 算例可复现 | 依据与样本 |
| 责任 | 无人格 | **有提出者与批准者** |

**本规格的「上下文中立」判据只适用于派生值，不适用于经验。**
经验挂在场景下，因为它是围绕一个用途积累的。

## 附二：本规格补齐的缺口

此前链路为 `原件 → 断言 → 方案`，缺少中间层。补齐后：

| 层 | 共享范围 | 是否事实 | 是否需核验 |
|---|---|---|---|
| 原件 | 项目 | — | — |
| 断言 | 项目 | ✅ | ✅ |
| **派生断言** | **项目** | ✅ | ✅ |
| 场景中间结果 | 场景 | ❌ | ❌ |
| **经验** | **场景** | ❌（是判断） | ✅ 人批准 |
| 方案 | 场景 | — | — |
| 缓存（横切） | 项目 | ❌ | ❌ |

判据是**上下文中立性**：中立 → 项目级；否则 → 场景级。
这与 `scenario.spec.md` 的结论一致：**项目是隔离边界，场景是用途边界。**
