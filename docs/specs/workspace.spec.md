# 工作台：三层、六部件与 Case

## 目的

界面的首要任务不是好看，而是让人**一眼看出自己在哪一层、手上这个东西归谁**。

新结构里这件事最容易出错：项目级的文档、词表、数据定义、基础数据都是**只读**的，
Case 只能写自己的经验与数据表。如果界面上不标清楚，人就会在 Case 里以为改了项目级，
或者反过来以为经验是全局的。

因此界面按三层组织，并把两个分界**显式画出来**：

```
平台
└─ 项目 <选择器>
   ├─ 概览             六部件各自什么规模、就绪没有、缺它会怎样
   ├─ 建设             项目级六部件（主对话 / 工具 / 文档 / 词表 / 数据定义 / 基础数据）
   ├─ 待办             人唯一需要动手的地方：待拍板、待裁决
   └─ Case <选择器>
      ├─ 上下文        干什么事、核心数据、核心文档、正常情况下怎么用
      ├─ 分析          给条件要答案
      ├─ 经验          可以改、可以删，但改动留痕
      └─ 数据表        Case 自己的工作数据
```

**没有独立的「核验队列」入口**：这个结构里人负责提要求与拍板，
交叉校验是主对话 Agent 的活。人需要动手的地方集中在「待办」——
待拍板（内容要进项目级）与待裁决（歧义要人来定）。

## 术语

- **工作台（workspace）**：整个界面。它同时持有一个「当前项目」与一个「当前 Case」。
- **建设区**：项目级六部件的页面。在这里的写入都由主对话 Agent 协助、需人拍板。
- **待办区**：待拍板与待裁决两个列表。**人唯一必须动手的地方。**
- **Case 工作区**：Case 自己的四个页面（上下文 / 分析 / 经验 / 数据表）。
- **只读呈现**：项目级内容出现在 Case 工作区里时的形态——可看、可跳转、**不可改**。

## 领域规则（Given-When-Then）

### 三层与导航

- Given 工作台启动且未指定项目 When 加载 Then 取项目列表的第一个；
  列表为空时**明确提示「还没有项目」**并给出建立入口，不得指向不存在的位置
- Given 项目列表 When 显示 Then 只列出**结构完整可加载**的项目；
  结构不完整的单独列出并说明缺什么，不混在可用项目里
- Given 切换到新项目 When 加载失败 Then **保持原项目不变**并返回失败原因；
  不得留下一个半加载的项目
- Given 切换项目成功 When 完成 Then 当前 Case 重置为该项目的第一个 Case；
  没有 Case 时当前 Case 为空并说明这不是错误
- Given 当前项目 When 顶部展示 Then 必须同时显示项目名与**完整位置**——
  两个项目可能同名，靠位置区分
- Given 切换 Case When 完成 Then **只重取 Case 级视图**；
  项目级视图（工具、文档、词表、数据定义、基础数据）**不重新取数也不变样**
- Given 一个项目 When 概览展示 Then 必须逐部件给出：**规模**（多少条内容）、
  **就绪情况**（可用 / 空 / 不完整 / 失败）、**缺它会导致什么**——
  只给一个总数，人无法判断这个项目能不能用
- Given 项目没有任何 Case When 显示 Then 说明「这个项目还没有 Case」并给出建立入口

### 归属必须可见

这是本规格最硬的一条：**项目级与 Case 级在界面上必须一眼可辨。**

- Given 项目级内容出现在 Case 工作区里 When 显示 Then 必须带**只读标识**，
  并说明「这是项目级的，要改请走主对话」
- Given Case 工作区 When 呈现 Then **不出现**任何直接修改项目级内容的入口——
  界面上能点到的写操作必须在服务层也通不过（见 `architecture.spec.md`）
- Given 人在 Case 里发现项目级问题 When 想记录 Then 界面给出的路径是
  **写一条上报经验**，而不是一个被禁用的按钮
- Given Case 的经验与数据表 When 显示 Then 标明「属于本 Case」，
  并说明其他 Case 看不到
- Given 一个数字 or 一条内容 When 显示 Then 必须能看出它属于项目级还是 Case 级

### 主对话界面

- Given 一个项目 When 打开主对话 Then 支持**多个会话**：可新建、可继续、可归档
- Given 一次对话 When Agent 回答 Then 必须显示它**动了什么**：
  改了哪个部件的哪些条目——只说「我整理好了」而看不出改了什么，等于没有交代
- Given 一次对话 When Agent 想改项目级 Then 界面显示为**待拍板提议**，
  而不是已经生效的改动
- Given 一条提议 When 显示 Then 必须给出：改哪个部件、一句话说清要改什么、
  **改动前后的差异**、凭什么改、**出自哪个会话的哪一处**（可跳转）
- Given 会话记录 When 显示 Then 标注它**不是事实源**：
  结论要生效必须落到部件或经验里
- Given Agent 不可用 When 显示 Then 明确说明哪些动作不可用及原因；
  其余内容**全部仍可读**——不得因为 Agent 挂了就让项目打不开
- Given 一个会话 When 很久未用 Then 可归档；归档后仍可读，不可继续

### 待办：人唯一需要动手的地方

- Given 一个项目 When 有待拍板项 Then 每条显示：部件、要改什么、差异、依据、来源会话；
  可**逐条**或**批量**拍板，且每批都要留下理由与拍板者
- Given 一次拍板 When 提交 Then 记录拍板者与理由；
  拍板者必须是**人**，界面不得提供「以 agent 身份拍板」的路径
- Given 一个待裁决项 When 显示 Then 必须给出**全部候选与上下文片段**，
  使人**不打开原文也能判断**；并给出「都不对」与「暂缓」两个出口
- Given 一个歧义项 When 出现在词表页或数据定义页 Then 它同时出现在待裁决列表里；
  **同一件事只有一处队列**，不得在多个页面各排一次
- Given 待裁决项 When 提交裁决 Then 记录选择、理由、裁决者；
  选「都不对」是一个合法结论，不得要求必须选一个
- Given 待办都为空 When 显示 Then 说明「没有待处理」以及**这只说明没有待你决定的事**，
  不说明数据已经正确
- Given 一个答案 or 一条数据 When 显示 Then 不存在一个「已核验」的状态流转，
  也不存在核验队列；分级与来源**可查**（见 `basicdata.spec.md`）但不排队

### 命名与显示

这一条直接来自使用者的原话：「里面有很多都是变量没有 label，看不懂什么意思。」

- Given 界面上出现一个字段、词条、单位、类型、分级、状态、参与者、主体、依据、
  修订标识 When 显示 Then 必须给出**中文名**，并把原始标识符**同时**显示
- Given 定义里没有中文名 When 显示 Then **退回显示标识符**，
  并说明「暂无中文名」——**不编名字**：一个听起来合理的错名字比看不懂更糟
- Given 界面与命令行 When 显示同一件事 Then 使用**同一套命名**
- Given 一个中文名 When 来自词条 Then 点它可跳到该词条（见 `dict.spec.md`）
- Given 一个标识符 When 显示 Then 必须可复制——
  人要拿它去对账、去写在 YAML 里

### 通用呈现约束

- Given 任一列表为空 When 显示 Then 必须说明「没有」以及**这意味着什么**，
  不得留白——留白与「加载失败」在界面上无法区分
- Given 一次加载失败 When 显示 Then 错误必须可见并给出重试入口；不得静默失败
- Given 界面上的数字 When 显示 Then 必须可追溯到它的来源
  （哪个项目、哪个部件、哪一版）；不可追溯的数字不得出现在界面上
- Given 一条内容 When 带了来源与依据 Then 依据必须**可跳转**：
  跳到文档的哪一段、哪条数据、哪条经验、哪次工具执行
- Given 一个答案 When 显示 Then 必须同时显示：用了哪些数据与文档、
  未核验比例、所依据内容的版本标识、以及全部警告（关键假设失效、公式未验证、依据已变）
- Given 一个条件（输入） When 生成表单 Then 必须显示单位与范围；
  缺这两个的表单会产出不可比的值
- Given 一次操作失败 When 处理 Then **保留人已填的内容**——
  那正是人最需要保留刚才填了什么的时候
- Given 分级、状态、争议 When 显示 Then 必须有可区分的视觉标识；
  直引与推断长得一样，等于让人盲信

## 验收标准

- [ ] 没有项目时给出明确提示与建立入口，不指向不存在的位置
- [ ] 结构不完整的项目单独列出并说明缺什么
- [ ] 切换项目失败时保持原项目不变并返回原因
- [ ] 切换项目成功后当前 Case 重置为第一个 Case
- [ ] 顶部同时显示项目名与完整位置
- [ ] 切换 Case 只重取 Case 级视图，项目级视图不变
- [ ] 项目概览逐部件给出规模、就绪情况与缺它的后果
- [ ] 没有 Case 的项目给出明确说明
- [ ] Case 工作区里的项目级内容带只读标识
- [ ] Case 工作区不出现直接修改项目级的入口
- [ ] 在 Case 里发现项目级问题时的路径是写上报经验
- [ ] Case 级内容标明归属本 Case 且其他 Case 不可见
- [ ] 主对话支持多会话：新建、继续、归档
- [ ] Agent 每次回答显示它动了什么
- [ ] Agent 改项目级时显示为待拍板提议而非已生效
- [ ] 提议显示部件、摘要、差异、依据与来源会话，且来源可跳转
- [ ] 会话标注不是事实源
- [ ] Agent 不可用时其余内容仍可读，不可用动作有明确说明
- [ ] 待拍板项可逐条或批量拍板，每批留下理由与拍板者
- [ ] 拍板者必须是人的路径，界面无 agent 拍板入口
- [ ] 待裁决项给出全部候选与上下文片段，不打开原文也能判断
- [ ] 待裁决项提供「都不对」与「暂缓」两个出口
- [ ] 同一歧义只在一处队列出现
- [ ] 待办为空时说明「只说明没有待你决定的事」
- [ ] 界面上不存在核验队列入口与「已核验」状态流转
- [ ] 字段、词条、单位、类型、分级、状态等都有中文名
- [ ] 中文名与原始标识符同时显示
- [ ] 没有中文名时退回显示标识符并说明，不编造
- [ ] 界面与命令行使用同一套命名
- [ ] 中文名可跳到词条，标识符可复制
- [ ] 空列表说明「没有 + 这意味着什么」
- [ ] 加载失败可见并可重试
- [ ] 界面数字可追溯到来源
- [ ] 依据可跳转到具体位置
- [ ] 答案显示所用数据与文档、未核验比例、版本标识与全部警告
- [ ] 条件表单显示单位与范围
- [ ] 操作失败时保留已填内容
- [ ] 分级与状态有可区分的视觉标识

## 边界与异常

- 工作台启动时项目结构损坏：显示失败原因与位置，进入「没有可用项目」状态
- 项目在会话期间被外部删除：下一次取数时报错，**不静默返回空**
- 项目在会话期间被外部修改：下次加载重新校验并报告差异
- 一个部件加载失败：其余部件仍可读，失败的部件在概览里标红并说明；
  不得让整个项目变成打不开
- 两个项目同名：允许，界面上显示完整位置
- 运行中切换项目或 Case：本次结果作废，不得把 A 的结果显示在 B 之下
- Case 处于「未就绪」（上下文缺项）：Case 工作区可读，
  但分析入口标为不可用并逐项列出缺什么
- Agent 不可用：主对话与待办里的提议不可用；其余全部可用
- 待办项很多：按影响面排序（先说会影响多少 Case 产物），
  并给出排序理由；排序必须确定可复现
- 一条提议被驳回：条目保留并可查，标出驳回者与理由
- 一条提议长期未处理：标出「已放置 N 天」，不自动生效也不自动丢弃
- 会话中产生凭据或密钥：界面不显示，写入时即拒绝
- 一个 Case 的经验条数很多：需要检索与按类型筛选，不能只给一个长列表

## 前后端契约

### `WorkspaceService`（作用域：平台，只读聚合）

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Tree` | — | `NavView` | 导航结构：当前项目、六部件状态、Case 列表 |
| `Overview` | — | `ProjectOverview` | 逐部件的规模与就绪情况 |
| `Todo` | — | `TodoView` | 待拍板与待裁决两个列表及其理由 |
| `Glossary` | — | `GlossaryView` | 界面共用的命名：词条显示名、单位名、类型名、分级名、状态名 |
| `AgentStatus` | — | `AgentStatus` | Agent 是否可用及原因 |

`ProjectOverview`：`{ dir, name, path, version, status, statusText, parts: PartStatus[], cases: CaseRef[], warnings: string[] }`

`PartStatus`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `part` | string | 否 | `agent` / `tools` / `documents` / `dict` / `schemas` / `basicdata` |
| `name` | string | 否 | 中文名 |
| `scale` | string | 否 | 规模的人话表述（如「283 份文档」） |
| `status` | string | 否 | `ok` / `empty` / `incomplete` / `failed` |
| `statusText` | string | 否 | |
| `consequence` | string | 否 | **缺它会怎样**，人据此判断能不能用 |

`TodoView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `proposals` | `ProposalView[]` | 否 | 待拍板；结构见 `agent.spec.md` |
| `decisions` | `DecisionView[]` | 否 | 待裁决；结构见 `decision.spec.md` |
| `note` | string | 否 | 为空时的说明，必须包含「只说明没有待你决定的事」 |

`GlossaryView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `terms` | `map[string]Named` | 否 | 词条标识 → 显示名与说明 |
| `units` | `map[string]Named` | 否 | |
| `types` | `map[string]Named` | 否 | |
| `confidences` | `map[string]Named` | 否 | |
| `statuses` | `map[string]Named` | 否 | |
| `actorKinds` | `map[string]Named` | 否 | |
| `revisions` | `map[string]Named` | 否 | |

`Named`：`{ label, note, extra }`
——**`label` 为空串表示没有中文名**；界面此时显示标识符并说明「暂无中文名」，
**不得**由界面自己补一个名字。

约定：

- `Glossary` 的词表**随项目切换而更新**；界面不得缓存跨项目的命名
- **界面与命令行使用同一套命名**：命名规则在服务层实现，
  不在前端各写一份——两处不一致，人就无法对账
- `Todo.note` 在列表为空时**必须非空**：空白与「没有待办」在界面上无法区分
- 所有写操作返回受影响的范围，使界面能提示「有多少 Case 产物将标为依据已变」
- 项目级与 Case 级的归属由服务返回的字段体现，界面不得自行推断

### 页面与服务的对应

本规格定的是**壳**（三层、导航、待办、命名）；每个页面自己的规则在它自己的规格里：

| 页面 | 规格 |
|---|---|
| 项目概览 | 本规格（`WorkspaceService.Overview`） |
| 主对话 / 待拍板 | `agent.spec.md` |
| 工具 | `tools.spec.md` |
| 文档 | `document.spec.md` |
| 词表 / 待裁决（指代） | `dict.spec.md` |
| 数据定义 / 待裁决（抽取） | `dataschema.spec.md` |
| 基础数据 / 公式 | `basicdata.spec.md` |
| Case 上下文 / 分析 | `case.spec.md` |
| 经验 | `experience.spec.md` |
| 数据表 | `casedata.spec.md` |
| 歧义裁决机制 | `decision.spec.md` |
