# 内核：断言模型与数据校验

## 目的

定义整个系统最基础的数据单元与校验规则。

其余三份规格全部建立在「断言」之上——`verification.spec.md` 定义它的核验状态，
`alternatives.spec.md` 由它生成备选方案，`player-profile.spec.md` 用同一结构表达个人状态。
本规格定义**断言本身的结构**。

解决的问题：同一份游戏事实会有多个来源、多个版本、多种表述，且持续被补丁修改。
若把它当成「某实体的某个字段值」，会立刻丢失来源、时效与成立条件，
于是无法判断可信度、无法呈现冲突、无法追踪过期——而这三件事恰恰是「不能错」的全部内容。

## 术语

- **断言（Assertion）**：系统的最小事实或建议单位。
  它不是「实体的属性」，而是**一句话**：某个主体、在特定条件下、由某个来源、在某个时间点、以某个可信度成立。
- **主体（subject）**：断言谈论的对象，用**稳定标识**而非名称指代。
- **谓词（predicate）**：属性名或关系名。
- **限定条件（qualifiers）**：使该断言成立的条件——适用版本或时间区间、场景、触发条件。
- **来源（source）**：谁说的。
- **依据（evidence）**：凭什么这么说。**与来源不是一回事**（见 `verification.spec.md`）。
- **溯源（provenance）**：原文锚点 + 源内容的修订标识 + 采集时间。
- **断言分级**：L1 直引 / L2 结构化 / L3 推导 / L4 推断。
- **量纲**：同一事实在不同来源中的表示单位（百分数 vs 小数）。
- **穷尽性**：可枚举集合的完整性。

## 领域规则（Given-When-Then）

### 断言的基本结构

- Given 任何内容进入系统 When 存储 Then 必须以断言形式存储，携带主体、谓词、值、限定条件、来源、溯源与分级
- Given 一条断言缺少来源或溯源 When 存储 Then **拒绝**
- Given 两条断言主体与谓词相同但**限定条件不同** When 存储 Then **并存**，互不覆盖
- Given 两条断言主体、谓词与限定条件完全相同但值不同 When 存储 Then 并存并**标记冲突**，不得择一

> 这条是本规格的核心。它直接回答「同一个指代在不同条件下有不同效果」——
> 那**不是指代问题**，是效果被错建模成了实体的属性。

### 主体标识

- Given 一个主体 When 被引用 Then 必须使用稳定标识，**不得使用名称**
- Given 同一主体存在多个名称 When 记录 Then 名称作为**别名数据**单独登记，并带来源与适用范围
- Given 一个名称指向多个主体 When 被引用 Then **报歧义**，不得猜测
- Given 别名表新增映射 When 记录 Then 必须记录其来源

### 断言分级

- Given 原文照抄的内容 When 记录 Then 分级为 L1，且必须能通过与原文比对**自动验证**
- Given 从文本解析成字段的内容 When 记录 Then 分级为 L2，核验前不得作为权威
- Given 由其他断言计算得出的内容 When 记录 Then 分级为 L3，且必须记录**推导链**；
  **仅在上下文中立时固化为断言**，否则只作为场景中间结果（见 `derivation.spec.md`）
- Given 凭理解补全的假设 When 记录 Then 必须分级为 L4，且**不得与 L1 混同展示**
- Given 一条 L4 断言 When 被方案引用 Then 方案输出必须标注其中存在推断成分

> 分级的意义：**隐式信息与直引事实必须可分辨**。没有分级，猜测会与事实混在一起，无从追溯。

### 溯源

- Given 一条断言 When 记录 Then 必须携带源内容标识、原文锚点与采集时间
- Given 源内容的修订标识发生变化 When 系统检测到 Then 由该源产出的断言转为**待重核验**
- Given 原文被删除或不可达 When 查询溯源 Then 标注依据不可达，**不得静默丢弃锚点**

### schema 与漂移

- Given 元模型不认识的关键字或类型 When 加载 schema Then **失败并指出位置**（严格模式）
- Given 数据中出现的字段未被 schema 声明 When 检测 Then 报告漂移（**数据 → schema** 方向）
- Given schema 声明的字段在数据中从未出现 When 检测 Then 报告漂移（**schema → 数据** 方向）
- Given 字段存在但内容为空 When 统计覆盖率 Then **不计为已填充**
- Given schema 本身发生变更 When 记录 Then 必须记录版本与生效时间

> 实测依据：某 wiki 的 schema 声明 13 个字段而数据中实际出现 15 个（双向漂移同时存在）；
> 281 条记录里 276 条的 `stats` 是空对象——**「字段存在」不等于「已被使用」，更不等于「已被核验」**。

### 校验

- Given 一条记录 When 校验 Then 必填、类型、范围、枚举、唯一、引用完整性六类**各自独立判定**
- Given 任一校验失败 When 写入 Then 持久化层**零变更**
- Given 一批记录部分失败 When 写入 Then 处理方式（整批回滚 / 逐条报告）由**调用方选择**
- Given 引用目标不存在 When 校验 Then 失败并指出引用目标
- Given 校验所依赖的 schema 尚未加载 When 校验 Then **失败并要求补齐**，不得放行

### 量纲归一

- Given 同一事实来自两个来源且量纲不同 When 比对 Then **必须先归一**
- Given 两个来源归一后仍不一致 When 检测 Then 标记冲突，不得择一
- Given 一条断言未声明量纲 When 与其他断言比对 Then **拒绝比对**并指出缺失的声明

> 实测依据：同一式神的暴击在来源 A 记为 `50`、来源 B 记为 `0.5`；
> 若不归一，会把**一致**误判为**冲突**。

### 穷尽性与归因

- Given 可枚举集合存在多个来源（索引 / 属性表 / 明细文件） When 校验 Then 逐一对齐并报告差异
- Given 出现仅存在于一侧的条目 When 报告 Then 必须**逐一归因**，判定是缺失还是合法类别差异
- Given 归因结论为合法类别差异 When 记录 Then 记录该类别，后续同类不再报警

> 实测依据：索引声明 275 个角色而明细文件有 281 个，多出的 6 个是**阴阳师主角而非式神**。
> **报警 ≠ 判错，必须能归因**；否则真实问题会被误报淹没。

### 原子性与并发

- Given 并发写入同一唯一约束 When 提交 Then 只有一个成功，另一个得到冲突错误而非静默覆盖
- Given 事务回滚 When 查询 Then 无任何残留

## 验收标准

- [ ] 断言必须携带主体、谓词、值、限定条件、来源、溯源、分级，缺任一项即拒绝
- [ ] 限定条件不同的两条断言并存，互不覆盖
- [ ] 主体、谓词、限定条件全同而值不同的两条断言并存且被标记冲突
- [ ] 一个名称指向多个主体时报歧义，不猜测
- [ ] 别名映射带来源
- [ ] L1 可与原文自动比对验证
- [ ] L4 断言在输出中与 L1 可区分
- [ ] 源内容修订标识变化后，相关断言转为待重核验
- [ ] 原文不可达时锚点保留并标注
- [ ] schema 加载遇未知关键字失败并指出位置
- [ ] 双向漂移均可检出
- [ ] 空字段不计入已填充
- [ ] 六类校验各有正反用例
- [ ] 校验失败时持久化层零变更
- [ ] 依赖缺失时校验失败而非放行
- [ ] 量纲不同的两源比对前先归一
- [ ] 未声明量纲的断言拒绝参与比对
- [ ] 穷尽性差异逐一归因；记为合法类别差异后不再重复报警
- [ ] 并发写同一唯一约束只有一个成功
- [ ] 回滚后无残留

## 边界与异常

- 空 schema 文件、语法错误、非 UTF-8：加载失败并报出位置
- 主体标识重复但指向不同实体：拒绝并报冲突
- 别名自指或循环：拒绝
- 断言值超长、数值溢出：拒绝，**不得截断或回绕**
- 溯源锚点在原文变更后越界：标记锚点失效，**保留断言本身**
- 同一断言被两个来源在同一时刻以不同值给出：并存并标记冲突
- 批量为空：合法，但不产生任何变更
- 校验所依赖的 schema 尚未加载：失败，不前移
- schema 之间的循环引用：**待定**
- 断言的限定条件互相排斥（不可能同时成立）：允许存入，但引用它的方案必须报出冲突约束

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 断言的分级、来源、溯源与核验状态必须可被**外部读取**，而不只显示在界面上
- 校验结果必须**逐条可定位**：哪一条、哪个字段、哪一类约束
- 冲突必须成对暴露（双方的值与来源），不得只给一个「冲突」标记

## 与其他规格的关系

| 规格 | 定义 |
|---|---|
| **本规格** | 断言的**结构**与校验规则 |
| `project.spec.md` | **项目**：一个领域的封装单位（隔离边界；定义与实例的分界） |
| `scenario.spec.md` | **场景**：项目内的一个用途（用途边界；`requires` 的载体） |
| `metamodel.spec.md` | 断言可用的**类型与约束原语**（通用引擎的封闭集合） |
| `computation.spec.md` | **表达式、量纲与时间**——场景声明领域规则的唯一途径 |
| `derivation.spec.md` | **派生与缓存**——断言与方案之间的中间产物层次 |
| `experience.spec.md` | **经验**——人机协作产出的可复用判断与责任归属 |
| `ingestion.spec.md` | **接入层**：取回、存档、解析 → 候选 |
| `admission.spec.md` | **准入层**：候选 → 断言的守门人，产出变更集 |
| `migration.spec.md` | schema 变更时**既有数据怎么办** |
| `verification.spec.md` | 断言的**核验状态与可信度** |
| `player-profile.spec.md` | **个人状态与偏好**断言（同结构，不同信任域） |
| `alternatives.spec.md` | 由断言生成的**备选方案** |
