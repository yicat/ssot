# 核心：元模型与数据校验

## 目的

为「用声明式 schema 管理一类结构化数据」提供内核。元模型（可用字段类型、约束种类、状态机节点类型）在代码中固化；具体 schema 由项目以声明式文件提供并在运行时加载；**任何写入的数据必须先通过其 schema 的校验才能持久化**。

解决的问题：同一份数据被多个脚本 / 服务 / agent 各写各的，字段含义、必填性、取值范围在不同地方不一致，错误要等到下游消费时才暴露。

使用方：外部程序、批处理脚本、agent，以及本工具自身的运维界面。

## 术语

- **元模型**：本工具允许出现的字段类型、约束种类、状态机节点类型的全集。由实现者维护，项目不修改。
- **schema**：某个数据类型的声明，包含字段、约束、状态机。由项目以声明式文件提供。
- **记录**：一条符合某 schema 的数据。
- **校验**：判定一条记录是否满足其 schema 的全部约束。
- **迁移**：schema 本身发生变更时，把既有数据带到新 schema 的过程。

## 领域规则（Given-When-Then）

### schema 加载

- Given 一份声明式 schema When 加载它 Then 其中每个字段都映射到元模型已定义的类型与约束，并可被完整列出
- Given schema 使用了元模型不认识的关键字或类型 When 加载 Then 失败，报错指出所在位置
- Given 两个 schema 声明了相同名称 When 加载 Then 失败
- Given 同一个字段在同一 schema 中被声明两次 When 加载 Then 失败
- Given 一份已验证过的 schema When 重复加载 Then 结果与首次一致（幂等）

### 数据校验

- Given 字段声明为必填 When 记录缺失该字段 Then 校验失败并指出该字段
- Given 字段声明了类型 When 记录的值类型不符 Then 校验失败并指出该字段
- Given 字段声明了取值范围或枚举 When 记录的值越界 Then 校验失败并指出字段与命中的约束
- Given 字段声明为引用另一 schema 的记录 When 目标记录不存在 Then 校验失败并指出引用目标
- Given schema 声明了唯一约束 When 写入的记录在唯一字段上与既有记录重合 Then 拒绝写入并指出冲突
- Given 一条记录通过了全部校验 When 持久化 Then 之后读回的字段值与写入一致

### 原子性

- Given 一条记录存在任一校验失败 When 尝试写入 Then 持久化层不产生任何变更
- Given 一批记录其中部分校验失败 When 批量写入 Then 已成功部分与失败部分的处理方式由调用方选择：整批回滚，或跳过失败项并返回逐条结果

### 状态机

- Given schema 为某字段声明了状态机 When 记录尝试从未声明允许的状态转换 Then 拒绝并指出当前状态与目标状态
- Given 转换被声明允许 When 执行转换 Then 记录状态变更且该次变更可被追溯

### schema 演进

- Given schema 新增了必填字段 When 既有数据不满足该字段 Then 不自动删除或篡改既有数据，而是报出违规记录清单
- Given schema 变更导致既有数据不再满足新约束 When 请求演进 Then 先给出影响清单，得到确认后才执行

## 验收标准

- [ ] 加载合法 schema 成功，且能列出其字段、约束与状态机
- [ ] 加载非法 schema 失败，报错包含出错位置（文件与行）
- [ ] 必填、类型、范围、枚举、唯一、引用完整性六类约束各有正反用例
- [ ] 非法状态迁移被拒绝，合法迁移被接受且留下可追溯记录
- [ ] 校验失败的写入不产生任何持久化变更
- [ ] 批量写入的部分失败行为符合调用方选择（整批回滚 / 逐条结果）
- [ ] 同一 schema 重复加载结果幂等

## 边界与异常

- schema 文件为空、语法错误、或编码非 UTF-8：加载失败，报错含文件与行号
- 字段名非法（空、含保留字符）：加载失败
- schema 之间的自引用与循环引用：**待定**——需明确允许还是拒绝
- 记录值超长、数值溢出：校验失败，**不得静默截断或回绕**
- 并发写入同一唯一字段：只有一个成功，另一个得到冲突错误，不得静默覆盖
- 校验规则本身无法判定（如引用的目标 schema 尚未加载）：失败并请求补齐，不得放行
- 空记录（所有字段均缺省）：按必填约束判定，无必填字段时视为合法

## 前后端契约

**待定**，取决于对外接口形态。当前已确认的约束：

- 主要调用方是程序与 agent，因此接口必须能在进程外调用；仅生成给内置前端用的绑定不满足要求
- 本工具的运维界面与外部调用方必须看到**同一份**校验结果，不得各自实现一套校验

## 待确认

1. 对外接口形态：HTTP（服务模式）／CLI／MCP／兼有？
2. 运维界面的职责边界：查看、审核、还是也允许修改数据？
3. 持久化选型与其约束（嵌入式单文件 vs 可并发多进程）
4. 引用完整性是强约束（写入时强制）还是最终一致（允许悬空引用 + 后续校验报告）
5. 校验失败的返回形态：首个错误即返回（fail-fast）还是收集全部错误（全量报告）
6. 循环引用是否允许
