# 工具：Agent 的手脚

## 目的

Agent 要「获取数据」就必须能对外做事：抓网页、调接口、读文件、跑分析查询。
这些动作不能写死在程序里——每个项目要取的东西都不一样，而且取数方式会变。

因此它们是**项目级的声明式工具**：一组脚本，各自声明自己吃什么、吐什么，
可以自由组合成流水线。Agent 负责选用与编排，人负责写与维护。

三个必须守住的边界：

1. **执行结果不是事实源。** 工具只是把手伸出去，取回来的东西要经过准入才能成为项目级数据。
2. **工具有副作用，因此必须声明。** 会不会联网、会不会写盘、用不用凭据，都要写在声明里。
3. **Case 能跑不能改。** Case 的 Agent 可以用工具取数，但不得增删改工具。

## 术语

- **工具（tool）**：一段带声明、可独立执行的脚本。运行环境为 Deno——
  这是对外约定而非内部实现细节，因为**用户要自己写这些脚本**。
- **声明（manifest）**：工具的名字、用途、输入、输出与副作用。没有声明的工具不可用。
- **执行（run）**：一次工具调用，带具体参数，产生一份执行记录与一份产出。
- **组合（pipeline）**：把若干工具按顺序串起来，前一个的输出绑定为后一个的输入。
- **产出（output）**：工具执行的结果。产出是**中间物**，不是项目级数据。
- **凭据（credential）**：访问外部所需的口令或令牌。凭据**不属于项目内容**。

## 领域规则（Given-When-Then）

### 声明

- Given 一个工具 When 登记 Then 必须声明五件事：名字、用途（一句话说清它取什么）、
  输入（名字、类型、是否必填、单位）、输出（名字、类型）、**副作用**
- Given 一个工具的副作用 When 声明 Then 必须逐项说明：是否访问网络、
  是否读写本地文件、是否需要凭据、是否耗时较长
- Given 一个工具 When 缺少声明 Then **不可用**：不能被 Agent 选用，也不能被执行
- Given 一个工具的输出 When 声明 Then 必须给出类型，使组合时能判断能不能接上
- Given 一个工具 When 声明需要凭据 Then 只声明**凭据名**，不得在工具内容里出现凭据本身

### 执行

- Given 一次工具执行 When 完成 Then 记录：谁发起的、何时、用了哪些参数、
  结果成功还是失败、产出的摘要与位置
- Given 一次工具执行 When 结果 Then 产出是**中间物**：
  它不出现在项目基础数据里，也不能被当作依据引用
- Given 工具产出 When 要成为项目级数据 Then 必须走准入流程（见 `admission.spec.md`），
  **工具本身不得直接写入项目级**
- Given 工具访问网络取回内容 When 执行 Then 必须记录取回的**来源标识与时间**，
  使取回的内容可被重新验证
- Given 一次执行失败 When 报告 Then 说明失败原因与已完成到哪一步，
  不得只给一个「失败」
- Given 一次执行超时 When 处理 Then 报告超时并列出已完成的部分，不假装成功
- Given 执行产生部分结果 When 失败 Then 部分结果必须显式标出为不完整，
  不得让它看起来像一份完整的产出

### 组合

- Given 多个工具 When 组合 Then 前一个的输出可以绑定为后一个的输入；
  **绑定必须显式声明**，不得靠名字猜
- Given 两个工具 When 组合 Then 输出类型与输入类型对不上时**拒绝**组合，并指出是哪一对
- Given 一条组合里的某一步失败 When 处理 Then 后续步骤**不执行**；
  已产生的中间产物保留并标出
- Given 一条组合 When 执行 Then 记录整条链路的每一步，而不仅记录最终产出——
  否则出了问题无从定位
- Given 一条常用组合 When 复用 Then 可以登记为**具名组合**，供 Agent 与人反复使用
- Given 一条组合 When 登记 Then 它同样要声明输入、输出与副作用（副作用是各步的并集）

### 分析查询

- Given 需要分析数据 When 使用分析型查询 Then 可以查询项目内的**数据与文档**（含跨表聚合）
- Given 分析型查询 When 执行 Then **只读**：不得通过它修改任何项目级内容
- Given 分析型查询的结果 When 呈现 Then 它同样是产出，不是事实源；
  结论要留下来必须落成文档、定义或 Case 的 experience

### 权限与安全

- Given 一个工具 When 执行 Then 只能使用它**声明过的能力**；
  未声明网络访问的工具不得联网
- Given 工具试图读写声明之外的位置 When 执行 Then **拒绝**并记录
- Given 工具需要凭据 When 执行 Then 凭据由平台注入，工具自身不持有
- Given 凭据 When 导出项目 Then **不得包含**
- Given 工具内容中检测到疑似凭据 When 登记 Then 拒绝登记并指出位置
- Given Case 子 Agent When 使用工具 Then **可以执行**；
  新增、修改、删除工具一律拒绝，并提示走 experience 上报
- Given 一个工具被删除 When 有组合仍引用它 Then 引用处标为失效，
  组合不可执行并指出缺哪个工具

### 演进

- Given 一个工具的输入或输出声明变更 When 应用 Then 引用了它的组合被标为「需复核」，
  不得静默沿用
- Given 工具变更 When 完成 Then 报告影响面：有多少组合与多少历史执行用了旧版本
- Given 已执行过的历史记录 When 工具后来变了 Then 历史记录仍指向**当时那一版**，
  不得改写成新版本

## 验收标准

- [ ] 未声明的工具不可选用、不可执行
- [ ] 工具的声明包含输入、输出与副作用四类信息
- [ ] 需要凭据的工具只声明凭据名，工具内容中不含凭据
- [ ] 每次执行都有记录，可回答「谁、何时、什么参数、结果如何」
- [ ] 执行产出不出现在项目基础数据中，也不能被引用为依据
- [ ] 工具产出成为项目级数据必须经过准入
- [ ] 联网取回的内容带有来源标识与时间
- [ ] 执行失败时说明原因与完成到哪一步
- [ ] 组合的输入输出类型不匹配时被拒绝，并指出是哪一对
- [ ] 组合中某步失败后续步骤不执行，中间产物标出
- [ ] 组合执行记录包含每一步，不只最终产出
- [ ] 分析型查询可跨表聚合，且无法修改任何项目级内容
- [ ] 工具只能使用声明过的能力，越权被拒绝并记录
- [ ] Case 可以执行工具，但无法新增、修改或删除工具
- [ ] 工具被删除后引用它的组合标为失效并指出缺件
- [ ] 工具声明变更后，引用它的组合被标为需复核
- [ ] 历史执行记录指向当时的工具版本

## 边界与异常

- 工具内容为空或语法错误：拒绝登记，指出位置
- 工具名重复：拒绝
- 工具执行环境缺少依赖：报告缺什么，不静默跳过
- 工具输出为空：允许，但执行记录中标为「空产出」——
  「没取到」与「取到空」是两件事
- 工具输出超大：允许，但必须说明截断策略，不得悄悄截断
- 组合为空（一个工具都没绑定）：拒绝
- 组合形成环：拒绝加载并指出环上的工具
- 组合过深导致难以理解：给出提示（阈值见「待确认」），不阻止
- 同一工具被并发执行多次：允许，但执行记录必须可区分
- 工具产出与项目基础数据矛盾：以**提议**形式摆出差异，见 `agent.spec.md`，
  不直接覆盖
- 外部站点不可达或需要登录：报告为「不可用」而不是「缺失」——
  前者是环境问题，后者是数据问题，处置完全不同
- 项目没有任何工具：允许；依赖取数的动作标注为不可用并说明原因

## 前后端契约

`ToolService`（作用域：项目；执行在 Case 作用域内也允许）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | — | `ToolView[]` | 全部工具及其声明与就绪状态 |
| `Get` | `name` | `ToolView` | 含完整声明 |
| `Put` | `ToolInput` | `ToolView` | 登记或更新；需人拍板（见 `agent.spec.md`） |
| `Remove` | `name` | — | 删除；引用它的组合标为失效 |
| `Pipelines` | — | `PipelineView[]` | 具名组合 |
| `PutPipeline` | `PipelineInput` | `PipelineView` | 登记组合；类型不匹配即拒绝 |
| `Run` | `name, args` | `RunResult` | 执行单个工具 |
| `RunPipeline` | `name, args` | `RunResult` | 执行组合 |
| `Runs` | `name, limit` | `RunView[]` | 历史执行记录，指向当时的工具版本 |

`ToolView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `name` | string | 否 | |
| `title` | string | 否 | 中文名；定义里没有时为空串，界面退回显示名字 |
| `purpose` | string | 否 | 一句话说清取什么 |
| `inputs` | `PortView[]` | 否 | 每项含名字、类型、是否必填、单位 |
| `outputs` | `PortView[]` | 否 | 每项含名字、类型 |
| `effects` | string[] | 否 | `network` / `fs-read` / `fs-write` / `credential` / `slow` |
| `credential` | string | 否 | 凭据**名**；空串表示不需要 |
| `status` | string | 否 | `ok` / `missing-deps` / `invalid` |
| `statusText` | string | 否 | 中文说明，含缺什么 |
| `revision` | string | 否 | 工具版本标识 |

`RunResult`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `ok` | bool | 否 | |
| `message` | string | 否 | 成功说明或失败原因 |
| `steps` | `StepView[]` | 否 | 组合时每一步的结果；单工具时一项 |
| `outputs` | `PortValue[]` | 否 | 产出；**中间物，不是事实源** |
| `artifact` | string | 否 | 产出的存档标识，空串表示未存档 |
| `at` | string | 否 | RFC3339 |

约定：

- `Run` / `RunPipeline` 在服务层校验副作用声明；未声明联网的工具联网一律拒绝
- 产出**没有**「写入项目基础数据」的接口——要落项目级必须另走准入流程，
  这是刻意的：不给工具留一条绕过准入的近路
- `List` 必须一并返回就绪状态，使界面能显示「哪些工具现在用不了、为什么」
- 执行结果必须带 `artifact`，使取回的内容可被重新验证

## 待确认

1. 组合深度的提示阈值
2. 工具是否需要版本化的输入输出兼容性声明（当前只做类型匹配）
3. 分析型查询是否需要独立的工具类型（区别于普通脚本），以便限制其能力
4. 一个工具的输出能否直接作为另一个项目的内容来源（当前：不能，项目间只允许复制）
