# 经验：Case 里长出来的判断

## 目的

Case 的价值不在它算了一次，而在它**记住了怎么算、以及为什么这么算**。
这些判断就是经验。

上一版要求经验**只追加、不可改、不可删**，理由是可追溯。那个理由在项目级是对的
（依据被改过就不可信了），但在 Case 里是错的：**把草稿和结论混在一起，
人就不敢往里写东西了**——而 Case 里最该发生的恰恰是不断写、不断改。

所以这一版的可变性是：

| 操作 | 界面上 | 底层 |
|---|---|---|
| 新增 | 新增 | 新条目 |
| 修改 | 改 | **追加新修订**，旧修订保留 |
| 删除 | 删 | **标记作废**，不物理删除 |

人看到的就是「改」和「删」，不需要理解版本概念；但**底层不丢东西**：
任何一个结论当时凭什么、改之前是什么，事后都还查得到。

经验**不改变项目级**。Case 发现项目级有问题时，写一条**上报**经验，
由主对话汇总后统一改——这是 Case 唯一能表达「这里该改」的方式。

## 术语

- **经验条目（entry）**：一条判断。有稳定标识，跨修订不变。
- **修订（revision）**：条目的一次改动。**改 = 追加新修订**，旧修订保留。
- **作废（void）**：删除的结果。条目不再出现在默认列表与依据里，但仍可查。
- **依据（basis）**：这条判断凭什么。可以是数据、文档、词条、某次工具执行、
  某个会话位置、某张 CaseData 表。
- **适用条件（applies）**：这条判断在什么条件下成立。超出条件时标为不适用。
- **提出者 / 修改者**：谁提出的、谁改的。**二者都记**，因为改的人可能不同意原判断。
- **上报（report）**：一种特殊经验——「项目级这里有问题，建议这么改」。

## 领域规则（Given-When-Then）

### 归属与身份

- Given 一条经验 When 记录 Then 必须归属到**具体 Case**；无归属即拒绝
- Given 一条经验 When 记录 Then 必须有：稳定标识、标题、内容、**类型**、依据、提出者、时间
- Given 一条经验 When 记录 Then 可以声明**适用条件**；
  不声明表示在该 Case 内普遍适用
- Given 一条经验 When 记录 Then 必须能给出**依据**——
  说不出凭什么的经验不是经验，是印象
- Given 一条经验 WHEN 引用其他东西 Then 引用必须是可跳转的标识：
  数据、文档（含段落）、词条、数据定义、某次工具执行、某个会话位置、某张 CaseData 表

### 增删改查

- Given 新增一条经验 When 提交 Then 只要求归属、内容、类型、依据、提出者
- Given 修改一条经验 When 提交 Then **追加新修订**，
  记录修改者与**修改理由**；旧修订保留可查
- Given 删除一条经验 When 提交 Then 标为**作废**，
  记录删除者与理由；条目**保留**
- Given 一条作废的经验 When 查询 Then 默认列表看不到它，
  但可以显式筛出来；它**不再**作为任何答案的依据
- Given 一条经验 When 查看 Then 默认显示当前修订；
  可展开看到全部修订及每次改动的人与理由
- Given 一条作废的经验 When 恢复 Then 允许，作为一次新修订记录——
  作废与恢复都留在历史里

### 类型与各自的要求

- Given 一条**推导型**经验 When 记录 Then 必须带推导链：
  用了哪些数据、哪个公式的哪一版；并且**可重放**
- Given 一条推导型经验 When 无法重放（缺输入、公式已删、数据已变） Then
  **降级**并标注为不可重放，**不删除**
- Given 一条**判定型**经验 When 记录 Then 必须带依据与判定者；
  它是人的裁定，因此**可以被另一个人推翻**，推翻记录保留
- Given 一条**总结型**经验 When 记录 Then 必须带**样本量**
  （从多少次实践归纳而来）与适用条件
- Given 一条总结型经验 When 缺样本量 Then **拒绝记录**——
  没有样本量的「经验」只是意见，而意见与经验的差别恰恰在这里
- Given 一条**上报**经验 When 记录 Then 必须带：目标部件、问题描述、依据、建议；
  `目标部件`取自六部件之一
- Given 一条上报经验 When 记录 Then 它**不是**项目级的改动，
  只是给主对话的一条输入（汇总规则见 `agent.spec.md`）

### 冲突与裁决

- Given 一条新经验 When 与既有经验冲突（同一话题、不同结论） Then
  **并存并标记**，不覆盖、不自动择一
- Given 冲突的经验 When 展示 Then 两条都要给出各自的依据与提出者——
  让人看到分歧在哪，而不是看到一个被抹平后的结论
- Given 一次裁决 When 记录 Then 含依据、裁决者、时间；
  被否的那条**保留**并标为「已否决但保留」
- Given 经验与**事实**冲突 When 遇到 Then 按经验处理（并存并标记），
  但必须提请人注意：这说明数据可能有问题，值得走一次上报

### 失效与依赖

- Given 一条经验所依赖的项目级内容被否决或删除 When 检测到 Then
  标为**失效**并指出失效依据
- Given 一条经验依赖的计算方式（公式）变更 When 检测到 Then 标为**待重算**
- Given 一条经验被引用 When 超出它的适用条件 Then 标为**不适用**，
  并说明条件边界
- Given 一条经验引用的 CaseData 表被删除 When 检测到 Then
  标为**依据不可达**，不删除经验
- Given 一条经验引用的会话位置 When 会话被裁剪 Then
  标为**依据不可达**；这正是「会话裁剪不得裁掉结论与改动」的原因

### 与项目级的边界

- Given 一条经验 When 记录 Then 它**不改变**项目级六部件中的任何一处
- Given 一条经验被两个以上 Case 需要 When 检测到 Then
  提示「该提升为项目级」，并给出提升路径（数据定义 / 文档 / 词条）
- Given 一个 Case When 尝试复用另一个 Case 的经验 Then **拒绝**；
  并提示两条出路：写进自己的经验，或上报建议提升为项目级
- Given 一条经验 When 被答案引用 Then 答案标注：这条经验的类型、
  依据强度、以及它是否已失效或不适用

### 与会话的关系

- Given 一条经验 When 记录 Then 可以引用**会话的具体位置**（哪次对话的哪一句），
  使判断能回溯到当时的上下文
- Given 会话记录 When 记录 Then **只追加**，不可改写（改写对话等于伪造工作记录）
- 两者的可变性不同，因此不能合并成一种东西：
  **会话是过程，经验是结论**。过程不可改，结论可以改——改了留痕

## 验收标准

- [ ] 经验必须归属到具体 Case，无归属被拒绝
- [ ] 经验必须有类型、依据与提出者
- [ ] 说不出依据的经验被拒绝记录
- [ ] 修改经验时追加新修订并记录修改者与理由，旧修订保留
- [ ] 删除经验时标记作废并记录删除者与理由，条目保留
- [ ] 作废的经验不出现在默认列表，也不作为答案的依据
- [ ] 作废的经验可被筛出、可恢复，且恢复记录在历史里
- [ ] 推导型经验带推导链且可重放
- [ ] 无法重放的推导型经验被降级标注而非删除
- [ ] 判定型经验带依据与判定者，且可被推翻，推翻记录保留
- [ ] 总结型经验带样本量与适用条件
- [ ] 缺样本量的总结型经验被拒绝
- [ ] 上报经验带目标部件、问题、依据与建议
- [ ] 冲突经验并存并标记，不自动择一
- [ ] 冲突经验的依据与提出者都可见
- [ ] 裁决记录含依据、裁决者与时间，被否条目保留
- [ ] 依赖的项目级内容被否决时经验标为失效并指出失效依据
- [ ] 依赖的公式变更时经验标为待重算
- [ ] 超出适用条件时经验标为不适用并说明边界
- [ ] 引用的 CaseData 表被删除时经验标为依据不可达且不被删除
- [ ] 引用的会话位置被裁剪时经验标为依据不可达
- [ ] 经验不改变项目级六部件的任何一处
- [ ] 被多个 Case 需要时提示提升为项目级
- [ ] 跨 Case 复用经验被拒绝并给出两条出路
- [ ] 答案引用经验时标注类型、依据强度与失效状态
- [ ] 经验可回溯到会话的具体位置
- [ ] 会话只追加，不可改写

## 边界与异常

- 内容为空或纯占位：拒绝
- 标题重复：允许（不同 Case 里的经验本来就可能同名），但在同一 Case 内提示
- 类型缺失：拒绝；类型不得由系统猜
- 推导链引用不存在的断言或公式：拒绝记录并指出
- 推导链成环：拒绝
- 适用条件引用不存在的 Case 或数据定义：拒绝并指出位置
- 同一秒内对同一条经验多次修改：按修订顺序排列，不合并
- 修改把依据全部删掉：拒绝（经验必须有依据）
- 作废后又被答案引用（历史答案）：允许，但历史答案需标注「所依据的经验已作废」
- 一条经验同时被两个 Case 引用（历史遗留）：保留并在界面上标出角色问题，
  不自动删除
- 一条上报经验的目标部件已被删除：标为「目标不存在」，保留记录
- 经验为空（Case 里一条都没有）：允许；界面说明「还没有经验」并给出新增入口，
  不显示成错误
- 提出者是 agent：允许，但界面上**明确标出**是 agent 提的

## 前后端契约

`ExperienceService`（作用域：Case）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | `kind, includeVoid, q` | `ExperienceView[]` | 默认不含作废 |
| `Get` | `id` | `ExperienceView` | 当前修订 |
| `Create` | `ExperienceInput, by` | `ExperienceView` | `by` 是提出者，可以是 agent |
| `Revise` | `id, ExperienceInput, by, reason` | `ExperienceView` | 追加新修订 |
| `Void` | `id, by, reason` | `ExperienceView` | 标记作废 |
| `Restore` | `id, by, reason` | `ExperienceView` | 恢复，记为新修订 |
| `History` | `id` | `ExperienceView[]` | 全部修订与每次的人与理由 |
| `Conflicts` | — | `ConflictView[]` | 同话题不同结论 |
| `Stale` | — | `StaleView[]` | 失效 / 待重算 / 不适用 / 依据不可达 |
| `Decide` | `id, choose, by, reason` | `ExperienceView` | 裁决冲突；被否条目保留 |
| `Reports` | — | `ReportView[]` | 上报汇总（主对话与界面用） |
| `Usage` | `id` | `UsageView[]` | 哪些答案引用过它 |

`ExperienceView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 跨修订稳定 |
| `revision` | string | 否 | 本修订标识 |
| `case` | string | 否 | 归属 Case |
| `title` | string | 否 | |
| `body` | string | 否 | 判断内容 |
| `kind` | string | 否 | `derived` / `judgment` / `summary` / `report` |
| `kindText` | string | 否 | |
| `basis` | `Basis[]` | 否 | **不可为空** |
| `applies` | string[] | 否 | 适用条件 |
| `samples` | int | 否 | 样本量；总结型必填，其他为 0 |
| `chain` | `ChainView[]` | 否 | 推导链；推导型必填 |
| `replayable` | bool | 否 | 推导型是否可重放 |
| `report` | `ReportView \| null` | 是 | 上报型必填 |
| `proposedBy` | `ActorView` | 否 | 提出者，可以是 agent |
| `revisedBy` | `ActorView \| null` | 是 | 最后修改者 |
| `reviseReason` | string | 否 | |
| `status` | string | 否 | `effective` / `void` / `failed` / `stale` / `recompute` / `inapplicable` / `unreachable` |
| `statusText` | string | 否 | |
| `conflictsWith` | `string[]` | 否 | 冲突条目 |
| `decidedBy` | `ActorView \| null` | 是 | 裁决者 |
| `createdAt` / `updatedAt` | string | 否 | RFC3339 |

`ChainView`：`{ kind, ref, label, revision }`
——`kind` 为 `assert` / `formula` / `doc` / `tool-run` / `table`。

`ReportView`：`{ part, subject, problem, suggestion }`
——`part` 为 `tools` / `documents` / `dict` / `schemas` / `basicdata` / `case`。

约定：

- `Revise` 与 `Void` **都要求理由**：改动别人的判断必须留下为什么
- `Create` 与 `Revise` 都要求 `basis` 非空；服务层校验，不靠界面
- `List` 默认排除作废条目，但 `includeVoid` 必须可用——
  「删掉了还能查」是这套设计的承诺，接口上不能只给一半
- `Reports` 是给主对话汇总用的：**同一条问题会被多个 Case 各报一次**，
  汇总时合并但**保留全部来源**（两个 Case 都遇到过，这本身是信息）
- `Usage` 返回引用过该经验的答案记录；经验作废后，这些引用仍需可查

## 待确认

1. 经验是否需要跨 Case 的只读浏览入口（当前：主对话可读，其他 Case 不可）
2. 「已否决但保留」是否需要独立状态，还是并入 `failed`
3. 上报经验汇总后的去向如何回填（主对话改完后，是否回头更新那条上报的状态）
4. 经验是否需要标签/分类体系，便于在条数变多后检索
5. 修订的保留策略（是否需要压缩极久远的中间修订）
