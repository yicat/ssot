# 经验：人机协作产出的可复用判断

## 目的

定义工具里**最有价值的一层**：从事实推导或归纳出来的、可复用的判断。

数据是公开的、抄得来的；**经验要踩坑才有**。
wiki 上的数值谁都能查，但"怎么算、怎么配、什么重要"散落在会过期、会互相抄、无法验证的攻略里。

**本项目有 agent 参与**——而 agent 的主要贡献不在搬运数据，而在**生产与维护经验**。
因此本规格的核心不是"怎么存经验"，而是**人机分工与责任归属**。

## 术语

- **经验（experience）**：从事实推导或归纳出的、上下文中立、可复用的判断。
- **参与者（participant）**：人，或 agent。二者都有身份，都可追溯。
- **提出者 / 批准者**：一条经验由谁提出、由谁批准。**两者必须分别记录。**
- **候选经验**：已产出、尚未确认的经验。
- **责任级别**：该经验由谁确认，决定其可信度上限。
- **推导链**：该经验依据了哪些断言、用了哪个公式或哪组推理。

## 一、归属与形态

### 经验挂在场景下，不是项目级

| | 归属 | 例子 |
|---|---|---|
| **派生断言（L3）** | **项目** | 满级面板——关于游戏本身的事实，上下文中立 |
| **经验** | **场景** | 「这个版本斗技的先手速度线是多少」——关于某个用途的判断 |

两者都"由推导或归纳而来"，但性质不同：

| | 派生断言 | 经验 |
|---|---|---|
| 性质 | 事实 | 判断 |
| 上下文中立 | ✅ | ❌ **围绕用途** |
| 验证方式 | 算例可复现 | 依据与样本 |
| 责任 | 无人格 | **有提出者与批准者** |

`derivation.spec.md` 里的「上下文中立」是**派生断言的判据**，不适用于经验。

### 形态：像一个长期会话

经验不是一张静态表，而是**围绕该场景长期累积的记录**：

- **可追加，不可覆盖**——新判断追加，旧判断保留（与"冲突并存"一致）
- **有上下文**——每条经验都嵌在它产生的讨论里：为什么这么判断
- **可回溯**——能回答「这条经验是怎么来的」
- **可被推翻**——新的交互可以否定旧经验，但旧经验不消失

### 会话记录就是依据

场景下同时保存两类东西：

```
scenarios/<name>/experience/
├─ entries/        经验条目（结构化：责任级别、推导链、适用条件）
└─ sessions/       原始会话记录（= 原件，是依据）
```

**这与接入流程完全同构**：

| 接入层 | 经验积累 |
|---|---|
| 原件（wiki 页面） | **会话记录** |
| 解析 | 从会话中提炼 |
| 准入（依据检查 + 人确认） | 同样 |
| 断言 | **经验条目** |
| 溯源锚点（原文位置） | 指向**会话中的具体位置** |

由此得到一个直接收益：**经验的溯源可以精确到「哪次对话的哪一句」**。
这是它能被审查、能被推翻、能传给别人的前提。

## 二、经验的三种类型

| 类型 | 例子 | 怎么得到 | 验证手段 |
|---|---|---|---|
| **推导型** | 满级面板、伤害公式的结果 | 按公式从事实算出 | 算例可复现 |
| **判定型** | 冲突裁决、取舍原则 | 人工裁定 | 依据可查、可推翻 |
| **总结型** | 「超鬼王建议用 X」「当前 T0 是 Y」 | **从多次实践归纳** | **无机械办法，只能看依据与样本** |

第三类最难，也是工具最该解决的：它天然带概率性、带时效、会互相矛盾。
**不得把它当作确定事实处理**（见 `alternatives.spec.md`：冲突并存，不裁决）。

## 三、参与者模型

- 每一个产生或修改经验的动作，**必须标识参与者**（人 / agent / 协作）
- **「无追责的核验等于没有核验」**——这条对 agent 同样成立
- agent 不得作为**批准者**，只能作为提出者与证据提供者；
  批准者必须是人（例外见下节的四级责任）
- 人与 agent 的**协作**是一种明确的责任级别，不是"没记清是谁做的"

## 四、经验的生产流程

```
事实（断言）
  ↓ agent 推导 / 归纳 / 提出判定
候选经验 + 依据 + 推导链
  ↓ 经验准入：依据是否充分、推导链是否完整、是否与既有经验冲突
  ↓ 人确认（高影响项）或按级别自动采纳（低风险项）
经验（带责任级别、时效、推导链）
```

**经验也需要准入**，与断言准入（`admission.spec.md`）同构，但检查项不同：

| | 断言准入 | 经验准入 |
|---|---|---|
| 校验 | schema、引用完整性 | **依据充分性** |
| 分级 | L1–L4 | **责任级别** |
| 冲突 | 与既有断言比 | 与既有经验比 |
| 溯源 | 原文锚点 + 修订标识 | **推导链** |

## 五、责任级别（决定可信度上限）

| 级别 | 来源 | 说明 |
|---|---|---|
| **1** | 人机协作确认 | 人看过并确认了 agent 的产出与依据。**最高** |
| **2** | 人工确认 | 人独立产出或复核 |
| **3** | agent 产出，**依据可复现** | 有推导链或算例，可被重放验证 |
| **4** | agent 产出，**推断** | 无可复现依据。**等同 L4，不得作为权威** |

- Given 一条经验 When 记录 Then 必须带责任级别
- Given agent 独立产出的经验 When 缺少推导链与算例 Then **只能定为 4 级**
- Given 一条经验的可信度 When 计算 Then **不得高于其责任级别所允许的上限**
- Given agent 单独批准了一条高影响经验 When 检测 Then **拒绝**

## 六、总结型经验的积累

工具不仅消费外部经验，**跑起来之后会自己产出经验**。原料是它已经在记录的两样东西：

| 原料 | 已在何处定义 |
|---|---|
| 谁在什么条件下选了什么方案 | `alternatives.spec.md` 的选择记录 |
| 执行结果如何 | `alternatives.spec.md` 的反馈闭环 |

归纳流程：

```
多次「选择 + 结果」记录
  ↓ agent 归纳
候选总结型经验（例：「在 X 条件下，方案类型 A 的达成率高于 B」）
  ↓ 附带样本量与条件范围
  ↓ 人确认
经验（4 级或以上，带样本量）
```

**关键要求：总结型经验必须携带样本量与适用条件。**
没有样本量的"经验"只是意见，不得进入经验层。

## 领域规则（Given-When-Then）

### 归属与形态

- Given 一条经验 When 记录 Then 必须归属到某个**场景**；无归属的经验拒绝记录
- Given 一条经验 When 记录 Then 必须能回溯到产生它的**会话记录中的具体位置**
- Given 既有经验 When 新的判断与它冲突 Then **追加**新条目并标记冲突，**不得覆盖**
- Given 一条经验条目 When 被修订 Then 只能追加修订版本，原条目保留
- Given 会话记录 When 保存 Then **不得删改**——它是依据，可删改的依据不是依据
- Given 一个场景 When 被移除 Then 其会话记录与经验一并处理（见 `project.spec.md`）
- Given 一个场景的经验 When 被另一个场景需要 Then **不得直接共享**；
  应提示该判断可能上下文中立，宜提升为派生断言（见 `derivation.spec.md`）

### 提出与批准

- Given 任何经验的产生或修改 When 记录 Then 必须标识提出者
- Given 一条经验 When 被批准 Then 必须标识批准者，且批准者必须是人
- Given 批准者缺失 When 记录 Then **拒绝**该经验
- Given agent 作为批准者 When 记录 Then **拒绝**
- Given 人与 agent 协作产出 When 记录 Then 责任级别为 1，且提案者与批准者分别记录

### 依据与可重现

- Given 一条推导型经验 When 记录 Then 必须带**推导链**（依赖的断言、所用公式及版本）
- Given 一条推导型经验 When 被引用 Then 必须可被**重放**并得到相同结果
- Given 一条经验无法重放 When 检测 Then 降级为 4 级并标注
- Given 一条总结型经验 When 记录 Then 必须带**样本量**与**适用条件范围**
- Given 总结型经验缺少样本量 When 记录 Then **拒绝**——那是意见，不是经验

### 冲突与时效

- Given 两条经验冲突 When 准入 Then **并存并标记**，不得择一（同 `alternatives.spec.md`）
- Given 经验冲突 When 裁决 Then 必须记录依据、裁决者、时间；裁决本身也是经验
- Given 一条经验所依赖的断言被驳回 When 检测 Then 该经验标记「失效」
- Given 一条经验所依赖的公式被修改 When 检测 Then 该经验标记「待重算」
- Given 一条经验超出其适用条件 When 被引用 Then 标注不适用，**不得静默使用**

### 自动采纳的边界

- Given 责任级别为 3 或 4 的经验 When 被方案引用 Then **允许**，但方案必须标注其级别
- Given 一条经验将影响**方案的选择**（而非仅展示） When 引用 Then 必须至少为级别 2（人工确认）
- 理由：agent 可以产出大量候选经验，但**不能自己决定什么算数**

## 验收标准

- [ ] 每条经验归属到具体场景，无归属时拒绝记录
- [ ] 每条经验可回溯到会话记录中的具体位置
- [ ] 新判断与既有经验冲突时追加并标记，不覆盖
- [ ] 经验修订只追加版本，原条目保留
- [ ] 会话记录不可删改
- [ ] 跨场景的经验复用被拒绝，并提示可能应提升为派生断言
- [ ] 每条经验都记录提出者
- [ ] 每条经验都记录批准者，且批准者是人
- [ ] 缺少批准者时拒绝记录
- [ ] agent 作为批准者时拒绝
- [ ] 协作产出的经验责任级别为 1，且提案者与批准者分别记录
- [ ] 推导型经验带推导链且可重放
- [ ] 无法重放的推导型经验被降级并标注
- [ ] 总结型经验带样本量与适用条件
- [ ] 缺少样本量的总结型经验被拒绝
- [ ] 冲突经验并存且被标记，不自动择一
- [ ] 裁决记录含依据、裁决者、时间
- [ ] 依赖断言被驳回时经验标记失效
- [ ] 依赖公式被修改时经验标记待重算
- [ ] 超出适用条件的经验被标注不适用
- [ ] 3/4 级经验被方案引用时方案标注其级别
- [ ] 影响方案选择的经验至少为 2 级

## 边界与异常

- 提出者与批准者为同一人：允许，但记录中必须体现（自提自批）
- 提出者与批准者为同一 agent：**拒绝**
- 经验引用了不存在的断言或公式：拒绝加载
- 经验的推导链成环：拒绝
- 一条经验的样本量很小（如 1 次）：允许记录，但必须标注样本量，且不得用于影响方案选择
- 一条经验的条件范围覆盖了全部情形：提示可能过度泛化
- 冲突中一方为 1 级、另一方为 4 级：**仍不得自动择一**，但可在展示时标明级别差异
- 人批准了明显错误的经验：记录照实保留，后续可通过核验流程推翻，**不得事后静默修改**
- agent 批量产出候选经验：允许，但必须进入队列，**不得直接成为经验**

## 前后端契约

### 责任级别由参与者与依据**推导**，不由人填

给级别留一个输入框，就一定会有人填错；而级别错会让整层可信度失真。
因此它由两个客观事实算出：

| 参与者 | 依据 | 级别 |
|---|---|---|
| 同时有人与 agent | — | **1**（协作） |
| 只有人 | — | **2**（人工确认） |
| 只有 agent | 有推导链或算例 | **3**（可复现） |
| 只有 agent | 无推导链 | **4**（推断） |

「协作」判据是**参与者里同时出现人与 agent**，不是「记不清是谁做的」。

### 可信度上限

责任级别决定可信度上限。级别 1 与 2 的上限同为 L2——
两者的差别在**来源**（有没有 agent 参与），不在分级本身；
把协作直接抬到 L1 会让「可与原文逐字比对」这个含义被稀释。

| 级别 | 上限 |
|---|---|
| 1 / 2 | L2 |
| 3 | L3 |
| 4 | L4 |

### 冲突的比较键

「与既有经验比」需要一把尺子。同一条经验的身份是
**(场景, 话题)**：同一场景下、同一个话题的两条不同说法即为冲突。
因此 `话题` 是必填项——没有它，冲突检测无从落地。

### 方法

方法挂在 `ExperienceService` 上。

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | `scenario string` | `EntryView[]` | 空场景名表示全部 |
| `Propose` | `Proposal` | `EntryView` | 提出候选经验；**不直接生效** |
| `Approve` | `id, by, reason string` | `EntryView` | `by` 必须是人 |
| `Reject` | `id, by, reason string` | `EntryView` | |
| `Conflicts` | `scenario string` | `ConflictView[]` | 同一 (场景, 话题) 的不同说法 |
| `Sessions` | `scenario string` | `SessionView[]` | |
| `AppendTurn` | `sessionID, role, kind, text string` | `SessionView` | **只能追加**；不存在删除/修改方法 |
| `OpenSession` | `scenario, title string` | `SessionView` | |
| `Refresh` | — | `RefreshResult` | 重算失效/待重算状态 |

`Proposal`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scenario` | string | 是 | 归属场景；无归属拒绝记录 |
| `topic` | string | 是 | 冲突比较键 |
| `kind` | string | 是 | `derived` / `judgment` / `summary` |

| `chain` | string[] | 推导型必填 | 依赖的断言 ID 与公式名 |
| `sampleSize` | int | 总结型必填且 > 0 | 样本量 |
| `sampleFrom` | string | 否 | 样本来自哪 |
| `conditions` | string | 否 | 适用条件范围 |
| `preference` | string | 否 | 该判断假设的偏好 |
| `sessionId` | string | 是 | 依据所在会话 |
| `anchor` | string | 是 | 会话中的具体位置 |
| `proposedByKind` | string | 是 | `human` / `agent` |
| `proposedById` | string | 是 | |
| `collaborators` | `{kind,id}[]` | 否 | 其他参与者；含人即判为协作 |

`EntryView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | |
| `scenario` / `topic` / `kind` | string | 否 | |
| `statement` / `rationale` | string | 否 | |
| `chain` | string[] | 否 | |

### 级别与状态的可观测性

- 每条经验的**责任级别、推导链、依据**必须可被外部读取，而不只显示在界面上
- 级别 3/4 的经验被引用时，引用方必须标注其级别
- 界面**不得**提供修改级别的入口——它由参与者与依据推导


## 待确认

1. agent 的身份如何界定：单一 agent 身份，还是每个 agent 实例独立标识
2. 责任级别 3 的"可复现"由谁验证：自动重放，还是也要人确认
3. 总结型经验的样本量阈值
4. agent 能否独立修改自己的历史产出（倾向：**否**，只能追加）
5. 是否需要「经验冲突的自动发现」——大规模下人工不可能发现所有矛盾
