# 准入层：候选到断言的守门人

## 目的

决定**候选能否成为断言**，并以**变更集**的形式交付。

准入层是事实源的**唯一入口**。接入层拿回来的东西一律不可信；只有经过准入，
外部内容才变成系统内的数据。因此准入层也是**校验不可能被绕过**的保证。

它同时是「自动」与「人工」的交界：能自动判定的一律自动处理；
需要人判断的（分级不确定、冲突、歧义、回退解析）转入核验队列。

## 术语

- **候选（candidate）**：接入层产出、尚未准入的中间产物。
- **准入（admission）**：对候选做出的一组判定。**不是写库动作。**
- **变更集（changeset）**：一次准入产出的待应用变更的集合。
- **分级（grading）**：L1 直引 / L2 结构化 / L3 推导 / L4 推断。
- **自动预检**：全部自动检查通过的状态。**不等于已核验。**
- **歧义挂起**：主体无法唯一解析时中止该候选，**不新建实体、不猜测**。
- **重放（replay）**：对已存档原件重新执行准入。

## 领域规则（Given-When-Then）

### 准入必须完成的判定

- Given 一个候选 When 准入 Then 必须完成且记录以下六项判定：
  1. schema 校验（类型、约束、量纲）
  2. 引用完整性（目标实体与 schema 存在）
  3. 分级判定
  4. 来源与别名登记
  5. 与既有断言的冲突检测
  6. 初始核验状态赋值
- Given 上述任一项未完成 When 候选被应用 Then **拒绝**

### 分级判定

- Given 候选可与原文**逐字比对** When 定级 Then L1
- Given 候选由文本解析得出 When 定级 Then L2
- Given 候选由其他断言推导得出 When 定级 Then L3，且必须记录**推导链**
- Given 候选包含补全的假设 When 定级 Then L4
- Given 候选的解析方式被标记为回退或推测 When 定级 Then **不得定为 L1**
- Given 无法确定级别 When 准入 Then **不得默认为 L1**，应取最低级别并标记

### 冲突处理

- Given 候选与既有断言的主体、谓词、限定条件相同但值不同 When 准入 Then
  **并存并标记冲突**，不得覆盖
- Given 候选与既有断言完全相同 When 准入 Then 幂等，不产生新断言
- Given 候选与**已核验**断言冲突 When 准入 Then 冲突进入人工队列，
  **不得自动采信新值，也不得自动保留旧值**
- Given 候选与既有断言限定条件不同 When 准入 Then 视为不同断言，并存，不构成冲突

### 主体解析与别名

- Given 候选引用了未登记的名称 When 准入 Then 必须解析为稳定标识
- Given 一个名称指向多个主体 When 准入 Then **歧义挂起**：中止该候选并转入人工队列，
  **不得猜测，也不得新建实体**
- Given 候选带来了新的别名 When 准入 Then 登记别名及其**来源与适用范围**
- Given 别名与既有别名冲突 When 准入 Then 标记冲突，不覆盖

### 未知值

- Given 候选表示「该有值但我们不知道」 When 准入 Then 记为**未知**，
  不得记为空值、缺失，也不得推断一个值（见 `metamodel.spec.md`）
- Given 一个字段为「未知」 When 校验 `required` Then 通过，但不计入已填充

### 初始核验状态

- Given 候选通过全部自动检查 When 准入 Then 状态为**「已自动预检」**，
  **不得为「已核验」**
- Given 候选出现以下任一情形 When 准入 Then 转入核验队列：
  分级不确定、与已核验断言冲突、主体歧义、解析回退、引用目标缺失
- Given 候选被拒绝 When 记录 Then 必须记录**拒绝原因与位置**，不得只记「失败」

### 变更集

- Given 一次准入 When 完成 Then 产出**变更集**，**不得直接写事实源**
- Given 变更集 When 应用 Then 必须原子：要么全部成功、要么全部回滚
- Given 变更集 When 应用 Then 必须产出审计记录（来源、候选数、接受/拒绝/挂起数、时间）
- Given 变更集被拒绝应用 When 处理 Then 候选状态保留，可修正后重新准入

> 变更集的原子应用与 `migration.spec.md` 共用同一套执行机制——
> 二者都是「一批必须整体成功的数据变更」。

### 重放与幂等

- Given 准入规则改进 When 对已存档原件重放 Then 必须能重新产出变更集，
  **不需要重新抓取**（见 `ingestion.spec.md`）
- Given 重放 When 执行 Then 不得重复创建已存在的断言
- Given 重放产生了与上次不同的结论 When 记录 Then 必须能说明是规则变更导致的，
  并保留两次结论的差异

## 验收标准

- [ ] 每个候选的准入记录包含六项判定结果
- [ ] 六项判定任一项缺失时候选被拒绝
- [ ] 可逐字比对的内容定为 L1
- [ ] 回退解析产生的候选不被定为 L1
- [ ] 无法确定级别时不默认 L1，而是取最低并标记
- [ ] 同主体同谓词同限定条件而值不同的候选与既有断言并存且标记冲突
- [ ] 完全相同的候选不产生新断言
- [ ] 与已核验断言冲突时进入人工队列，不自动采信任一方
- [ ] 限定条件不同的候选不构成冲突
- [ ] 主体歧义时挂起，不猜测、不新建实体
- [ ] 新别名被登记并带来源与适用范围
- [ ] 「未知」值不被记为空值或缺失，也不被推断
- [ ] 自动检查通过的状态为「已自动预检」，非「已核验」
- [ ] 需要人工判断的候选进入核验队列
- [ ] 被拒绝的候选带具体原因与位置
- [ ] 准入产出变更集而非直接写库
- [ ] 变更集应用原子化，失败全回滚
- [ ] 变更集应用产出审计记录
- [ ] 重放不需要重新抓取
- [ ] 重放不重复创建已有断言
- [ ] 重放结论变化时可展示两次差异

## 边界与异常

- 候选引用的 schema 尚未加载：**挂起**，不拒绝也不假装通过
- 候选引用的主体在所有来源中都不存在：挂起并转入人工队列，**不自动创建实体**
- 候选值超出枚举集合：接受并标记「未建模取值」（见 `metamodel.spec.md`）
- 候选使用 `opaque` 字段：接受，但计入未建模
- 一次准入中同一断言被多次提出且值不同：全部保留并标记冲突
- 候选与已驳回断言相同：不因「曾被驳回」而自动拒绝，但必须指出该历史
- 变更集应用中途失败：全部回滚，候选状态保留为「待重新准入」
- 重放时原件已被删除：明确报告无法重放，不得静默跳过
- 准入规则自身出错（崩溃）：候选保持未准入状态，不得部分应用
- 主体解析依赖的别名表本身处于冲突状态：歧义挂起

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 被拒绝的候选必须能查到**具体原因与原文位置**，而不只是「不合格」
- 歧义与冲突必须**成对呈现**（候选与其对立方），供人工裁决
- 变更集在应用前必须可预览
- 准入与重放的操作必须可审计

## 待确认

1. 「自动预检通过」的候选是否可以不等待人工核验即被方案引用？
   —— 当前设计为**可以，但必须标注未核验**（见 `verification.spec.md`）
2. 冲突进入人工队列后，是否会阻塞该主体的其他候选？
3. 变更集的粒度：按源 / 按同步批次 / 按主体
4. 重放是否需要与新准入走同一套审计，还是单独标记
5. 准入规则版本是否需要与断言关联（便于解释历史结论）

## 附：四层流水线中的位置

```
外部源
  ↓  接入层：取回、存档、解析            （不可信，可替换，有副作用）
候选
  ↓  准入层：校验、分级、冲突、登记        （守门人，可重放，无副作用）
变更集 → 原子应用 → 断言库
  ↓
核验层：人工验证与可信度                  （见 verification.spec.md）
  ↓
方案层：备选方案生成                      （见 alternatives.spec.md）
```

- 接入层**发现**变化，准入层**决定**影响面。
- 准入层不写库，只产出变更集；写库是独立的原子应用步骤。
- **重放**使准入层可以在不重新抓取的前提下被反复改进——这是分层的最大收益。
