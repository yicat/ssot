# 准入：候选到事实的守门人（底座）

## 目的

决定**候选能否成为事实**，并以**变更集**的形式交付。

准入是项目基础数据的**唯一入口**。工具取回来的、导入的东西一律不可信；
只有经过准入，外部内容才变成系统内的数据。因此准入也是**校验不可能被绕过**的保证——
工具没有直接写库的近路（见 `tools.spec.md`），Agent 的改动走提议与拍板
（见 `agent.spec.md`），最后都必须从这里过。

它同时是「自动」与「人工」的交界：能自动判定的一律自动处理；
需要人判断的（分级不确定、冲突、指代不明）**登记成待办**——
要么是歧义事项（见 `decision.spec.md`），要么是提议（见 `agent.spec.md`）。
**没有核验队列**：需要人动手的事集中在工作台的待办区（见 `workspace.spec.md`）。

## 术语

- **候选（candidate）**：工具或导入产出、尚未准入的中间产物。
- **准入（admission）**：对候选做出的一组判定。**不是写库动作。**
- **变更集（changeset）**：一次准入产出的待应用变更的集合。
- **分级（grading）**：L1 直引 / L2 结构化 / L3 推导 / L4 推断。
- **自动预检**：全部自动检查通过的状态。**不等于已核验。**
- **挂起**：无法自动判定时中止该候选并登记待办，**不猜测、不新建东西**。
- **重放（replay）**：对已存档内容重新执行准入。

## 领域规则（Given-When-Then）

### 准入必须完成的判定

- Given 一个候选 When 准入 Then 必须完成且记录以下六项：
  1. **定义校验**：谓词来自齐备可用的数据定义；类型、约束、量纲相符
  2. **引用完整性**：引用的主体与定义存在
  3. **分级判定**
  4. **来源与指代登记**：来源、溯源锚点；称呼走词表机制
  5. **冲突检测**：与既有事实比对
  6. **初始状态赋值**
- Given 上述任一项未完成 When 候选被应用 Then **拒绝**
- Given 候选的谓词所依据的数据定义**不齐备**（缺使用文档、显示名未挂词条）
  When 准入 Then **拒绝**，并说明定义为什么不可用——
  「定义不齐备」不是警告，是硬门槛（见 `dataschema.spec.md`）

### 分级判定

- Given 候选可与原文**逐字比对** When 定级 Then L1
- Given 候选由文本解析得出 When 定级 Then L2
- Given 候选由其他内容推导得出 When 定级 Then L3，且必须记录**推导链**
- Given 候选包含补全的假设 When 定级 Then L4
- Given 候选的解析方式被标记为回退或推测 When 定级 Then **不得定为 L1**
- Given 无法确定级别 When 准入 Then **不得默认为 L1**，应取最低级别并标记
- Given 候选的分级 When 定级 Then **不得超过**其抽取规则声明的上限
  （见 `dataschema.spec.md` 的 `extract.maxConfidence`）

### 冲突处理

- Given 候选与既有事实的主体、谓词、限定条件相同但取值不同 When 准入 Then
  **并存并标记争议**，不得覆盖
- Given 候选与既有事实完全相同 When 准入 Then 幂等，不产生新事实
- Given 候选与**已拍板**的事实冲突 When 准入 Then
  **登记为歧义事项**（见 `decision.spec.md`），**不得自动采信新值，
  也不得自动保留旧值**
- Given 候选与既有事实限定条件不同 When 准入 Then 视为不同事实，并存，不构成冲突
- Given 冲突涉及两条以上来源 When 准入 Then 把各来源与依据**成对摆出**，
  使人在裁决时不需自己去查

### 主体解析与指代

- Given 候选引用了未登记的名称 When 准入 Then 必须解析为稳定标识
- Given 该名称在文档里的**来历**尚未登记 When 准入 Then **自动登记该称呼及其来历**
  ——这只是记录「文档里这么写」，不是判断
- Given 一个称呼指向多个词条 When 准入 Then **挂起**：中止该候选，
  登记为**指代歧义**交人裁决，**不得猜测，也不得新建词条**
- Given 该称呼有**条件指代规则**能唯一判定 When 准入 Then 直接判定并记录用了哪条规则
- Given 称呼与既有称呼冲突（同一称呼在同一条件下被指向不同词条） When 准入 Then
  登记为歧义，不覆盖

### 未知值

- Given 候选表示「该有值但我们不知道」 When 准入 Then 记为**未知**，
  不得记为空值、缺失，也不得推断一个取值（见 `dataschema.spec.md` 的四态）
- Given 一个字段为「未知」 When 校验必填 Then 通过，但不计入已填充

### 初始状态

- Given 候选通过全部自动检查 When 准入 Then 状态为**「已自动预检」**，
  **不得为「已核验」**
- Given 候选出现以下任一情形 When 准入 Then **挂起**并登记待办：
  分级不确定、与已拍板事实冲突、指代不明、回退解析、引用目标缺失
- Given 挂起 When 登记 Then 必须归入两类之一：
  **歧义事项**（需要选一个）或**提议**（需要人确认一个改动）
- Given 候选被拒绝 When 记录 Then 必须记录**拒绝原因与位置**，不得只记「失败」

### 变更集

- Given 一次准入 When 完成 Then 产出**变更集**，**不得直接写事实源**
- Given 变更集 When 应用 Then 必须原子：要么全部成功、要么全部回滚
- Given 变更集 When 应用 Then 必须产出审计记录
  （来源、候选数、接受/拒绝/挂起数、时间）
- Given 变更集被拒绝应用 When 处理 Then 候选状态保留，可修正后重新准入
- Given 一次变更集 When 预览 Then 必须能说明它会影响哪些已有内容
  （冲突数、将标为依据已变的引用数）

> 变更集的原子应用与定义演进（见 `dataschema.spec.md`）共用同一套执行机制——
> 二者都是「一批必须整体成功的数据变更」。

### 重放与幂等

- Given 准入规则改进 When 对已存档内容重放 Then 必须能重新产出变更集，
  **不需要重新取数**
- Given 重放 When 执行 Then 不得重复创建已存在的事实
- Given 重放产生了与上次不同的结论 When 记录 Then 必须能说明是规则变更导致的，
  并保留两次结论的差异
- Given 重放 When 执行 Then 已拍板的结论**不因重放而改变**，
  除非重放结论与之冲突——那时登记为歧义提请人看

## 验收标准

- [ ] 每个候选的准入记录包含六项判定结果
- [ ] 六项判定任一项缺失时候选被拒绝
- [ ] 谓词来自齐备可用的数据定义，定义不齐备时拒绝并说明原因
- [ ] 可逐字比对的内容定为 L1
- [ ] 回退解析产生的候选不被定为 L1
- [ ] 分级不超过抽取规则声明的上限
- [ ] 无法确定级别时不默认 L1，而是取最低并标记
- [ ] 同主体同谓词同限定条件而取值不同的候选与既有事实并存且标记争议
- [ ] 完全相同的候选不产生新事实
- [ ] 与已拍板事实冲突时登记为歧义事项，不自动采信任一方
- [ ] 冲突把各来源与依据成对摆出
- [ ] 限定条件不同的候选不构成冲突
- [ ] 未登记的名称被解析为稳定标识
- [ ] 称呼的来历被自动登记
- [ ] 一个称呼指向多个词条时挂起并登记指代歧义，不猜测、不新建词条
- [ ] 有条件指代规则能唯一判定时直接判定并记录用了哪条规则
- [ ] 「未知」值不被记为空值或缺失，也不被推断
- [ ] 自动检查通过的状态为「已自动预检」，非「已核验」
- [ ] 需要人判断的候选被归入歧义事项或提议两类之一
- [ ] 被拒绝的候选带具体原因与位置
- [ ] 准入产出变更集而非直接写库
- [ ] 变更集应用原子化，失败全回滚
- [ ] 变更集应用产出审计记录
- [ ] 变更集可预览并说明影响面
- [ ] 重放不需要重新取数
- [ ] 重放不重复创建已有事实
- [ ] 重放结论变化时可展示两次差异
- [ ] 重放不改变已拍板的结论，冲突时提请人看

## 边界与异常

- 候选引用的定义尚未加载：**挂起**，不拒绝也不假装通过
- 候选引用的主体在所有来源中都不存在：挂起并登记待办，**不自动创建主体**
- 候选取值超出枚举集合：接受并标记「未建模取值」（见 `dataschema.spec.md`）
- 候选使用未建模字段：接受，但计入未建模
- 一次准入中同一事实被多次提出且取值不同：全部保留并标记争议
- 候选与已驳回的事实相同：不因「曾被驳回」而自动拒绝，但必须指出该历史
- 变更集应用中途失败：全部回滚，候选状态保留为「待重新准入」
- 重放时原件已被删除：明确报告无法重放，不得静默跳过
- 准入规则自身出错（崩溃）：候选保持未准入状态，**不得部分应用**
- 流程中依赖的指代规则本身处于冲突状态：挂起
- 候选没有任何溯源锚点（例如由 Agent 直接给出）：不得走准入；
  它应当走提议路径（见 `agent.spec.md`）——**准入处理的是有出处的候选**

## 前后端契约

准入不单独设界面；它的结果体现在各部件服务的返回里。已确定的约束：

- 被拒绝的候选必须能查到**具体原因与位置**，而不只是「不合格」
- 挂起必须落到具体的待办项上：歧义事项给得出候选，提议给得出差异
- 变更集在应用前必须可预览，预览必须含影响面（冲突数、将失效的引用数）
- 准入与重放的操作必须可审计，且能回答「某次重放为什么得出不同结论」
- **不提供**「待核验队列」接口：挂起项的出口是待办区的两个列表

## 待确认

1. 「自动预检通过」的内容是否可以不等待人的任何动作即被答案引用？
   —— 当前设计为**可以，但必须标注未核验**（见 `verification.spec.md`）
2. 冲突挂起后，是否会阻塞该主体的其他候选
3. 变更集的粒度：按来源 / 按同步批次 / 按主体
4. 重放是否需要与新准入走同一套审计，还是单独标记
5. 准入规则版本是否需要与事实关联（便于解释历史结论）

## 附：流水线中的位置

```
外部源
  ↓  工具 / 导入：取回、存档              （产出不是事实源，可替换，有副作用）
候选
  ↓  准入：定义校验、分级、冲突、指代登记    （守门人，可重放，无副作用）
变更集 → 原子应用 → 项目基础数据
  ↓
核验记录（按需追加，**不排队**）
  ↓
Case 按条件给答案（标注未核验比例与依据版本）
```

- **工具发现变化，准入决定影响面。**
- 准入不写库，只产出变更集；写库是独立的原子应用步骤。
- **重放**使准入可以在不重新取数的前提下被反复改进——这是分层的最大收益。
- 需要人动手的事**只有两处出口**：歧义事项、提议。二者都在工作台的待办区。
