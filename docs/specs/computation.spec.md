# 计算：表达式、量纲与时间（底座）

## 目的

定义平台的计算能力。这是项目**声明式计算方式的唯一途径**——
平台不内置任何领域公式，公式由项目提供（「公式即数据」，见 `basicdata.spec.md`）。

三件事：

1. **表达式语言**——项目用它写公式（伤害、配速、收益、排期）。
2. **量纲检查**——在求值前挡掉一整类错误（把百分数当小数、把不同量纲相加）。
3. **时间与周期**——周期性产出、时长聚合、排期。

核心立场：**「不能错」的最后一环是算对。**
数据再准、公式算错，结果就是错的；而公式若不透明、不可测，错误就无法被发现。

## 术语

- **表达式（expression）**：一段声明式的计算描述，由项目提供。
- **求值（evaluate）**：用具体输入计算表达式的结果。
- **量纲（dimension）**：可互相换算的单位所属的类别（比例、计数、时间）。
- **单位（unit）**：具体计量单位（`percent`、`fraction`、`point`、`day`…）。
  同量纲的不同单位可换算。
- **周期（period）**：可重复的时间单位（每日 / 每周 / 每月 / 每版本 / 一次性）。
- **算例（case）**：一组输入与期望输出，用于锁定公式的正确性。
- **随机量**：取值不确定的量。**必须显式标记**，不得当作确定值参与计算。

## 一、表达式语言

### 类型

| 类型 | 说明 |
|---|---|
| `number` | 数值，**带单位** |
| `text` | 文本 |
| `bool` | 布尔 |
| `date` / `datetime` | 时间点 |
| `duration` | 时长（用于周期聚合） |
| `period` | 周期（每日 / 每周 / …） |
| `record` | 记录引用（可取字段） |
| `list` | 同质列表 |

### 字面量

- 数值：`50`、`0.5`
- 带单位：`50%`（等价于 `0.5`，单位为 `percent`）、`10 point`、`30 day`
- 文本：`"每日"`
- 布尔：`true` / `false`
- **无单位的数值字面量采用所在上下文的单位**（使 `speed + 10` 合法）

### 运算符

| 类别 | 运算符 |
|---|---|
| 算术 | `+ - * / % ^` |
| 比较 | `== != < <= > >=` |
| 逻辑 | `and` `or` `not` |
| 条件 | `if 条件 then 值 else 值` |
| 字段 | `记录.字段` |
| 集合 | `[a, b, c]` |

### 聚合与筛选

```
sum(表达式 where 条件)
count(表达式 where 条件)
max / min / avg(表达式 where 条件)
```

`where` 可省略。聚合作用于集合。

### 时间与周期

```
days(n) / weeks(n) / months(n) / years(n)     → duration
cycles(period, duration)                       → number，某周期在时长内的次数
over(表达式, duration)                          → 把「每周期一次」的量换算为该时长的总量
```

示例——「一个月能攒多少勾玉」：

```
over(
  sum(source.amount where source.period == daily)
  + sum(source.amount where source.period == weekly) * cycles(weekly, months(1)) / 1,
  months(1)
)
```

### 随机量

- 随机量**必须**用标记包裹，例如 `expected(抽卡次数 * 出货概率)`
- 未标记的随机量参与计算时，求值**拒绝执行**并指出位置
- 随机量的结果必须给出**区间或期望**，不得呈现为确定值

### 静态检查

求值前必须完成，且错误必须**在撰写期**而非运行期暴露：

- 字段引用是否存在（对照数据定义）
- 类型是否匹配
- **单位是否相容**
- 函数名与参数个数
- 聚合是否作用于集合

## 二、量纲检查

### 规则

- `+` 与 `-`：两侧必须**同量纲**（可换算），结果取左操作数的单位
- `*` 与 `/`：单位按代数组合；`percent` 与其他单位相乘时视为无量纲缩放
- 比较：两侧必须同量纲，或一侧为无单位字面量
- 函数参数：按声明的单位要求检查

### 能抓到什么

| 错误 | 是否拦下 |
|---|---|
| `暴击率(percent) + 速度(point)` | ✅ 量纲不同 |
| `50` 当 `0.5` 用（`percent` 与 `fraction` 混用） | ✅ 同量纲不同单位，按换算表归一 |
| `攻击(point) * 倍率(percent)` | ✅ 合法，结果为 `point` |
| **同量纲但语义不同**（`攻击 + 防御`） | ❌ **抓不到**——这需要领域语义，超出量纲能力 |

最后一行是**已知限制，必须写进文档**，不能让人以为量纲检查能挡住一切。

### 换算表

- 换算关系是**数据**，不是代码，可扩展
- 两个同量纲单位之间无换算关系时，**拒绝运算**并指出缺失的单位对
- 换算关系本身属于项目内容，**可被拍板、可被核验**

## 三、公式的测试与验证

### 每个公式必须可测

- 公式必须能接受一组输入并产出确定输出（随机量除外，见下）
- 公式应配有**算例**：给定输入 → 期望输出
- 算例中的期望输出**优先来自实测**，其次来自其他已核验来源

### 公式的可信度

- Given 一个公式**配有算例且全部通过** When 被引用 Then 视为该公式已验证
- Given 一个公式**没有算例** When 被引用 Then **允许**，但引用它的答案必须标注
  「公式未验证」
- Given 一个算例**未通过** When 引用该公式 Then **拒绝**，并报出失败的算例

### 公式与实测的交叉验证

这是计算层的核心机制：

```
公式算出的值  vs  实测观测的值
  一致 → 公式获得一条实测级依据
  不一致 → 报冲突，不得自动采信任一方
```

- Given 一个公式的输出与实测值不一致 When 检测 Then **标记冲突**，
  并保留两侧的输入条件
- Given 实测值与公式不一致 When 分析 Then 必须能回答「是公式错，还是输入数据错」
  ——做法是把该次实测的**输入**一并记录，重放公式

## 领域规则（Given-When-Then）

### 求值

- Given 一个表达式 When 求值 Then 必须先完成静态检查，未通过**不得执行**
- Given 表达式引用了数据定义中不存在的字段 When 静态检查 Then 失败并指出位置
- Given 表达式两侧单位不可换算 When 静态检查 Then 失败并指出单位对
- Given 同一表达式与同一输入 When 重复求值 Then 结果必须一致（**确定性**）
- Given 表达式含未标记的随机量 When 求值 Then **拒绝执行**
- Given 表达式含已标记的随机量 When 求值 Then 结果为区间或期望，且标注其随机性
- Given 一次求值 When 产出结果 Then 该结果的**归属**由上下文中立性决定：
  上下文中立 → 可固化为项目级派生值；依赖 Case 上下文 → 仅作为 Case 中间结果
  （见 `derivation.spec.md`）
- Given 一次求值的结果 When 被缓存 Then 必须携带输入指纹；
  指纹不匹配则重算或拒绝使用
- Given 求值失败 When 报告 Then 必须说明**缺什么**：
  缺哪个字段声明、哪个输入、哪条换算关系——不得只给一句失败

### 单位与换算

- Given 两个同量纲不同单位的值 When 运算 Then 按换算表归一后运算
- Given 两个单位之间无换算关系 When 运算 Then 拒绝并指出缺失的单位对
- Given 无单位字面量参与运算 When 求值 Then 采用上下文单位
- Given 一个数值字段 When 声明 Then 必须声明单位（见 `dataschema.spec.md`）

### 时间与周期

- Given 一个周期性产出的量 When 按某时长聚合 Then 由 `cycles` 换算，
  **不得手工折算**
- Given 一个周期在时长内不能整除 When 聚合 Then 结果必须标注为近似，
  并说明取整方式
- Given 跨越时间点的事件（活动起止） When 参与计算 Then
  必须按时长而非「第几次」表达
- Given 一个量的周期未声明 When 参与时间聚合 Then **拒绝**并指出缺失

### 公式的生命周期

- Given 一个公式 When 被创建 Then 必须记录其作者、来源与依据
  （与项目级内容同等要求，见 `basicdata.spec.md`）
- Given 一个公式被修改 When 记录 Then 必须保留旧版本，
  且引用旧版本的结果不受影响
- Given 公式与算例冲突 When 检测 Then 报告冲突，不自动修正任一方
- Given 一个公式被多处引用 When 它发生变更 Then 必须能列出受影响的地方，
  并把它们标为**待重算**

### 与校验约束的关系

- Given 校验约束（`requiredIf`、`compare` 等） When 声明 Then
  **仍使用固定形式**，不改为任意表达式
- 理由：校验约束需要可结构化展示、可逐条定位失败原因、可由界面生成表单；
  改为任意表达式会让数据定义变成代码，失去可检查性
- 同理，**回填策略**也不用表达式（见 `dataschema.spec.md` 的演进一节）——
  回填是数据操作，不是计算

## 验收标准

- [ ] 静态检查在求值前完成，未通过不执行
- [ ] 引用不存在的字段时指出位置
- [ ] 单位不可换算时指出单位对
- [ ] 无量纲字面量采用上下文单位
- [ ] 同量纲不同单位按换算表归一
- [ ] 缺换算关系时拒绝运算并指出缺失的单位对
- [ ] `percent` 与 `fraction` 混用被归一而非误判为冲突
- [ ] 聚合支持 `where` 筛选
- [ ] `cycles` 正确换算周期与时长
- [ ] 周期不能整除时结果标注近似与取整方式
- [ ] 未声明周期的量参与时间聚合时被拒绝
- [ ] 未标记的随机量导致求值被拒
- [ ] 已标记的随机量输出区间或期望并标注
- [ ] 相同表达式与相同输入重复求值结果一致
- [ ] 公式无算例时可被引用，但答案标注「公式未验证」
- [ ] 算例未通过时公式被拒绝引用，并报出失败算例
- [ ] 公式与实测不一致时报冲突，保留两侧输入条件
- [ ] 公式修改后保留旧版本，既有结果不受影响
- [ ] 能列出因公式变更而受影响的地方，并标为待重算
- [ ] 求值失败时说明缺哪个声明、哪个输入或哪条换算关系
- [ ] 量纲检查抓不到「同量纲但语义不同」，且这一点写进文档
- [ ] 校验约束与回填策略仍用固定形式，未改成表达式

## 边界与异常

- 表达式为空：拒绝
- 除零：求值失败并指出位置，**不得返回无穷或零**
- 数值溢出：失败，不得回绕
- 聚合作用于空集合：按声明的恒等值处理（`sum` 为 0，`avg` 为未知），
  **不得报错也不得返回 0 冒充平均值**
- `cycles` 的周期为「一次性」且时长已过：返回 1，不得返回 0 或无限
- 时长跨越版本变更：结果标注跨越了版本边界，可能不适用
- 换算表存在循环定义：拒绝加载换算表
- 算例的期望输出本身来自未核验来源：允许，但该算例的证据等级随之降低
- 公式引用其他公式：允许，但必须记录依赖链；存在循环引用时拒绝
- 公式执行超时：中断并报告，**不得返回部分结果**
- 随机量的分布未声明：允许用期望值，但必须标注「仅期望，未含分布」
- 表达式语法错误：报告位置与期望，不猜测作者意图

## 前后端契约

公式的**呈现契约**见 `basicdata.spec.md`（公式与算例、算例状态三态）。
本规格只定行为约束：

- 静态检查的错误必须**指出具体位置**（列号），而不只是失败状态
- 求值结果必须携带其单位、随机性标注与所用公式的版本
- 公式与其算例必须可被外部读取，以支持复用与审查
- 答案的输出必须能追溯到**每一条公式及其算例的通过情况**
- 三级状态（算例全过 / 无算例 / 算例未过）在呈现上**不得互相等同**
- 求值失败时的「缺什么」必须逐项列出，使界面能生成修复提示

## 待确认

1. 表达式语法的最终形态（当前为 C 风格中缀）
2. 是否需要用户自定义函数（当前只有内置函数）
3. 随机量是否需要支持完整分布，还是先只支持期望值
4. 算例的组织方式：附在公式上，还是作为独立条目
5. 单位换算表归属：平台内置一份基础表，还是完全由项目提供
6. 求值超时的具体上限
7. 是否允许公式引用记录集合之外的输入（例如 Case 的条件），以及如何声明

## 附：为什么必须有表达式引擎

早先的规格里曾出现「**不得使用任意表达式**」，理由是
「标准库无表达式求值能力、离线环境无表达式库」。

**那个理由是实现现状，不是设计目标。** 在「公式即数据」这一前提下它被推翻：

- 若只服务一个用途，公式可以写死在代码里；
- 要做成平台，**不同的项目与 Case 公式不同，不可能为每个项目改代码**，
  因此公式必须由使用者在项目里声明 ⇒ **必须有一个表达式引擎**。

同时保留两处**不用**表达式的地方，各有其理由：

| 位置 | 做法 | 理由 |
|---|---|---|
| 校验约束 | 只用四种固定形式 | 需可结构化展示、可逐条定位失败原因、可由界面生成表单 |
| 回填策略 | 只允许常量 / 复制 / 标记未知 | 回填是数据操作，不是计算 |
