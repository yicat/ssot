# 项目基础数据：事实、计算方式与质量

## 目的

数据定义说的是「字段长什么样」，这一层装的是**实际的值**，外加两样经常被塞进代码里的东西：

1. **计算方式**。「哪些加成是加算、哪些是乘算」「取整方式」「运算顺序」——
   这些是项目的知识，不是程序的逻辑。它们必须是**数据**：可声明、可核验、可替换。
   写死在代码里，换一个游戏就要改代码，而且没人能回答「这个数是怎么算出来的」。
2. **质量**。「275 个式神里有 268 个有暴击系数」——缺口在哪、缺多少，必须能一眼看到。

事实本身用**断言**表示：主体、谓词、取值、限定条件、来源、溯源、分级。
这是上一版留下来的底座，**保留它**：来源可追、冲突可并存、分级让「直引」与「推断」可分辨。
但**取消独立的核验界面**——这个结构里人负责提要求与拍板，交叉校验是 Agent 的活。

## 术语

- **断言（assertion）**：一条事实。主体 + 谓词 + 取值 + 限定条件 + 来源 + 溯源 + 分级。
- **限定条件（qualifiers）**：这条事实在什么条件下成立。**限定条件不同的两条断言不是同一条。**
- **来源（source）**：这条值从哪来（某份文档、某次工具执行、某次交叉校验的结论）。
- **溯源（provenance）**：锚点——哪份文档的哪一版、哪一段。**只能指一处。**
- **分级（confidence）**：直引 / 结构化 / 推导 / 推断。**回退解析读出来的值不得算直引。**
- **公式（formula）**：一段有名字、有版本、有输入输出与量纲的表达式，带算例。
- **计算约定（convention）**：加算 / 乘算 / 取整 / 顺序这类规则的声明。
- **派生值（derived）**：由公式算出来的值。它是断言，但分级是推导，不是直引。
- **覆盖率**：有值的占比。**分母是主体数**，同一谓词的多条断言只算一次。

## 领域规则（Given-When-Then）

### 事实用断言表示

- Given 一条事实 When 记录 Then 必须携带七项：主体、谓词、取值、限定条件、来源、溯源、分级；
  **缺任一项即拒绝**
- Given 一条事实 When 记录 Then 它的溯源**只能指一处**（一份文档的某一版某一段）——
  指多处的话「这个值从哪读出来的」就没有唯一答案，变更传导也无从判断该标什么
- Given 同一件事由多份独立来源佐证 When 记录 Then 那是**多条断言**加上交叉校验的结论，
  不是一条断言挂多个来源
- Given 一条事实 When 记录 Then 它的谓词必须来自一个**齐备可用**的数据定义
  （见 `dataschema.spec.md`）；定义不可用时该值不得进入基础数据
- Given 一条事实 When 主体或谓词指向不存在的东西 Then 拒绝，并指出哪一项不存在

### 限定条件

- Given 两条断言 When 主体与谓词相同而取值不同 Then 检查限定条件：
  **限定条件不同 → 两条都合法，并存，互不覆盖**
- Given 两条断言 When 主体、谓词、限定条件全同而取值不同 Then 两条都留，
  标为**有争议**，**系统不自动择一**——谁对谁错要人判断，或者由交叉校验取证后由人拍板
- Given 一个条件性的事实 When 记录 Then 条件落在**限定条件**上，不落在数据定义上
  （定义描述字段长什么样，数据描述什么条件下是什么）
- Given 一条断言的限定条件 When 展示 Then 必须显示出来——
  把两条条件不同的值并列而不显示条件，等于制造了一个假冲突

### 来源与分级

- Given 一条断言 When 记录 Then 记录它是怎么来的：哪份文档、哪次工具执行、
  还是哪次交叉校验的结论
- Given 一条值由**回退解析**读出（原文没有明确格式，靠猜格式读到的） When 记录 Then
  它的分级**不得为直引**；解析方式决定分级上限
- Given 一条值由公式算出 When 记录 Then 分级为推导，并记录它依赖的公式版本
- Given 一条值由 Agent 推断得出 When 记录 Then 分级为推断，并标明是推断
- Given 一个答案 When 引用基础数据 Then 必须带上所引用值的分级与未核验比例
- Given 一个值 When 分级为直引 Then 它必须能被**逐字比对**原文验证
- Given 基础数据 When 展示 Then 分级必须可见且可区分——
  直引与推断长得一样，等于让人盲信

### 冲突

- Given 两条冲突的断言 When 记录 Then 都标为有争议，且**都保留**
- Given 一次交叉校验 When 完成 Then 给出「一致 / 矛盾 / 单源」的结论与依据；
  **结论不自动改写数据**，它是一条提议（见 `agent.spec.md`）
- Given 互相转载的两份文档 When 交叉校验 Then **只算一份证据**
  （转载关系见 `document.spec.md`）
- Given 争议 When 由人拍板 Then 记录选了哪条、凭什么、是谁；
  未被选中的那条**保留**并标为「已否决但保留」

### 写入路径

- Given 任何来源产生的候选值 When 要进入基础数据 Then **必须经过准入**
  （见 `admission.spec.md`）：校验定义、类型、量纲、约束、身份、来源
- Given 一次准入 When 成功 Then 以**变更集**的形式原子应用；失败全回滚
- Given 工具执行产生的产出 When 想要入库 Then **工具本身不得直接写入**——
  它只能产出候选（见 `tools.spec.md`）
- Given 主对话 Agent 想改基础数据 When 生效 Then 必须取得人的拍板（见 `agent.spec.md`）
- Given 未在数据定义中声明的字段 When 出现在候选里 Then **被准入层过滤**，
  并报出来——不静默丢弃，也不放行

### 计算方式就是数据

- Given 一段计算方式 When 需要被使用 Then 必须**在项目里声明**：
  名字、版本、输入（含量纲）、输出（含量纲）、表达式、算例
- Given 一个公式 When 声明 Then 必须有**算例**：一组已知输入与期望输出
- Given 一个公式 When 被引用而它**没有算例** Then 允许使用，
  但引用它的答案必须标注「公式未验证」
- Given 一个公式的算例**未通过** When 被引用 Then **拒绝**，并报出失败的算例
- Given 两个来源就同一计算方式说法不同 When 遇到 Then 报冲突，保留两侧的输入条件，
  **不得取其一**
- Given 一个公式 When 修改 Then **旧版本保留**，引用旧版本的既有结果不受影响
- Given 公式变更 When 完成 Then 列出受影响的派生值与答案，并标为「待重算」
- Given 计算约定（加算/乘算/取整/顺序） When 声明 Then 与公式同等对待：
  有名字、有版本、需拍板、可被引用
- Given 一条计算方式 When 只在代码里存在而项目里没有声明 Then 是缺陷：
  计算结果出不来时必须说明「缺哪条声明」，不得悄悄用代码里的默认行为

### 派生值

- Given 一个值由公式算出 When 固化为断言 Then 记录推导链：用了哪个公式的哪一版、
  依赖了哪些断言
- Given 上下文中立的值（与任何 Case 无关） When 计算 Then 可以固化为断言；
  上下文相关的值**不固化**——它只属于那一次计算
- Given 缓存 When 使用 Then 记录输入指纹；指纹不匹配时缓存**不得使用**
- Given 缓存 When 呈现 Then **不得被呈现为已核验事实**——缓存不是断言
- Given 清空缓存 When 执行 Then 不产生数据损失

### 质量视图

- Given 一个字段 When 统计覆盖率 Then 分母是**主体数**；
  同一谓词的多条断言（限定条件不同）**只算一次**
- Given 值为「未知」或「空值」 When 统计 Then **不计为已填充**（四态见 `dataschema.spec.md`）
- Given 一类主体 When 一条数据都没有 Then 仍要列出并标为「无数据」——
  不列出来，人就以为它不存在
- Given 数据里出现而未在定义中声明的字段 When 统计 Then 列出，并说明它会被准入层过滤
- Given 定义里有而数据里从未出现的字段 When 统计 Then 列出
- Given 必填字段没有值 When 统计 Then **单独标出**，与「整体为空」区分
- Given 一个字段的覆盖率为 100% When 展示 Then 不得呈现为「数据正确」——
  覆盖率只说填了没有，不说填得对不对
- Given 使用了未建模字段 When 统计 Then 计为未建模，不计为已填充
- Given 质量视图 When 展示 Then 每个数字都能追溯到**具体字段名**；
  只给一个「质量分」既说不出哪里有洞，也无法行动

### 没有独立核验界面

- Given 基础数据 When 使用者浏览 Then 能看到每条值的来源、溯源自哪个文档的哪一段、分级
- Given 基础数据 When 浏览 Then **没有独立的「核验队列」入口**——
  交叉校验由主对话 Agent 发起并汇总成人可拍板的提议
- Given 一条值 When 需要人确认 Then 走提议与拍板（见 `agent.spec.md`），
  不进入另一个排队界面
- Given 一条值被拍板 When 记录 Then 拍板针对**具体哪一版**；值再变，拍板作废

## 验收标准

- [ ] 断言缺七项中任一项时被拒绝
- [ ] 一条断言的溯源只指一处
- [ ] 谓词来自齐备可用的数据定义，定义不可用时值不入库
- [ ] 限定条件不同的两条断言并存且互不覆盖
- [ ] 限定条件全同而值不同的两条断言并存并标为有争议
- [ ] 界面上并列显示多条值时同时显示限定条件
- [ ] 回退解析读出的值分级不为直引
- [ ] 派生值分级为推导并记录公式版本
- [ ] 直引值可被逐字比对原文验证
- [ ] 分级在界面上可见且直引与推断可区分
- [ ] 交叉校验产出结论但不自动改写数据
- [ ] 互相转载的两份文档在交叉校验中只算一份证据
- [ ] 争议拍板后被否决的值保留并标明
- [ ] 任何候选值进入基础数据都必须经过准入
- [ ] 一次准入的变更集原子应用，失败全回滚
- [ ] 工具产出无法直接写入基础数据
- [ ] 主对话改基础数据需人拍板
- [ ] 未声明字段被准入层过滤并报出
- [ ] 公式在项目中声明，含输入输出的量纲与算例
- [ ] 公式无算例时可被引用但答案标注「公式未验证」
- [ ] 算例未通过的公式被拒绝引用并报出失败算例
- [ ] 同一计算方式两个来源不一致时报冲突并保留两侧输入条件
- [ ] 公式修改后旧版本保留，既有结果不受影响
- [ ] 公式变更后受影响的派生值与答案被标为待重算
- [ ] 计算约定与公式同等对待：版本化、需拍板、可引用
- [ ] 项目里没有声明的计算方式导致计算结果出不来，并说明缺哪条声明
- [ ] 上下文中立的值可固化为断言，上下文相关的值不固化
- [ ] 缓存带输入指纹，指纹不匹配时不使用
- [ ] 缓存不被呈现为已核验事实
- [ ] 清空缓存不产生数据损失
- [ ] 覆盖率分母是主体数，同一谓词多条断言不重复计入
- [ ] 「未知」「空值」不计为已填充
- [ ] 无数据的主体类仍被列出并标注
- [ ] 未声明字段、从未出现的字段、必填无值字段分别列出
- [ ] 覆盖率 100% 不被呈现为「数据正确」
- [ ] 未建模字段不计入已填充
- [ ] 质量视图的每个数字可追溯到具体字段名
- [ ] 每一条值的来源、溯源与分级可查
- [ ] 界面上没有独立的「核验队列」入口
- [ ] 拍板针对具体版本，值变更后拍板作废

## 边界与异常

- 取值类型与定义不符：拒绝，指出字段与期望类型
- 取值量纲与定义不符：拒绝，不做隐式换算（换算只在比对时进行）
- 取值超出 `min`/`max`：拒绝，指出范围
- 一条断言的主体不存在：拒绝并指出
- 两个来源给出同一件事的同一个值：产生一条断言还是两条？——
  **两条都留**（来源不同），交叉校验时它们构成「多源一致」
- 空字符串与空值：区分（空值是明确无值，空字符串是空文本）
- 公式表达式引用不存在的字段：拒绝加载并指出位置
- 公式表达式量纲不可换算：拒绝并指出单位对
- 公式算例期望输出为空：拒绝（算例必须能判定通过与否）
- 派生链成环：拒绝并指出环上的断言
- 缓存被外部清空：允许，重算即可，不影响事实
- 基础数据为空：允许；界面说明「还没有任何数据」并给出取数入口，
  不显示成错误
- 主体数在两次统计之间变化：覆盖率随之变化，但报告必须注明统计时点
- 同一字段有 3000 条限定条件不同的断言：覆盖率仍按主体数算，界面需说明这一点，
  否则 100% 覆盖会给人「很完整」的错觉

## 前后端契约

`BasicDataService`（作用域：项目；读在 Case 作用域内同样可用）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Quality` | `entity` | `QualityView[]` | 逐字段覆盖率、四态计数、缺口分类 |
| `Assertions` | `filter, limit, offset` | `AssertionPage` | 断言库浏览；按实体、谓词、分级、状态筛 |
| `Subject` | `entity, subject` | `Assertion[]` | 一个主体上的全部断言（含限定条件） |
| `Subjects` | `entity` | `string[]` | 该实体下的主体列表 |
| `Disputes` | — | `DisputeView[]` | 有争议的断言分组 |
| `Formulas` | — | `FormulaView[]` | 公式与算例验证状态 |
| `PutFormula` | `FormulaInput, by, reason` | `FormulaView` | 需人拍板 |
| `Conventions` | — | `ConventionView[]` | 计算约定 |
| `PutConvention` | `ConventionInput, by, reason` | `ConventionView` | |
| `Derived` | `filter, limit` | `Assertion[]` | 派生断言及其推导链 |
| `Stale` | — | `StaleView[]` | 因公式或来源变更而待重算／依据已变的值 |
| `Diagnose` | `entity, predicate` | `DiagnoseView` | 某个值算不出来时，说明缺哪条声明或哪个输入 |

`QualityView`（每个字段一条）：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `entity` / `predicate` | string | 否 | 字段标识 |
| `label` | string | 否 | 中文名（挂词条）；无中文名时为空串，界面退回显示标识 |
| `subjects` | int | 否 | 分母：主体数 |
| `filled` | int | 否 | 有值的主体数 |
| `unknown` | int | 否 | 值为「未知」的主体数 |
| `nulls` | int | 否 | 值为「空值」的主体数 |
| `absent` | int | 否 | 无此字段的主体数 |
| `unmodeled` | int | 否 | 未建模的主体数 |
| `coverage` | float | 否 | `filled / subjects`；`subjects` 为 0 时为 0 |
| `required` | bool | 否 | 是否必填 |
| `declared` | bool | 否 | 是否在定义中声明；false 表示未声明字段 |
| `note` | string | 否 | 缺口说明：必填无值 / 从未出现 / 未声明 等 |

`AssertionPage`：`{ items: Assertion[], total: int }`

`Assertion`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | string | 否 | |
| `entity` / `subject` / `predicate` | string | 否 | |
| `label` | string | 否 | 谓词中文名 |
| `subjectLabel` | string | 否 | 主体中文名（来自其 `name` 值） |
| `value` | `ValueView` | 否 | 含四态：有值 / 未知 / 空 / 缺失 |
| `qualifiers` | `QualifierView[]` | 否 | 限定条件；**展示时必须显示** |
| `source` | `SourceView` | 否 | 来源名与层级 |
| `provenance` | `ProvenanceView` | 否 | 文档、修订、段落锚点；可跳转 |
| `confidence` | string | 否 | `L1`–`L4` |
| `confidenceText` | string | 否 | 中文说明 |
| `status` | string | 否 | `ok` / `disputed` / `stale` / `rejected` / `unmodeled` |
| `statusText` | string | 否 | |
| `derived` | `DerivationView \| null` | 是 | 派生链；非派生为 null |

`ValueView`：`{ state: "value" | "unknown" | "null" | "absent", text: string, unit: string }`
——四态必须能分别计数与分别展示，「未知」不得显示成空。

`DisputeView`：`{ entity, predicate, label, subject, claims: Assertion[], note }`

`FormulaView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `name` | string | 否 | |
| `revision` | string | 否 | 版本 |
| `inputs` / `outputs` | `PortView[]` | 否 | 含量纲 |
| `expression` | string | 否 | |
| `cases` | `CaseView[]` | 否 | 算例与通过情况 |
| `status` | string | 否 | `ok` / `no-cases` / `failed` |
| `statusText` | string | 否 | 未通过时报出失败算例 |
| `signedBy` | `ActorView \| null` | 是 | |

`StaleView`：`{ kind, ref, label, why, since }`
——`kind` 为 `recompute`（公式变了）/ `basis-changed`（依据文档变了）/ `rejected-dep`（依赖被否决）。

`DiagnoseView`：`{ ok, message, missing: string[], hints: string[] }`
——算不出来时必须说明缺什么：缺哪条声明、哪个输入、哪条换算关系。

约定：

- 读接口一律返回 `label` 与 `confidenceText`：**界面上不允许只出现标识符**
  （命名与显示规则见 `workspace.spec.md`）
- 任何写接口都**不直接写断言**：写入只经准入产生变更集，
  因此本服务只暴露公式与计算约定的写入口，断言写入口属于准入（见 `admission.spec.md`）
- `Diagnose` 是给「这个数为什么算不出来」用的：缺件必须逐项列出，不能只给一句失败
- `Quality` 必须区分「未声明」「从未出现」「必填无值」三类缺口，不能合并成一个「缺」
