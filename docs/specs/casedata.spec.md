# CaseData：Case 自己的数据表

## 目的

Case 在分析过程中会产生一批只对自己有意义的数据：候选清单、试算表、打分结果、
从工具产出里筛出来的中间集。把它们塞进项目基础数据是错的——它们不是项目的事实，
别的 Case 也用不上；但它们又必须留下来，否则经验就成了「我说我算过」。

因此给 Case 一块自己的地方：**普通数据表**。

它刻意做得很轻：

| | 项目基础数据 | CaseData |
|---|---|---|
| 是什么 | 项目的事实 | Case 的工作数据 |
| 谁能看到 | 项目内全部 Case | **只有这个 Case** |
| 写入要求 | 必须过准入、谓词必须来自齐备的数据定义、要人拍板 | 建表即可写 |
| 要不要使用文档 | 数据定义必须有使用文档，缺了不可用 | **只要一句说明** |
| 依据可追 | 每条值都能追到原文某一段 | 不要求逐条溯源（它本来就是算出来的） |

**这个轻不是偷懒，是刻意的**：如果 CaseData 也要走数据定义那一套仪式，
人就会绕过它，把东西塞回项目级——那才是真正的污染。
但轻也有代价，所以有三条硬规则守着：

1. **它绝不是事实源**：任何答案用到它必须说出来。
2. **它必须有说明**：一张没人解释怎么用的表等于一堆难以理解的数字。
3. **它不该长期承担复用**：一旦别的 Case 也需要，或者它开始有严格定义的需求，
   就说明**它该被提升为项目级**——走 experience 上报。

## 术语

- **表（table）**：一张普通数据表。有名字、一句说明、若干列、若干行。
- **列（column）**：列有名字与类型，类型取自平台的类型原语。
- **行（row）**：一行数据，有稳定标识以便更新与被引用。
- **说明（note）**：一句话讲清这张表存什么、怎么来的、怎么用。**必填。**
- **提升（promote）**：把 CaseData 的内容变成项目级定义与数据。**需要走 experience 上报。**

## 领域规则（Given-When-Then）

### 建模

- Given 一个 Case When 建表 Then 必须给出：表名、**说明**、列定义（列名、类型、可空）
- Given 一张表 When 建表 Then 必须指定**主键列**（一行如何被唯一标识），
  否则行无法被更新或引用
- Given 列的类型 When 声明 Then 取自平台的类型原语（见 `dataschema.spec.md`）；
  数值列可以声明量纲，但**不强制**——它是工作数据，量纲缺失时按原值比较
- Given 一张表 When 建表 Then **不要求**身份字段、不要求使用文档、不要求拍板
- Given 表名 When 与另一个 Case 的表同名 Then 允许——它们互不可见
- Given 说明为空或纯占位 When 建表 Then **拒绝**——没有被解释过的表就是数字垃圾

### 隔离

- Given 一个 Case 的表 When 查询 Then **只有该 Case 能读写**；
  其他 Case 与主对话**只读不可写**（主对话汇总上报时需要看得到）
- Given 一个 Case When 尝试读取另一个 Case 的表 Then **拒绝**并说明原因
- Given 项目级内容 When 导出 Then **不含**任何 CaseData；
  它属于 Case 的工作区，不是项目的可分享内容

### 写入与删除

- Given 一个 Case When 写行 Then 允许；写入记录谁写的、何时写的
- Given 一行 When 主键与既有行相同 Then **更新**该行（upsert），不产生重复行
- Given 一行 When 主键缺失 Then 拒绝该行，其余行照常写入，并逐行报告失败原因
- Given 一批行 When 写入 Then **原子**：任一行失败则整批回滚，
  除非调用方显式要求「跳过坏行」——那时必须逐行报告跳过了什么
- Given 一张表 When 删除 Then 需要理由并记录；
  被经验引用时**提示影响面**（多少条经验会失去依据）
- Given 一张表被经验引用 When 删除 Then 允许，但被引用的经验标为「依据不可达」，
  **不删除经验**（见 `experience.spec.md`）
- Given 从工具产出导入 When 处理 Then 记录该次执行的标识，
  使表里的数据能追到「哪次取数」

### 与经验的关系

- Given 一张表 When 存在 Then 可以没有经验引用它（刚建的表），
  但界面上**标出「还没有经验说明怎么用它」**——这通常意味着它会被遗忘
- Given 一条经验 When 引用一张表 Then 必须写清**这张表怎么用**：
  取哪些列、按什么条件、结果代表什么
- Given 一条经验 When 引用表而未写使用说明 Then 拒绝记录该经验
- Given 一张表 When 打开 Then 能看到**哪些经验引用了它、怎么用的**

### 提升为项目级

- Given 一张表 When 出现下列任一情形 Then 提示「建议提升为项目级」：
  被两个以上 Case 需要、需要有严格定义与使用文档、需要有独立来源与拍板、
  成为下游计算的输入
- Given 一次提升 When 执行 Then 走 experience 上报，
  由主对话汇总后建立项目级数据定义与数据；**Case 不得自己写项目级**
- Given 一次提升 When 完成 Then 原表**保留**并标为「已提升，见某定义」——
  删除会让当时依据它的经验失去依据
- Given 一张表长时间未变且无引用 When 检查 Then 提示可以清理，
  但**不自动删除**（它可能是某个结论的依据）

### 规模与用途边界

- Given 一张表 When 行数或列数超过阈值 Then 提示「这已经不像工作数据了，
  考虑提升为项目级或改用分析查询」
- Given 需要跨表聚合分析 When 处理 Then 用工具做分析查询（见 `tools.spec.md`），
  而**不是**把 CaseData 当数据仓库
- Given CaseData When 被答案引用 Then 答案必须说明它用了这张表——
  它不是事实源，读者需要知道结论建立在工作数据上

## 验收标准

- [ ] 建表必须有表名、说明与主键列
- [ ] 说明为空或纯占位时拒绝建表
- [ ] 列类型取自平台原语
- [ ] 一个 Case 的表对其他 Case 不可读写
- [ ] 主对话可读 CaseData 但不可写
- [ ] 导出项目不含任何 CaseData
- [ ] 写入记录谁写的、何时写的
- [ ] 主键相同则更新而非新增行
- [ ] 主键缺失的行被拒绝并逐行报告，其余行照常写入
- [ ] 批量写入原子；显式要求跳过坏行时逐行报告跳过内容
- [ ] 删除表需要理由并记录
- [ ] 删除被引用的表时提示影响面
- [ ] 表被删除后引用它的经验标为「依据不可达」且不被删除
- [ ] 从工具产出导入的记录能追到那次执行
- [ ] 无经验引用的表被标出「还没有经验说明怎么用它」
- [ ] 引用表的经验必须写清怎么用，否则拒绝记录
- [ ] 表被打开时能看到哪些经验引用了它、怎么用的
- [ ] 满足提升条件时提示建议提升为项目级
- [ ] 提升走 experience 上报，Case 不直接写项目级
- [ ] 提升后原表保留并标注去向
- [ ] 长期未变且无引用的表提示可清理但不自动删除
- [ ] 规模超阈值时提示改用分析查询或提升
- [ ] 用到 CaseData 的答案明确说明这一点

## 边界与异常

- 表名为空或含分隔符：拒绝
- 列名为空或重复：拒绝
- 列数为 0：拒绝（至少一列）
- 主键列声明为可空：拒绝（主键不能空）
- 主键值重复且内容也相同：视为同一行的重复写入，幂等
- 单元格值超出列类型：拒绝该行并报告
- 单元格为空与列为空串：区分（同 `dataschema.spec.md` 的四态）
- 一行有大量列：允许，但界面需要能横向滚动而不是截断
- 表很大：允许，但分页；一次性全量加载在界面上是禁忌
- 导入的文件格式不认识：整体拒绝，不猜测、不部分导入
- 导入过程中途失败：整批回滚，不留半张表
- 并发写同一张表：允许；主键冲突时后写覆盖先写，并都留在写入记录里
- 表被提升为项目级后又在 Case 里继续写：允许，但界面提示「此表已提升，
  新写入不会进入项目级」——避免人以为改了这边项目级就变了
- Case 被禁用：表仍可读，不可写

## 前后端契约

`CaseDataService`（作用域：Case）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Tables` | — | `TableView[]` | 本 Case 的全部表及引用情况 |
| `Get` | `name` | `TableView` | 含列定义、行数、说明 |
| `Put` | `TableInput, by` | `TableView` | 建表或改列；**不需要拍板** |
| `Drop` | `name, by, reason` | `ImpactView` | 删除并返回影响面 |
| `Rows` | `name, filter, limit, offset` | `RowPage` | |
| `Upsert` | `name, rows, by, skipBad` | `RowResult` | 主键相同即更新 |
| `DeleteRows` | `name, keys, by` | `int` | |
| `Import` | `name, runId, by` | `RowResult` | 从某次工具执行的产出导入 |
| `Usage` | `name` | `UsageView[]` | 哪些经验引用了它、怎么用的 |
| `Promote` | `name, note, by, reason` | `PromoteView` | 生成一条上报（写进 experience） |

`TableView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `name` | string | 否 | |
| `title` | string | 否 | 中文名；无则界面显示 name |
| `note` | string | 否 | **说明：存什么、怎么来的、怎么用**。必填 |
| `columns` | `ColumnView[]` | 否 | |
| `key` | string[] | 否 | 主键列；至少一列 |
| `rows` | int | 否 | 行数 |
| `updatedAt` | string | 否 | RFC3339 |
| `usage` | int | 否 | 被多少条经验引用 |
| `promotedTo` | string | 否 | 已提升到的项目级定义标识；空串表示未提升 |
| `warnings` | string[] | 否 | 「无经验引用」「规模偏大」「已提升仍在写」等 |

`ColumnView`：`{ key, name, type, unit, nullable, note }`
——`name` 为中文名；没有时为空串，界面退回显示 `key`。

`RowPage`：`{ items: Record<string,string>[], total: int, columns: string[] }`

`RowResult`：`{ upserted: int, failed: int, errors: RowError[] }`，
`RowError`：`{ key, column, reason }`

`UsageView`：`{ experienceId, title, how }`
——`how` 是那条经验里写的「这张表怎么用」。

约定：

- `Put` **不需要拍板**，这是刻意的：Case 作用域内的东西改错了代价小，
  要拍板的是它进入项目级的那一刻
- `Drop` 必须返回影响面，且影响面非空时**必须在界面上说清**有哪些经验会失去依据
- `Rows` 一律分页；没有不分页的接口
- `Upsert` 的 `skipBad` 默认 false：默认原子，要求跳过坏行必须显式说明
- `Promote` **只生成上报**，不写项目级——这是 Case 唯一能表达「该提升了」的方式

## 待确认

1. 行数与列数的提示阈值
2. 是否需要保留单元格级的修改历史（当前只记录整批写入）
3. 表结构变更（加列/改类型）是否需要单独流程，还是直接改并标注
4. CaseData 是否需要导出为文件（便于人用别的工具分析）
5. 「已提升」的表是否禁止继续写入（当前允许但提示）
