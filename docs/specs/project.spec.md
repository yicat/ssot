# 项目：一个领域的封装单位

## 目的

定义**一个领域**在平台里的封装单位，以及它与其他项目之间的边界。

**项目 = 一个领域**（一个游戏、一套设定）。不同游戏 = 不同项目。
项目之内再分 **Case**——同一领域的不同用途，见 `case.spec.md`。

项目由**六个部件**组成（见 `architecture.spec.md`）：主对话 Agent、工具、文档、词表、
DataSchema、项目基础数据。这六件是**项目级的**——它们不随 Case 变化，被项目内所有 Case 共享。

上一版把项目描述为「定义 + 实例」两半：schema/公式/数据源是人写的，断言库是运行出来的。
那个切法在新结构里不够用：文档可能来自下载、也可能是 Agent 的整理；基础数据可能来自抽取、
也可能是推导。因此本版改用两个更硬的切法：

| 切法 | 是什么 | 为什么要分 |
|---|---|---|
| **项目级 / Case 级** | 六部件属项目；experience 与 CaseData 属 Case | 它决定**谁能写什么**（见 `architecture.spec.md`） |
| **来源 / 生成** | 内容是从外面取回来的，还是在这里算出来或写出来的 | 它决定**依据能否追到底**——生成的内容必须指出它依据了什么 |

## 术语

- **项目（project）**：一个领域的封装单位，落在平台的一个位置里，可被独立加载、复制、分享。
- **部件（part）**：项目下的六件东西之一。部件是**逻辑划分**，不代表六个目录。
- **Case**：项目下的一个用途，每个 Case 是一个子 Agent。见 `case.spec.md`。
- **项目清单（manifest）**：项目元信息：名称、版本、所要求的平台与元模型版本。
- **来源（source）**：项目内容的外部出处（站点、接口、文件、人的输入）。
- **生成（derived）**：由 Agent 整理、由公式算出、或由推导得出的内容。

## 领域规则（Given-When-Then）

### 项目由什么构成

- Given 一个项目 When 建立 Then 它包含六个部件：主对话 Agent、工具、文档、词表、
  DataSchema、项目基础数据
- Given 一个项目 When 建立 Then 可以包含**任意多个 Case**，也可以一个都没有
- Given 一个部件 When 内容为空 Then 允许——项目刚建立时六件都是空的；
  界面必须说清「空」与「加载失败」的区别
- Given 项目内容 When 标记来源 Then 必须区分**来源**与**生成**；
  生成的内容必须指出它依据了哪些来源或哪些既有内容
- Given 一份内容 When 归类到部件 Then 只能落一处（判据见 `architecture.spec.md`）

### 项目在磁盘上的样子（示意）

六部件是逻辑划分，不是六个目录。下面只是说明「项目是一个目录、可被复制与分享」这件事：

```
<项目目录>/                    例：阴阳师
├─ project.yml            项目清单：名称、版本、所要求的平台与元模型版本
├─ tools/                 工具：一组脚本，各自声明输入与输出
├─ docs/                  文档：导入的原文、下载的存档、Agent 的整理
├─ dict/                  词表：词条、同义与多义关系、条件指代规则
├─ schemas/               数据定义：每个定义带自己的使用文档
├─ formulas/              计算方式：公式即数据，不在代码里
├─ cases/                 Case：一个用途一个目录（内含 experience 与 CaseData）
└─ .data/                 项目实例数据（不进版本控制，可由来源重建）
```

### 隔离

- Given 两个项目并存 When 查询 Then 只返回当前项目的内容，**不得跨项目读取**
- Given 两个项目定义了同名但内容不同的 DataSchema When 并存 Then 允许，互不影响
- Given 一个项目的实例数据 When 另一个项目运行 Then 不可见、不可引用
- Given 一个 Case When 运行 Then 只能看到**本 Case** 的 experience 与 CaseData，
  看不到项目内其他 Case 的
- Given 一个项目被删除 When 处理 Then 另一个项目不受影响
- Given 两个项目共用同一实例数据位置 When 出现 Then **拒绝**——隔离已被破坏

### 加载与版本

- Given 一个项目 When 加载 Then 必须读取项目清单并校验所要求的平台与元模型版本
- Given 项目清单缺失或版本声明缺失 When 加载 Then **拒绝**
- Given 项目声明的版本**高于**当前平台支持 When 加载 Then 拒绝并列出所需版本
- Given 项目声明的版本**低于**当前支持 When 加载 Then 允许，但标注为旧版并提示可升级
- Given 项目内容中存在失效引用（引用了不存在的定义、词条、文档、工具）When 加载 Then
  报告**全部**失效引用，不得只报第一个
- Given 一个部件加载失败 When 处理 Then 其余部件仍可读，
  且失败的那个必须显式标出——不得让整个项目变成打不开
- Given 项目加载失败 When 处理 Then 保持原项目上下文不变，返回失败原因，不进入半加载状态

### 重建与备份

- Given 项目实例数据 When 丢失 Then 可由**来源 + 六部件中的声明性内容**重建
  （原件存档仍在、准入可重放）
- Given 项目声明性内容未变 When 重建实例 Then 在来源未变的前提下结果应与原实例一致
- Given 实例数据需要备份 When 处理 Then 可与项目声明性内容分开备份
- Given 项目内容含凭据 When 导出 Then **不得包含**

### 分享与分发

- Given 一个项目 When 导出 Then 产出可被他人加载的包：六部件中的**声明性内容**、
  工具、词表、DataSchema、基础数据与文档，**不含**凭据与实例缓存
- Given 导出包里含 Agent 的会话记录 When 导出 Then **默认不含**；
  会话是工作记录不是事实源，需要时显式选择
- Given 接收一份导出包 When 加载 Then 必须能自行取数并运行——**不需要提供方的数据**
- Given 两个项目需要同一份 DataSchema When 评估 Then **倾向复制而非引用**，
  避免隐式耦合（一个项目的变更悄悄影响另一个）
- Given 项目内容引用另一个项目的东西 When 出现 Then 视为**复制**，不建立运行时依赖

### 演进

- Given 项目内容发生变更 When 应用 Then 走 `dataschema.spec.md` 的演进流程：
  影响清单 → 显式确认 → 原子应用
- Given 项目级内容发生变更 When 完成 Then 必须能回答：谁改的、何时改的、凭什么改、改前是什么
- Given 项目级内容发生变更 When 完成 Then 报告影响面：
  有多少 Case 产物引用了它，将被标为「依据已变」
- Given 项目升级需要平台表达不了的东西 When 评估 Then **不得**为此临时扩展平台通用能力，
  应记录需求并走平台发布流程；项目内可先用「未建模」的方式原样保留，不丢信息

## 验收标准

- [ ] 项目由六个部件构成，缺件时被标注为不完整而不是加载失败
- [ ] 平台可同时存在多个项目，且一个项目的行为不影响另一个
- [ ] 两个项目并存时查询不跨项目
- [ ] 同名不同定义的 DataSchema 在并存时不冲突
- [ ] 一个项目的实例数据对另一个项目不可见
- [ ] 一个项目的 Case 看不到同项目内其他 Case 的 experience 与 CaseData
- [ ] 删除一个项目不影响另一个
- [ ] 两个项目共用实例数据位置时被拒绝
- [ ] 加载项目时校验清单与版本声明，缺失即拒绝
- [ ] 声明的版本高于平台时拒绝并列出所需版本
- [ ] 失效引用被全部列出，不只报第一个
- [ ] 单个部件加载失败时其余部件仍可读，失败的那个显式标出
- [ ] 项目内容区分「来源」与「生成」，生成的内容指出其依据
- [ ] 实例数据可由来源加声明性内容重建
- [ ] 导出不含凭据、不含实例缓存、默认不含会话记录
- [ ] 接收导出包后无需提供方数据即可取数运行
- [ ] 项目级变更走演进流程，且报告影响面
- [ ] 项目级变更能回答「谁、何时、凭什么、改前是什么」
- [ ] 平台通用能力不因单一项目的需要而被临时扩展

## 边界与异常

- 项目名为空或与既有项目重复：拒绝
- 项目缺少某个部件（如没有工具）：允许加载，标注为不完整，并说明缺它会导致什么不可用
- 项目一个 Case 都没有：允许，界面说明这不是错误，并给出建立 Case 的入口
- 部件文件为空：允许（刚建立的项目就是空的），但界面必须说明「空」的含义
- 项目内容引用了另一个项目的东西：按复制处理，导出时**自包含**
- 项目升级中途失败：项目内容与实例均回滚到演进前
- 项目内容被外部直接修改：允许，但下次加载时必须重新校验一致性并报告差异
- 项目声明的元模型版本低于当前：允许但标注旧版，且提示可升级
- Agent 不可用（无网络、无凭据、无额度）：项目仍**可读**；只有依赖 Agent 的动作不可用
- 平台没有任何项目：给出明确提示与建立路径，不指向不存在的位置

## 前后端契约

`PlatformService`（作用域：平台）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Projects` | — | `ProjectRef[]` | 平台上全部项目及其加载状态 |
| `Create` | `name, description` | `ProjectRef` | 建立项目（六个空部件） |
| `Remove` | `dir` | — | 移除项目；不影响其他项目 |
| `Open` | `dir` | `Session` | 加载项目；失败时原上下文不变 |
| `Current` | — | `Session \| null` | 当前项目与其 Case 列表 |
| `Overview` | — | `ProjectOverview` | 六部件各自的规模与就绪情况 |

`ProjectRef`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `dir` | string | 否 | 项目标识（也是它的位置） |
| `name` | string | 否 | 展示名 |
| `description` | string | 否 | |
| `version` | string | 否 | 项目自己的版本 |
| `status` | string | 否 | `ok` / `incomplete` / `outdated` / `failed` |
| `statusText` | string | 否 | 中文说明，含缺哪个部件或失败原因 |
| `current` | bool | 否 | 是否为当前打开的项目 |

`ProjectOverview` 必须逐部件给出：**规模**（有多少条内容）、**就绪情况**
（可用 / 空 / 不完整 / 失败）、以及**缺它会导致什么**。四项缺一不可——
只给一个总数，人就无法判断该项目能不能用。

`Session`（= 当前项目 + 当前 Case）：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `dir` / `name` / `description` | string | 否 | 项目标识与展示信息 |
| `parts` | `PartStatus[]` | 否 | 六部件的就绪情况 |
| `cases` | `CaseRef[]` | 否 | 项目内的 Case；可为空数组 |
| `case` | string | **是** | 当前 Case 名；null 表示未选中或项目没有 Case |
| `warnings` | string[] | 否 | 旧版标注、失效引用、不可达依据等 |

约定：

- 项目切换必须显式，切换后所有查询的作用域随之改变
- 导出与导入必须是可脚本化的操作
- 加载报告中的 `warnings` **不得为空即静默**：有失效引用必须在界面上可见

## 待确认

1. 平台同时加载的项目数量是否有上限
2. 项目之间是否允许显式的只读引用（当前设计为**只允许复制**）
3. 导出包的格式，以及是否包含各部件的历史版本
4. 一个项目能否包含多个「数据集」（当前假设一个项目一套数据）
5. 项目清单的字段全集
