# 项目：领域的封装单位

## 目的

定义**一个领域**在工具里的封装单位。

**项目 = 一个领域**（一个游戏、一套数据）。不同游戏 = 不同项目。
项目之内再分**场景**——同一领域的不同用途（斗技阵容分析、每日任务、每月攒资源…），
见 `scenario.spec.md`。

机制由引擎提供、全局统一；内容由项目提供、各自不同：

| | 归属 | 内容 |
|---|---|---|
| **机制** | 引擎 | 断言模型、准入、核验、迁移、计算求值、投影 |
| **内容** | 项目 | schema、校验规则、计算公式、视角、数据源与解析器、单位换算表 |

工具因此是「**一个引擎 + N 个项目**」。项目之间互不影响，可以被复制、分享、独立演进。

## 术语

- **项目（project）**：一个场景的封装单位，落在一个目录里。
- **定义（definition）**：项目里由人编写、可读可版本化的部分——schema、公式、视角、数据源配置、单位表。
- **实例（instance）**：项目运行后产生的部分——原件存档、断言库、核验记录、个人档案、方案。
- **项目清单（manifest）**：项目的元信息：名称、版本、所要求的引擎与元模型版本。

## 一、项目的构成

```
<项目目录>/                    例：阴阳师
├─ project.yml            项目清单
├─ schema/                领域模型：式神、技能、御魂、活动…
├─ formulas/              项目级公共公式（伤害、速度、面板）
├─ sources/               数据源与解析器配置
├─ units.yml              单位与换算表
├─ scenarios/             场景：一个用途一个目录
│  ├─ pvp-team/           斗技阵容分析
│  │  ├─ scenario.yml     requires / inputs / preferences / outputs
│  │  ├─ formulas/        场景私有公式
│  │  └─ views/           该场景的视角
│  ├─ daily-tasks/
│  ├─ monthly-savings/
│  └─ event-prep/
└─ .data/                 实例数据（不进版本控制）
   ├─ artifacts/          原件存档
   ├─ store              断言库
   └─ profiles/          个人档案与方案
```

### 三层：引擎 / 项目 / 场景

| 层 | 是什么 | 边界性质 |
|---|---|---|
| **引擎** | 机制：断言、准入、核验、迁移、计算、投影 | 全局统一 |
| **项目** | 一个领域：schema、数据源、单位表、公共公式 | **隔离边界**——项目间数据互不可见 |
| **场景** | 一个用途：斗技阵容分析、每日任务、每月攒资源… | **用途边界**——同项目内断言共享 |

**场景不是隔离边界**，它只组织「读什么、算什么、产出什么」。
详见 `scenario.spec.md`。

### 定义与实例必须分开

| | 定义 | 实例 |
|---|---|---|
| 由谁产生 | 人编写 | 运行产生 |
| 是否进版本控制 | ✅ | ❌ |
| 是否可分享 | ✅ **这是项目的可分享部分** | 视情况 |
| 大小 | 小 | 可能很大 |
| 含凭据 | ❌ | 可能（数据源凭据） |

这条分界带来三个直接好处：

1. **分享项目 = 分享定义**。接收方拿到 schema 与公式，**同步自己的数据**——不必接受别人的数据。
2. **数据可以整体丢弃重建**：只要定义与数据源在，实例数据是可再生的（原件存档 + 准入可重放）。
3. **个人档案天然属于实例**，不会被误分享出去。

## 二、隔离与并存

- 项目之间数据**完全隔离**：一个项目的断言、档案、方案不得被另一个项目读到
- 多个项目**可以在同一工具内并存**，各自独立加载与演进
- 不同项目可以使用**同名但定义不同**的 schema——这不算冲突
- 元模型**全局统一**，不随项目变化（引擎稳定性的保证）

### 项目被元模型卡住时的出路

若某个项目需要引擎表达不了的东西：

1. **`opaque` 逃生舱**——先原样记录，后建模（不丢信息）
2. **在 schema 层定义复合类型**——用现有原语的组合命名一个新类型（schema 能力，非元模型扩展）
3. 若两者都不够，那是**引擎需要升级**的信号，走工具的发布流程

**不得**因为一个项目的需要而给元模型加临时原语——那会破坏所有项目的稳定性。

## 三、版本与兼容

项目清单必须声明：

- 所要求的**引擎版本**
- 所要求的**元模型版本**（原语集合的版本）

- Given 项目声明的版本**高于**当前引擎支持 When 加载 Then **拒绝**并明确报告
- Given 项目声明的版本**低于**当前支持 When 加载 Then 允许，但标注为旧版
- Given 项目定义发生变更 When 应用 Then 走 `migration.spec.md` 的流程（影响清单 → 确认 → 原子应用）

## 四、分享与分发

- Given 一个项目 When 导出定义 Then 产出可被他人加载的定义包（不含实例数据与凭据）
- Given 接收一份定义包 When 加载 Then 必须能同步数据并运行——**不需要提供方的数据**
- Given 两个项目需要同一份 schema When 评估 Then **倾向复制而非引用**，
  避免隐式耦合（一个项目的变更悄悄影响另一个）
- Given 项目定义引用另一个项目的内容 When 出现 Then 视为**复制**，不建立运行时依赖

## 领域规则（Given-When-Then）

### 加载

- Given 一个项目目录 When 加载 Then 必须读取项目清单并校验引擎与元模型版本
- Given 项目清单缺失或版本声明缺失 When 加载 Then **拒绝**
- Given 项目声明的引擎版本高于当前 When 加载 Then 拒绝并列出所需版本
- Given 项目定义中引用了不存在的字段、公式或视角 When 加载 Then 报告全部失效引用，
  不得只报第一个
- Given 定义部分存在语法错误 When 加载 Then 拒绝并指出位置

### 隔离

- Given 两个项目并存 When 查询 Then 只返回当前项目的断言，**不得跨项目读取**
- Given 两个项目定义了同名 schema 但内容不同 When 并存 Then 允许，互不影响
- Given 一个项目的实例数据 When 另一个项目运行 Then 不可见、不可引用
- Given 一个项目被删除 When 处理 Then 另一个项目不受影响

### 实例数据

- Given 项目实例数据 When 丢失 Then 必须可由**定义 + 数据源**重建（原件存档 + 准入可重放）
- Given 项目定义未变 When 重建实例 Then 结果应与原实例一致（在数据源未变的前提下）
- Given 实例数据需要备份 When 处理 Then 可与定义分开备份
- Given 实例数据中含凭据 When 导出定义 Then **不得包含**

### 个人档案

- Given 个人档案引用的状态字段 When 定义来自项目 schema Then 档案归属于该项目
- Given 一个项目被移除 When 处理 Then 其个人档案一并处理，不得泄漏到其他项目

### 演进

- Given 项目定义变更 When 应用 Then 走迁移流程：影响清单 → 显式确认 → 原子应用
- Given 项目升级需要新增元模型原语 When 评估 Then **不得**就地扩展元模型，
  应记录需求并走引擎发布流程

## 验收标准

- [ ] 加载项目时校验清单与版本声明
- [ ] 清单缺失或版本声明缺失时拒绝加载
- [ ] 声明的引擎版本高于当前时拒绝并列出所需版本
- [ ] 失效引用被全部列出，不只报第一个
- [ ] 两个项目并存时查询不跨项目
- [ ] 同名不同定义的 schema 在并存时不冲突
- [ ] 一个项目的实例数据对另一个项目不可见
- [ ] 删除一个项目不影响另一个
- [ ] 实例数据可由定义加数据源重建
- [ ] 数据源未变时，重建结果与原实例一致
- [ ] 导出定义不含实例数据与凭据
- [ ] 接收定义包后无需提供方数据即可运行
- [ ] 个人档案归属项目，不跨项目泄漏
- [ ] 项目定义变更走迁移流程
- [ ] 元模型不因单一项目的需要而被就地扩展

## 边界与异常

- 项目名为空或与既有项目重复：拒绝
- 项目目录缺少必需部分（如无 `schema/`）：允许加载但标注为不完整，且不得产出方案
- 定义文件为空：拒绝
- `units.yml` 换算关系成环：拒绝加载（见 `computation.spec.md`）
- 项目定义引用了另一个项目的内容：按复制处理，并在导出时**自包含**
- 两个项目共用同一实例数据目录：**拒绝**（隔离被破坏）
- 项目升级中途失败：定义与实例均回滚到迁移前
- 项目声明的元模型版本低于当前：允许但标注旧版，且提示可升级
- 实例数据被外部工具修改：允许，但下次加载时必须重新校验一致性

## 前后端契约

**待定**，取决于对外接口形态。已确定的约束：

- 项目列表、各项目的加载状态与版本必须可被外部查询
- 项目切换必须显式，且切换后所有查询的作用域随之改变
- 导出定义与导入定义必须是可脚本化的操作

## 待确认

1. 工具同时加载的项目数量是否有上限
2. 项目之间是否允许显式的只读引用（当前设计为**只允许复制**）
3. 实例数据是否需要加密（含个人档案时）
4. 项目清单的字段全集
5. 导出定义包的格式与是否包含 schema 的版本历史
6. 一个项目能否包含多个「数据集」（当前假设一个项目一套数据）
