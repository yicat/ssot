# document.spec.md —— 界面：以文档为主 + 文档语法

主题：**主区长什么样、文档怎么写、标记与数据怎么融进文档里**。

配套：`vault.spec.md`（vault 内部结构）、`shell.spec.md`（窗口外壳）、`typography.spec.md`（字体字号）。

一句话：**界面按 Obsidian / Notable 那种「文档即界面」来做**——不是「表格 + 弹窗」的工具壳，
文档是主产物，状态、双链、数据表都长在文档里。

## 一、布局与层级

```
┌ 标题栏（应用名 | 当前项目 | 项目按钮 | 可拖 | 窗口按钮）        ← shell.spec.md
├ 工具条（vault 路径 | 检索（弹窗）| 刷新）
├──────────────┬────────────────────────────┬──────────────┐
│ 文件树        │ 文档 / 数据表（主体）          │ 侧栏（可选）  │
│ docs/        │  ├ 标题 + 状态/标签 chips    │  反链         │
│  └ 式神/      │  ├ 正文（markdown 渲染）     │  大纲         │
│     └ 茨木.md │  └ 数据表（内联渲染）        │  问题链接     │
│ raw/         │                             │              │
└──────────────┴────────────────────────────┴──────────────┘
```

**层级最多三层**，与目录结构一致：

| 层 | 是什么 | 例子 |
|---|---|---|
| 1 | 两层根：`docs/`（整理层）/ `raw/`（原始层） | `docs/` |
| 2 | 分类文件夹 | `docs/式神/` |
| 3 | 文档 | `docs/式神/茨木童子.md` |

- **不允许更深**：三级已经够表达「领域 → 分类 → 条目」；再深说明分类该重划。
  落地时超三层的文档仍会显示，但**文件树里会有提示**（见「怎么验证」）。
- **检索是弹窗**（命令面板式），不是在左栏里挤一块：检索是临时动作，看完就关；
  `/` 或 `Ctrl+K` 打开、`Esc` 关闭、回车在结果里打开第一篇。
- **数据表在左栏点得开**：点开后在主体区按行列展示（不弹窗、不新开页）。
- 左栏顶部的两层用**中文分组标题**（`整理层` / `原始层`），样式与 `数据表` 那组一致——
  目录名 `docs` / `raw` 是**结构**，不是给人看的标签；文件夹层仍显示真实目录名（`式神`）。
- **状态标记（未核验/已发布）放行尾**，不放在标题前面：标题是这一行要认的东西，
  标记只是附注，不该先看到。
- 侧栏（第三栏）可折叠；窗口窄时优先让位给正文——**文档永远是主角**。

## 二、文件树规则（不许乱）

1. **排序确定**：同一层里 **文件夹在前、文档在后**；各自按名称排序（用标题而不是文件名排，
   文件名只是为了寻址）。顺序永远一样——「上次那篇在第三条」得说得清。
2. **每篇文档一个名字**：文件名 = 文档标题的 slug（中文可原样用中文名）。
   `title` 与文件名不一致时**以 front matter 为准**，但文件树会显示两者不一致的提示。
3. **不在文件树里显示的东西**：`.data/`（派生索引）、`tables/` 之外的辅助文件、
   隐藏文件。派生数据不该出现在人的导航里。
4. **tag 是第二套导航**：文件夹负责「放在哪」，tag 负责「属于什么」。
   两者都要能点——点 tag 就是检索。
5. **未核验可见**：树里 `draft` 的文档要有标记（与正文里的状态一致）。

## 三、文档语法（对齐 Obsidian）

底座：**CommonMark + GFM + LaTeX**（这是 Obsidian 自己的口径），以下是**我们要支持的子集**：

| 语法 | 含义 | 我们怎么处理 |
|---|---|---|
| `[[文档]]` / `[[文档\|别名]]` | 内部链接 | 渲染成可点链接；**内嵌显示目标状态**；指不清/断链用醒目样式，点它报错 |
| `[[文档#标题]]` | 标题锚点 | 同上，点开跳到该标题 |
| `[[文档#^块]]` | 块引用 | **主张级溯源**，点开跳到该块（行号来自文件） |
| `^块id` | 定义块 | 渲染成锚点小标记（可点复制/跳转） |
| `![[文档]]` / `![[表.csv]]` | 嵌入 | **数据表：渲染成真表格**（见第四节）；文档：渲染成卡片（标题 + 状态 + 路径），**展开正文摘录还没做**（见未定） |
| `[^1]` | 脚注 | 渲染成上标 + 文末列表 |
| `%%注释%%` | 注释 | **默认隐藏**，悬停/开启「显示注释」时显示（注释是给自己看的） |
| `~~删除线~~` | 删除线 | 原样渲染 |
| `==高亮==` | 高亮 | 原样渲染 |
| `**粗**` `*斜*` `` `代码` `` | 基础 | 原样渲染 |
| ```` ```lang ```` | 代码块 | 语法高亮留到后面；先等宽渲染 |
| `- [ ]` / `- [x]` | 任务列表 | 渲染成勾选框，**点一下写回文件**（界面上点的是人，按 human 记账） |
| `> [!note]` 等 | Callout | 渲染成带颜色的块；类型至少支持 note / tip / warning / danger / quote |
| `$公式$` / `$$公式$$` | LaTeX 公式 | **KaTeX** 渲染（Obsidian 用 MathJax；KaTeX 更轻，够用） |
| 表格 | GFM 表格 | 渲染成表格，支持对齐；**表格里的 `[[链接]]` 也要能点** |

**明确不做**（说清楚免得以后当成 bug）：

- 不做所见即所得编辑器：**阅读视图优先**；编辑走「打开外部编辑器 / 以后再说」。
- 不渲染 HTML 里的 markdown（Obsidian 也是故意的）。
- 不做 Canvas / 图谱视图 / 插件体系。
- 不做 Mermaid（以后要加再说）。

## 四、标记与数据融进文档

**标记融合**（用户要求：「标记融合在文档里面」）：

- 状态与标签是**文档顶部的一行 chips**（在文档流里，不是外挂面板）：`[未核验] #式神 #SSR`。
  **标签要比标题轻**：小一号、灰色、不加底色块，别抢标题的视觉重心。
- `未核验` 的文档，正文第一行就是一条**行内提示**（不是浮层）：
  「这篇还没核验」。它随文档滚动，不遮挡内容。
- 双链**内联显示目标状态**（草稿/已发布用颜色区分），让人一眼看出引的是不是未核验的东西。
- 切状态（未核验/已发布/已归档）就在 chips 那一行，点一下切——不弹窗。

**数据融合**（用户要求：「数据相关也能融合进来」）：

- `![[tables/技能倍率.csv]]` 在文档里渲染成真表格（走派生索引查询，不是读文件拼字符串）。
- 文档里的 GFM 表格原样渲染。
- 表旁边/表下方可以带一句「查询这个表的例子」（来自 `tables/README.md` 的字段说明）——
  让人知道这张表能怎么查。

## 五、UI 一致性

- 字号只用两档（`typography.spec.md`）：正文 14/22、次要 12/18；标题用 scale 放大，不新造档位。
- 颜色只用主题 token（`--card` / `--border` / `--muted-foreground` 等），**不硬编码十六进制**。
  状态色是唯一例外（未核验=琥珀、已发布=绿、已归档=灰），也要集中定义在一处。
- 交互一致：**能点的东西看起来都能点**（链接色、hover 有反馈、光标是手型）；
  状态切换、检索、跳转都在原地完成，不弹窗、不切页。
- 键盘：`/` 聚焦检索框、`Esc` 清检索（已实现）；`↑/↓` 在文件树里移动、`Enter` 打开**还没做**（见未定）。

## 未定

1. 语法高亮（代码块）用哪个库、要不要。
2. Mermaid、Canvas、图谱视图要不要。
3. 任务列表勾选写回文件：算「人改」还是「agent 改」——现在是人在界面上点，算人改，但要留痕口径。
4. 编辑：要不要内置编辑器（现在是阅读优先）；「打开外部编辑器」要不要做。
5. 文档内的 `![[文档]]` 现在只渲染成卡片（标题 + 状态 + 路径）；要展开正文摘录就得先把正文也取到前端——取多少、什么时候取，没定。
6. 文件树里的键盘移动（`↑/↓` + `Enter`）。

## 怎么验证

- `node scripts/check/ui-test.mjs`：断言渲染结果（标题成 `<h2>`、表格成 `<table>`、
  公式有 KaTeX 标记、`[[链接]]` 可点、`%%注释%%` 默认不出现）。
- 文件树：同层文件夹在前、排序确定；超三层的文档有提示。
- 数据融合：文档里 `![[tables/…]]` 渲染出的行数与索引里一致。
