# 文档：不能变成数据的那部分事实源

## 目的

系统此前只接得住一类内容：**能被拆成 (主体, 谓词, 取值) 的东西**。
但项目里大量 source-of-truth 是不可拆的原文：

| | 例子 | 能不能拆 |
|---|---|---|
| 结构化事实 | 技能描述里的「造成攻击80%伤害」 | 能，已经在断言库里 |
| **拆了就失真** | 「防御减免没有权威来源」 | 「能」，但那会把判断伪造成字段 |
| **根本不可拆** | 机制说明、推导理由、版本叙事 | 不能 |

第二类是关键。把「防御减免没有权威来源」写成 `def_reduction.source_kind = none`，
那个字段的含义完全依赖读的人知道上下文——**这是把不可结构化的东西强行结构化**，
与「在前提找不到的情况下自己瞎猜」是同一个错误。

而它**是影响输出的**：`damage-calc` 的方案会标注「外部输入未核验」，依据就是它。
可它现在只写在 YAML 注释和调研笔记里——不进 SSOT，没有溯源、没有核验状态、没有时效。

本层给这类内容一个**一等公民**：文档。它与断言并列，**不参与计算，只作为依据**。

## 术语

- **文档（document）**：一份不可拆的原文，加上它的身份、适用范围与核验状态。
- **修订（revision）**：源内容的一个版本。文档的身份跨修订稳定，修订是它的历史。
- **依据（evidence）**：文档在系统里的角色。它支撑断言，但不被断言替代。
- **镜像文档**：内容就是归档原件的文档（如 wiki 的 `Data:Character/262.json`）。
  正文留在归档里，文档只记身份、修订与**内容摘要**。
- **自撰文档**：人写进系统的文档（机制说明、依据声明）。正文必须存在文档里。
- **适用范围**：这份文档在哪些版本 / 哪些场景下成立。

## 领域规则（Given-When-Then）

### 归属与身份

- Given 一份文档 When 记录 Then 它归属**项目**（源是项目级的：一份 wiki 原文
  会被多个场景引用）
- Given 一份文档 When 记录 Then 可以标注**适用场景**；标注表示「这份只在那些场景下成立」，
  不标注表示全项目适用
- Given 同一来源同一标题 When 换了修订 Then 文档**身份不变**，
  新修订成为当前版本，旧修订**保留为历史**
- Given 一份文档 When 记录 Then 必须携带：来源、标题、修订标识、采集时间、类型

### 只追加，不可删改

- Given 一份文档 When 登记 Then 它**不可修改正文**
- Given 一份文档需要更正 When 操作 Then 只能**登记新修订**，旧修订保留
- Given 旧修订 When 被新修订取代 Then 它仍在历史里可查，
  且**当时引用它的断言仍指向它**——不能悄悄改写成指向新修订

### 变更传导

- Given 一份文档的当前修订发生变化 When 系统检测到 Then
  **引用该文档的断言全部回到「待核验」**
- Given 修订标识没变但内容变了 When 系统检测到（内容摘要不符） Then
  按同一规则处理——**修订标识可信，但不能只信它**
- Given 断言回到待核验 When 显示 Then 必须说明原因是「所依据的文档变了」，
  不得让它看起来像一条新接入的数据
- Given 一条断言已经被驳回 When 其文档变更 Then **保持已驳回**，
  不因文档变化而复活

### 锚点必须落在存在的文档上

- Given 一条断言或经验 When 记录锚点 Then 锚点必须指向一份**已登记**的文档
- Given 一条依据未登记的断言 When 统计 Then 必须报出来——
  「溯源的终点是一个字符串」正是本层要消灭的状态
- Given 接入新原件 When 登记文档 Then 摘要是内容本身算出来的，
  不是来源声明的——**来源可以撒谎或出错，摘要不会**

### 核验

- Given 一份文档 When 核验 Then 核验人必须是**人**，且理由必填
- Given 一份文档 When 核验 Then 方法只能是**编审**——
  一个人读过并背书，不构成多源
- Given 多份**独立**文档就同一件事一致 When 核验 Then 方法可记为多源，
  但必须给出独立性判定结果；互相转载的两份文档**只算一份证据**
- Given 一份镜像文档 When 核验 Then 核验的是「这份原文可信」，
  **不是**「原文里的事实已被验证」——两者必须分开

### 不拆

- Given 一段原文 When 无法抽出 (主体, 谓词, 取值) Then **就让它留在文档里**，
  不得为了「变成数据」而强行拆
- Given 从文档抽出了断言 When 记录 Then 抽取结果是文档的**索引**，不是它的替代——
  文档仍然在，仍然作为依据
- Given 一份文档支撑多条断言 When 查询 Then 是**多对多**：
  一份文档可支撑多条断言，一条断言也可由多份文档佐证

## 验收标准

- [ ] 文档归属项目，并可标注适用场景
- [ ] 同一来源同一标题换修订时身份不变，旧修订保留为历史
- [ ] 文档正文不可修改，只能登记新修订
- [ ] 旧修订被取代后仍可查，且引用它的断言仍指向它
- [ ] 文档当前修订变化时，引用它的断言全部回到待核验
- [ ] 修订标识未变但内容变了（摘要不符）时按同一规则处理
- [ ] 因文档变更而回退的断言，其状态能说明原因
- [ ] 已驳回的断言不因文档变更而复活
- [ ] 锚点指向未登记文档时被报出来
- [ ] 摘要由内容算出，不采信来源声明
- [ ] 文档核验人必须是人且理由必填
- [ ] 文档核验方法只能是编审（除非确有多份独立文档一致）
- [ ] 镜像文档的核验与「原文里事实的核验」分开
- [ ] 无法拆成三元的原文留在文档里，不被强行拆
- [ ] 一份文档可被多条断言引用，一条断言可引用多份文档
- [ ] 界面能看到每份文档被多少条断言引用

## 边界与异常

- 内容为空：拒绝登记（空文档不是依据）
- 同一 (来源, 标题, 修订) 重复登记：幂等，返回已有记录
- 同一 (来源, 标题) 的修订**回退**到旧值：视为一次新变更，同样触发待重核验，
  并标注「修订回退」——这通常意味着来源出过问题
- 文档被来源删除：保留记录，标注「依据不可达」，**不删除**，
  引用它的断言状态不变但显示不可达
- 自撰文档缺正文：拒绝——镜像文档可以不存正文（归档里有），自撰文档不行
- 适用范围声明了不存在的场景：拒绝并指出，避免静默失效
- 一条断言的依据文档尚未登记：允许存在（历史数据），但必须计入「依据未登记」并可在界面上筛出
- 摘要算法变更：视为全部文档变更会引发大面积回待核验——因此摘要算法版本
  必须记在文档里，算法变更时**不触发**重核验，只重算摘要

## 前后端契约

### `DocumentService`

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | `scenario string` | `DocView[]` | 空场景名表示全部；场景名非空时含「全项目适用」的 |
| `Get` | `revID string` | `DocView` | 按修订取；不存在返回 error |
| `Register` | `DocInput` | `DocView` | 幂等；换修订时触发变更传导 |
| `Verify` | `revID, by, method, reason string` | `DocView` | `by` 必须是人 |
| `Reject` | `revID, by, reason string` | `DocView` | 条目保留 |
| `Usage` | `revID string` | `Item[]` | 引用它的断言 |
| `Unregistered` | — | `UnregisteredRef[]` | 依据未登记的断言（按原件聚合） |

`DocView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `revId` | string | 否 | 该修订的记录标识 |
| `docId` | string | 否 | 文档身份，**跨修订稳定** |
| `source` / `title` | string | 否 | |
| `kind` | string | 否 | `evidence` / `rule` / `explanation` / `change` / `unmodeled` |
| `kindText` | string | 否 | |
| `revision` | string | 否 | 源的修订标识 |
| `hash` | string | 否 | 内容摘要，**由内容算出** |
| `capturedAt` | string | 否 | RFC3339 |
| `registeredAt` | string | 否 | RFC3339 |
| `body` | string | 否 | 原文；镜像文档为空串 |
| `artifactPath` | string | 否 | 镜像文档的归档路径；自撰文档为空串 |
| `appliesVersions` | string[] | 否 | |
| `appliesScenarios` | string[] | 否 | 空数组表示全项目适用 |
| `status` | string | 否 | `unverified` / `verified` / `rejected` / `superseded` |
| `statusText` | string | 否 | |
| `verifiedBy` | string | **是** | null 表示未核验 |
| `method` / `reason` | string | 否 | |
| `current` | bool | 否 | 是否该文档的当前修订 |
| `usageCount` | int | 否 | 被多少条断言引用 |
| `supersededBy` | string | 否 | 取代它的 revId；空串表示没有 |

`DocInput`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source` / `title` / `revision` | string | 是 | |
| `kind` | string | 是 | |
| `body` | string | 自撰文档必填 | 镜像文档留空 |
| `artifactPath` | string | 否 | |
| `capturedAt` | string | 是 | RFC3339；采集时间，不是登记时间 |
| `appliesVersions` / `appliesScenarios` | string[] | 否 | |

`RegisterResult`：`{ doc: DocView, changed: bool, requeued: int }`
——`requeued` 是本次因修订变化回到待核验的断言数，**必须在界面上说出来**。

`UnregisteredRef`：`{ artifact string, assertions int }`

### 断言的呈现

- 断言的 `artifact` 字段即文档的 `title`；界面据此给出「查看依据」入口
- 断言因文档变更回到待核验时，其状态文案必须体现原因，
  不能与「新接入的待核验」长得一样
