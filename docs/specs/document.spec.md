# 文档：不可拆的内容，以及它们之间的关系

## 目的

文档层接住两类东西：

| 来历 | 例子 | 谁产生 |
|---|---|---|
| **取回的** | wiki 原文、接口返回、下载的表格 | 工具，或人导入 |
| **生成的** | 总结、整理、机制说明、变更叙事、决定理由 | 主对话 Agent，或人 |

第二类里有一批**根本不可拆**的内容：「防御减免没有权威来源」「这次改动的动机是 X」。
把它们强行写成字段（`def_reduction.source_kind = none`），含义完全依赖读的人知道上下文——
**这是把不可结构化的东西强行结构化**，与「在前提找不到的情况下瞎猜」是同一个错误。
所以它们留在文档里，作为依据存在。

但文档不只是「一堆原文」。项目里的文档会互相引用、互相总结、由同一份来源转载而来，
一份原文里的某个词又要和词表挂上钩。这些关系**不归纳好，文档就只是文件堆积**：
找不到谁引用了它、改一份会影响什么、这个词在这段里到底指哪个。

因此本层有两件事同等重要：**内容本身**（不可改，只追加修订）与
**关系**（双向索引、段落锚点、与词表的挂钩）。

## 术语

- **文档（document）**：一份内容，加上它的身份、来历、关系与版本状态。
- **修订（revision）**：内容的一个版本。身份跨修订稳定，修订是它的历史。
- **取回型 / 生成型**：见上表。这条分界决定**要不要人拍板**：
  取回型只是记录「来源说了什么」，生成型引入了判断。
- **段落（paragraph）**：文档内部可被单独引用的最小单位，有稳定标识。
- **锚点（anchor）**：对文档内容的定位，形如「哪份文档的哪一版、哪一段」。
- **引用（reference）**：一条锚点的使用。**钉住某一版**与**跟最新版**是两件事。
- **双向索引（backlinks）**：每份文档都能看到「它引用了谁」与「谁引用了它」。
- **关系（relation）**：文档之间的有向边：引用、派生自、取代、转载自、相关。
- **拍板（sign-off）**：人对生成型内容进入事实源的确认。见 `agent.spec.md`。
- **背书（attest）**：人对某一份取回型原文「我读过，它与实际一致」的记录。
  背书不改内容，也不阻断使用——它与拍板是两件事。

## 领域规则（Given-When-Then）

### 归属与身份

- Given 一份文档 When 记录 Then 它归属**项目**（来源是项目级的，会被多个 Case 引用）
- Given 一份文档 When 记录 Then 可以标注**适用 Case**；标注表示「这份只在那些 Case 下成立」，
  不标注表示全项目适用
- Given 同一来源同一标题 When 换了修订 Then 文档**身份不变**，
  新修订成为当前版本，旧修订**保留为历史**
- Given 一份文档 When 记录 Then 必须携带 meta：来源、标题、来历（取回型/生成型）、
  修订标识、采集或生成时间、内容摘要
- Given 取回型文档 When 记录 Then 摘要是**由内容算出**的，不采信来源的声明——
  来源可以撒谎或出错，摘要不会
- Given 生成型文档 When 记录 Then 除摘要外还必须记录**它依据了什么**（来源标识或既有内容标识）

### 只追加，不可删改

- Given 一份文档 When 登记 Then 它**不可修改正文**
- Given 一份文档需要更正 When 操作 Then 只能**登记新修订**，旧修订保留
- Given 旧修订 When 被新修订取代 Then 它仍在历史里可查，
  且**当时引用它的内容仍指向它**——不能悄悄改写成指向新修订
- 这条与 Case 的 experience 相反（见 `experience.spec.md`）：experience 是探索区，
  错了改了代价小；文档是依据，依据被改动过就不可信了

### 段落与锚点

- Given 一份文档 When 登记 Then 它的段落获得**稳定标识**，可被单独引用
- Given 一个锚点 When 记录 Then 必须能回答：哪份文档、**哪一版**、哪一段
- Given 一个锚点 When 不写明版本 Then 它表示**跟最新版**；
  写明版本则表示**钉住那一版**
- Given 一个跟最新版的引用 When 该文档产生新修订 Then 该引用标为「依据已变」，
  直到有人复核——不得静默沿用
- Given 一个钉住旧版的引用 When 该文档产生新修订 Then 引用本身**不变**，
  但显示上必须标出「依据不是最新版」，使人能判断是否该跟进
- Given 一个段落被引用 When 又产生新修订 Then 旧修订里的该段锚点**仍然解析得到**——
  这正是「只追加」换来的能力
- Given 一个锚点 When 解析失败（段落不存在、修订不存在） Then **报出未登记/失配**，
  不得静默当作没有

### 关系与双向索引

- Given 两份文档 When 建立关系 Then 必须指明方向与种类：
  引用、派生自、取代、**转载自**、相关
- Given 一份文档 When 打开 Then 必须同时看到**它引用了谁**与**谁引用了它**两个方向，
  且每条都能跳到对方
- Given 一份文档由另一份**转载**而来 When 交叉校验 Then 两份**只算一份证据**——
  转载关系必须显式建立，否则独立性判断会把同一来源算两次
- Given 一份文档被删除 When 处理 Then 指向它的关系标为「失效」，
  **不删除关系本身**——「曾经引用过」是审计信息
- Given 建立关系 When 形成环 Then 允许（A 引用 B、B 引用 A 是正常的），
  但**派生自**的环拒绝——那意味着推导依据不可能成立

### 与词表的挂钩

- Given 一份文档 When 分析 Then 它命中的词条挂到词表上；同一个词在一份文档里可能命中多处
- Given 词表里的一个词 When 打开 Then 能看到它出现在**哪些文档的哪些段落**
- Given 文档里一处命中 When 该词有多个义项 Then 按词表的**条件指代**规则判定指哪个；
  上下文不足以判定时**记录歧义并报出**，不猜（规则见 `dict.spec.md`）
- Given 一处命中 When 判定为一个义项 Then 该判定可被引用，也**可被推翻**——
  推翻后回到歧义状态，不删除原判定
- 文档不改词表、词表不改文档：两边各自持有内容，靠**命中与判定**连接

### 不拆

- Given 一段内容 When 无法确定地抽出「主体—关系—取值」 Then **就让它留在文档里**，
  不得为了「变成数据」而强行拆
- Given 从文档抽出了数据 When 记录 Then 抽取结果是文档的**索引**，不是它的替代——
  文档仍然在，仍然作为依据
- Given 一份文档支撑多条数据 When 查询 Then 一份文档可支撑**任意多条**
- Given 一条数据 When 阅读它的依据 Then 它的**锚点落在唯一一处**；
  同一件事由多份独立文档佐证时，那是多条数据 + 交叉校验的结论，
  不是一条数据挂多个依据——依据可指多处，「这个值从哪段原文读出来的」就没有唯一答案

### 生成型文档与拍板

- Given 一份取回型文档 When 登记 Then **不需要拍板**：它只是记录来源说了什么
- Given 一份生成型文档 When 写入 Then **必须有人拍板**，且记录拍板者与理由
  （规则见 `agent.spec.md`：人只在内容进入项目级事实源时拍板）
- Given 一份生成型文档 When 写入 Then 必须写出它**依据了哪些来源或哪些既有内容**；
  写不出依据的生成内容拒绝登记——那是凭印象编的
- Given 一份文档 When 有人背书 Then 记录背书者、时间与理由；
  背书**不改变**内容，也不使内容免于「依据已变」的标注
- Given 一份取回型原文 When 展示 Then 必须把两件事分开说：
  「这份原文可信」与「原文里讲的事实成立」——这是两件事，合成一件就是误导

### 变更传导

- Given 一份文档的当前修订发生变化 When 检测到 Then
  **所有跟最新版的引用标为「依据已变」**，并逐条列出
- Given 修订标识没变但内容变了 When 检测到（摘要不符） Then 按同一规则处理——
  **修订标识可信，但不能只信它**
- Given 内容因文档变更而标为「依据已变」 When 显示 Then 必须说明原因是「所依据的文档变了」，
  不得让它看起来像一条新写入的内容
- Given 一次变更传导 When 完成 Then 把它**说出来**：多少处引用被标、涉及哪些 Case 产物——
  一次同步让几百处悄悄失效，就是最坏的那种静默
- Given 摘要算法变更 When 处理 Then **不触发**变更传导，只重算摘要；
  因此摘要必须自带算法标识，使旧摘要不被误判成「内容变了」

## 验收标准

- [ ] 文档区分取回型与生成型，生成型必须指出依据
- [ ] 取回型登记不需要拍板；生成型没有人的拍板与理由时拒绝写入
- [ ] 写不出依据的生成型文档被拒绝
- [ ] 同一来源同一标题换修订时身份不变，旧修订保留为历史
- [ ] 文档正文不可修改，只能登记新修订
- [ ] 旧修订被取代后仍可查，当时引用它的内容仍指向它
- [ ] 段落有稳定标识，可被单独引用
- [ ] 锚点能回答「哪份文档、哪一版、哪一段」
- [ ] 不写版本的引用表示跟最新版；文档更新后该引用被标为「依据已变」
- [ ] 钉住旧版的引用在文档更新后不变，但标出「依据不是最新版」
- [ ] 旧修订里的段落锚点在新修订产生后仍解析得到
- [ ] 锚点解析失败时被报出，不静默当作没有
- [ ] 文档关系有方向与种类，且能看到双向索引两个方向
- [ ] 转载关系被显式记录，交叉校验时不把转载算作独立来源
- [ ] 派生自的关系成环时被拒绝
- [ ] 文档里命中的词条能挂到词表，词条能看到它出现在哪些文档的哪些段落
- [ ] 上下文不足以判定指代时产出歧义记录，不猜
- [ ] 指代判定可被推翻，推翻后回到歧义状态且不删除原判定
- [ ] 无法拆的内容留在文档里，不被强行拆
- [ ] 一份文档可支撑任意多条数据
- [ ] 一条数据的锚点落在唯一一处
- [ ] 变更传导把「多少处引用被标、涉及哪些产物」说出来
- [ ] 修订标识未变但内容变了时按同一规则处理
- [ ] 摘要由内容算出，自带算法标识；算法变更不触发变更传导
- [ ] 「原文可信」与「原文里的事实成立」在界面上分开呈现
- [ ] 界面能看到每份文档被多少处引用，且能跳到那些引用
- [ ] 文档被来源删除时标为「依据不可达」，不删除记录

## 边界与异常

- 内容为空：拒绝登记（空文档不是依据）
- 生成型文档缺依据：拒绝登记
- 生成型文档缺拍板者或理由：拒绝登记
- 同一 (来源, 标题, 修订) 重复登记：幂等，返回已有记录
- 同一 (来源, 标题) 的修订**回退**到旧值：视为一次新变更，同样触发变更传导，
  并标注「修订回退」——这通常意味着来源出过问题
- 文档被来源删除：保留记录，标注「依据不可达」，**不删除**；引用它的内容不变但显示不可达
- 取回型文档不存正文（正文只在归档里）：允许，但摘要与归档标识必须齐备
- 生成型文档不存正文：拒绝——它没有别的归档可依
- 适用 Case 声明了不存在的 Case：拒绝并指出，避免静默失效
- 锚点指向未登记的文档：允许存在（历史数据），但必须计入「依据未登记」并可筛出
- 引用一处锚点而该锚点未登记：入口**明说依据未登记**，并指向未登记列表——
  不得打开一个空白页让人以为是加载失败
- 一条数据没有锚点（由公式算出）：不显示依据入口，也不显示为空的锚点
- 一份文档的两个修订被不同 Case 各自引用：允许，两个引用各自指向自己那一版
- 同一份文档被两个 Case 各自总结：两份总结并存，互不覆盖，各自注明依据
- 词表里一个词在同一段上下文里指向两个都说得通的东西：产出歧义记录，
  携带两个候选与所在段落，由人裁决（见 `dict.spec.md`）
- 文档间的「相关」关系成环：允许
- 段落被引用后原文整体重排（新修订）：旧锚点在旧修订内仍解析得到，新修订的锚点按新内容重算

## 前后端契约

`DocumentService`（作用域：项目；读在 Case 作用域内同样可用）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `List` | `case, kind, limit` | `DocView[]` | `case` 为空表示全部；`kind` 为空表示全部种类。返回**当前修订** |
| `Get` | `docId, revision` | `DocView` | `revision` 为空取当前修订 |
| `History` | `docId` | `DocView[]` | 全部修订，登记时间倒序 |
| `Paragraphs` | `docId, revision` | `ParaView[]` | 段落与其锚点 |
| `Import` | `DocInput` | `DocResult` | 取回型：直接生效，不需拍板 |
| `Write` | `DocInput, by, reason` | `DocResult` | 生成型：`by` 必须是人，他就是拍板者 |
| `Attest` | `docId, revision, by, reason` | `DocView` | 背书「我读过这份原文」；不改内容 |
| `Relate` | `from, to, kind, by, reason` | — | 建立文档间关系 |
| `Unrelate` | `from, to, kind, by, reason` | — | 解除关系；解除记录保留 |
| `Links` | `docId` | `Links` | 双向索引：引用了谁、谁引用了它，含关系种类 |
| `Terms` | `docId, revision` | `TermHit[]` | 文档里命中的词条与判定状态 |
| `Unregistered` | — | `UnregisteredRef[]` | 依据未登记的引用（按目标聚合） |
| `Changed` | `docId` | `AffectedView[]` | 若该文档当前修订变更，会影响哪些引用与产物 |

`DocView`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `docId` | string | 否 | 文档身份，**跨修订稳定** |
| `revId` | string | 否 | 该修订的记录标识 |
| `source` / `title` | string | 否 | |
| `origin` | string | 否 | `retrieved`（取回型）/ `generated`（生成型） |
| `originText` | string | 否 | 中文说明 |
| `kind` | string | 否 | `source` / `digest` / `note` / `change` / `unmodeled` |
| `kindText` | string | 否 | |
| `revision` | string | 否 | 来源的修订标识；生成型为内容标识 |
| `hash` | string | 否 | 内容摘要，**自带算法标识** |
| `capturedAt` | string | 否 | RFC3339；采集或生成时间 |
| `registeredAt` | string | 否 | RFC3339 |
| `body` | string | 否 | 正文；取回型可空（正文在归档里） |
| `artifactPath` | string | 否 | 归档位置；生成型为空串 |
| `basis` | `Basis[]` | 否 | 生成型必填非空：依据了哪些来源或既有内容 |
| `appliesVersions` | string[] | 否 | |
| `appliesCases` | string[] | 否 | 空数组表示全项目适用 |
| `signedBy` | `ActorView \| null` | 是 | 生成型必须有；取回型可为 null |
| `signReason` | string | 否 | |
| `attestedBy` | `ActorView \| null` | 是 | 背书者；null 表示未被背书 |
| `attestReason` | string | 否 | |
| `current` | bool | 否 | 是否该文档的当前修订 |
| `supersededBy` | string | 否 | 取代它的 revId；空串表示没有 |
| `usageCount` | int | 否 | 被多少处引用 |

`Basis`：`{ kind: "doc" | "tool-run" | "data", ref: string, note: string }`
——`kind` 说明依据的是文档、某次工具执行、还是项目里的数据；`ref` 是可跳转的标识。

`DocInput`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source` / `title` / `revision` | string | 是 | |
| `origin` / `kind` | string | 是 | |
| `body` | string | 生成型必填 | 取回型可留空 |
| `artifactPath` | string | 否 | |
| `basis` | `Basis[]` | 生成型必填 | |
| `capturedAt` | string | 是 | RFC3339 |
| `appliesVersions` / `appliesCases` | string[] | 否 | |

`DocResult`：`{ doc: DocView, changed: bool, reverted: bool, affected: int }`
——`affected` 是本次因修订变化被标为「依据已变」的引用数，**必须在界面上说出来**；
`reverted` 报告修订标识回退。

`ParaView`：`{ anchor: string, index: int, text: string, terms: TermHit[] }`

`Links`：`{ out: LinkView[], in: LinkView[] }`，
`LinkView`：`{ docId, title, kind, kindText, revision, pinned: bool, anchor: string }`
——`pinned` 区分「钉住某一版」与「跟最新版」。

`TermHit`：`{ anchor, term, sense, senseText, status, decidedBy }`，
`status` 为 `resolved` / `ambiguous` / `overturned`。

约定：

- `Import` 与 `Write` 分两个方法，**不是**一个方法加参数：
  它们一个不需要拍板、一个必须有人的理由，合并会让「有没有拍板」变成可选字段
- 每个读接口返回的引用都带 `pinned` 与版本标识，使界面能显示「依据已变 / 依据不是最新版」
- `Links` 必须一次给全两个方向：只给一个方向的「双向索引」等于没有
- `Changed` 是只读的预演：让人在改动之前就知道会影响谁

## 待确认

1. 文档的「相关」关系是否需要权重或类型细分
2. 段落标识的算法（按内容散列 vs 按位置），以及重排后旧锚点的解析策略
3. 背书是否允许 Agent 发起（当前：只允许人发起，Agent 只能建议）
4. 词表命中是登记时算好并持久化，还是每次分析时重算
5. 取回型文档是否一律需要归档（当前：可只存摘要，但需说明理由）
