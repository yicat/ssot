# 整理：`raw/` → `docs/`

## 什么时候用

- 用户说「把这篇 raw 整理一下」「给 X 建个文档」「这批材料归档整理一下」
- `raw/` 里新到了一批原始材料，要变成人能读、能引用的说法

## 步骤

1. `vault_list` 看全貌。先确认目标文档是**新建**还是**已存在**；
   同名不止一篇时**问人**，不要自己挑一篇（系统不裁决）。
2. `doc_read` 读 `raw/` 里的原文。要引用哪一段，先用 `link_resolve` 确认
   `[[raw/…#^块]]` 解析到的文档与**文件行号**——行号是人跳过去看的，必须是文件行号。
3. 起草整理稿：
   - 正文里**每一条来自原始材料的主张**，后面跟一条指回原文的块级双链（`[[raw/灰机wiki/X#^段]]`）。
     这是这套东西的主张级溯源，不是装饰。
   - 与已有文档相关处用 `[[文档]]` 连过去；拿不准目标是哪篇就先 `link_resolve` 试。
   - `doc_write` 只写正文，front matter（title / tags / status / source）**原样保留**——
     所以别把 front matter 写进 `body` 里。
4. `doc_write` 写入。
5. 自检：`link_backlinks` 看**断链**（`broken`）与**指不清**（`ambiguous`），有就修掉再交。

## 不许做

- **不许改 `status`**：发布与归档只能由人做，能力层会直接拒绝 agent 的这类写入。
- **不许把两个来源的不同说法合成一句**：冲突要**并列**，各带各的双链（系统不裁决）。
- 不许删掉拿不准的内容——留着，并标明「来源未核验」。
- 不许为了好看而创造原文里没有的数字或结论。
