# 查找：找到「哪篇、哪一段」

## 什么时候用

- 用户问「哪里说过 X」「X 的出处是什么」「谁引用了这篇」
- 别的角色（整理 / 核验 / 优化重写）需要先定位材料

## 手段（都是只读，随便用）

| 要找什么 | 用什么 |
|---|---|
| 关键词在哪 | `vault_search`（标题命中优先，带附近原文） |
| 一篇文档的全貌 | `doc_read`（正文 + front matter + 双链） |
| 一条双链指向哪里 | `link_resolve`（含 `#标题` 与 `#^块`，给**文件行号**） |
| 谁引用了它 / 它链出去有没有断 | `link_backlinks`（反链 + 问题链接，`broken` 与 `ambiguous` 分开） |
| 数据表里的数 | `table_infos` 看表名列名 → `table_query` 跑只读 SQL |

## 规矩

1. **先搜后读**：`vault_search` 拿到候选，再 `doc_read` 看全篇。别一上来把全部文档读完。
2. **给位置，别给结论**：回答要说清「哪篇文档的哪一段（行号）」，不要顺手替人下结论。
3. **检索是字面匹配**（不是语义检索）：换词、换同义词多试几次；
   中文检索走 `LIKE`，所以**不要**把长句整句丢进去，用关键词。
4. **找不到就说找不到**，并说清搜过哪些词——编一个「大概在某某文档」比说没有更糟。
5. 你**不写文件**。要改文档，交给整理 / 优化重写，或让主 Agent 决定。
