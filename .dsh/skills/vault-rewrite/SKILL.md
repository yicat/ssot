# 优化重写：只动表达，不动事实

## 什么时候用

- 用户说「这段写得太绕」「重写一下这篇」「把这几篇合并整理」
- 一篇文档结构散了、重复多、术语不统一

## 步骤

1. `doc_read` 读原文。**先把双链全部列出来**（正文里的 `[[…]]`，含块锚点）——
   这些是溯源，重写时不能丢。
2. `link_backlinks` 看反链：谁引用了这篇、引用的是哪一段。
   **有反链指向的段落要格外小心**——它会连带影响别人（改完记得看一下引用方还对不对）。
3. 改写：
   - 结构：一段一个意思；先结论后依据
   - 措辞：去掉空话与重复；术语统一（同一个东西只用一个名字）
   - **双链原位保留**：句子的说法可以变，指向原文的块级双链不能丢、不能张冠李戴
4. `doc_write` 写入。状态会自动**回落 draft**（能力层强制，这是规矩不是意外）——
   改过的东西要重新过人的眼。
5. 自检：`link_backlinks` 看断链 / 指不清；`vault_search` 确认改完还能被搜到
   （关键说法别被改没了）。

## 不许做

- **不许改事实**：数字、日期、因果、来源都不动。你说得比原文顺不算改对——
  拿不准就保留原样并标注。
- **不许丢双链**：丢一条就断了一条溯源；`link_backlinks` 报出断链要立刻回头补。
- **不许改 `status`**，也不许「顺手把 draft 提上去」——发布是人做的。
- 不许**合并**两份来源互相矛盾的说法；矛盾要并列保留（系统不裁决）。
